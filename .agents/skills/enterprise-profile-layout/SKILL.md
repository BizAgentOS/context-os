# 企业档案内容区

本技能供开发 Agent 使用，不是 KodaX 产品运行 Skill。布局方法不创造企业事实，不扩大工具权限。

## 已确认的页面边界

保留公共顶部三页导航、Logo/名称、能力和设置入口，以及底部输入框、动画与对话记录。只调整中间企业内容区。使用宽屏 Web 布局，不制作 A4 长文页面，不引入新的全局侧边栏。

## 内容骨架（按已有内容选用）

1. 顶部紧凑企业概览：企业名称、业务简介、已有身份属性及编辑入口。名称和简介优先，次要属性在窄屏换行。
2. 页内分区：业务全景 / 发展与组织 / 资料与数据。企业概览保持可见；分区状态属于 UI，不建立三份企业事实或三个 Agent。
3. 业务全景：左侧业务构成和核心业务关系，右侧服务对象与范围，末行当前业务问题和资料入口。产品/服务充分时可分列，不为凑三列猜测业务。
4. 发展与组织：展示已有沿革、组织、职责及补充信息。无实际时间信息不造时间线，无组织依据不画推测组织图。未分类陈述仍可查看和修正。
5. 资料与数据：复用统一来源目录、文件、共同取证、旧记录恢复功能。接入方式与内容类型分开，连接成功不代表已读取或完成映射。

## 内容与操作

- 以现有 profile 陈述、foundation 版本和来源回执为输入，沿用领域引用与编辑/采用服务。不能把截图里的虚构企业样本写入真实空间。
- 已有的用户陈述、来源建议、候选定义与已采用内容保留各自状态；已有内容的待核实或冲突标记不能因精简排版而删除。引用的关系必须来自实际基础版本，不由同屏位置推断。
- 先盘点实际内容，再选择字段、板块与布局。没有信息的字段不写；整个板块没有内容就省略，不显示“暂无”“待补充”等占位文案，不保留空卡片、空图或强制补齐的章节。
- 分栏随内容收拢：只有业务内容就使用完整可用宽度，不为缺失的客户或关系信息预留空栏。不推测成立时间、组织职责、业务流程或关系来填满模板。
- 数据接入、编辑和助手等操作入口仍可使用；它们不是企业事实。完全没有企业信息时仅保留简洁的起步入口，不铺开一套空档案。
- 点击陈述进入同一编辑详情；关系可展开已有定义与依据。补充提示放入助手草稿，不自动发送，不覆盖已有草稿。
- 仅查看分区不运行模型；切换后保持该分区，轮询不应跳回业务全景。

## 版式与验证

使用现有黑白灰与字体。组件样式限定在 `.enterprise-profile` 内。宽屏在两侧均有内容时采用约 2:1 分栏，1000px 以下概览属性换行，700px 以下改为单栏；内容自然滚动，不强制塞进一屏。

验收稀疏内容不出现占位字段或空板块、资料充分内容、已有内容的待核实与候选、非标准字段、来源入口、编辑返回、草稿保留、键盘和宽窄屏；确认全局控件源码未改。静态分享使用相同渲染组件但维持只读边界。
