# Grilling(质询)

把一个模糊的想法 / 计划 / 设计,通过**穷追不舍**的提问,逼出每个决策树分支的答案,直到双方达成共同理解(shared understanding)。

本原语是 `grill-me`、`to-spec` 等场景共用的质询循环——逻辑只存这一处,变体做薄委托。

## 质询纪律

1. **一次只问一个问题。** 连问多个会让人眩晕。问完一个,等回答,再问下一个。
2. **每个问题都附你的推荐答案。** 不是空问,是带着建议问——让对方只需确认或修正,降低认知负担。
3. **事实自查,决策才问人。** 能通过读代码 / 查环境 / 读文件确认的*事实*,自己去查;只有*决策*(选 A 还是 B、要不要做 X)才问人。
4. **沿决策树逐分支收敛。** 把待澄清项建模成一棵决策树,按依赖关系逐个解决,一次推进一个分支;前置决策未定时,不问依赖它的问题。
5. **只在达成共同理解后才开始实现。** 还有未决分支时,继续把分支问清楚,直到收敛。

## 何时停

当每个决策树分支都有了答案(或被显式标为"暂不决定"),向用户复述一遍共同理解,确认后即结束。(实现门槛见纪律 5,此处不重复。)

## 与其他 skill 的关系

- `grill-me`:用户手动触发的无状态质询,薄包装本原语。
- `to-spec`:用本原语确认 spec 的关键决策。
