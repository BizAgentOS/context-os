# ADE 内部 Agent 行为与运行契约

更新：2026-10-19。本文是身份、模式、工具范围、上下文和运行生命周期的当前目标合同。产品价值见[PRD](PRODUCT.md)，共享语义见[语义契约](SEMANTIC_CONTRACTS.md)，界面卡片见[协作契约](AGENT_UI_DESIGN.md)。交付状态以[台账](FEATURE_LIST.md)和实际验收为准。

## 身份与责任

一个 ADE Agent 协助建设和使用企业本体，KodaX 是唯一模型 / 工具循环；宿主绑定身份、上下文、工具和运行有效性；确定性服务负责查询、复验、版本、授权、采用与持久化。Skill 提供方法，不产生实现或授权。外部普通消费直接调用领域服务，不经过模型。

程序生成初稿，程序、人和 Agent 均可提议结构。Agent 提议必须附业务依据，经过复验与预览后交人采用；不能自行决定身份对应、采用结构、发布或扩大许可。文档只补充已有定义的名称、说明、依据与未决项，不从资料生成结构。见[ADR-005](ADR/ADR-005-verified-structural-proposals.md)。

## 一个 Agent，两种模式

| 项 | 构建 | 问答 |
|---|---|---|
| 目的 | 让本体变对 | 用本体回答业务问题 |
| 视图 | 工作版快照、原始来源、待处理；实时读取需显式选择 | 工作版默认，或指定发布，或发布 + 接入方范围 |
| 工具 | 观察、统一提议、复验、查询预览、待处理、同步、文档、只读查询、交互 | 本体描述与检索、对象查询、关系遍历、聚合、依据、知识片段、缺口单 |
| 写权限 | 提议变更、复验预览、普通名称说明编辑 | 只允许创建缺口单 |
| 交付 | 变更清单、复验、决定卡 | 回答卡或缺口卡 |
| 页面默认 | 数据 | 本体、发布与接入（预选当前发布） |

模式由用户切换，Agent 只能建议；页面只改变默认值和焦点，不是权限边界。问答工具不提供原始来源、快照 SQL、待处理、提议或采用。模式工具在宿主注册与执行时双重隔离，不能只提示模型“只读”。[ADR-006](ADR/ADR-006-one-agent-two-modes.md)记录决定；FEATURE_048、052 分别接入两种工具层。

目标构建工具组及工具演进见[蓝图 §8.4](features/v0.3.0-blueprint.md#84-构建模式)：统一 change 提议、复验、预览和 pending 工具替代分散旧入口，旧数据集提议、报告保存、页面完成控制退出；具体开放签名随对应 Feature 定稿，不把目标名称注册为可调用工具。

## 工作、交接与完成

已授权普通读取、检查与编辑直接推进，先用已有成果，只在影响当前目标且资料不能补足时问具体问题。用户已经清楚给出企业身份时不机械重复确认。

问答回答包含结论、对象 / 关系 / 属性依据、视图版本、数据截至、覆盖与限制。依据与数字来自回执，模型只组织结论与解释。真实为空回答“没有”；覆盖不足说明截断；无关系类型、有类型未绑定、有绑定未匹配、身份未对应时创建缺口单，不能猜测结果。超出本体范围说明覆盖范围。

缺口单保存原问题、可重放查询、回执、原因、对象、观察和关联变更，状态为 open → in_fix → fixed → confirmed；可 dismissed，复问失败则 reopened。用户触发转构建，修复提议 → 复验 → 重放预览 → 人采用；fixed 后仍由用户触发问答复问，只有复问成功才 confirmed（FEATURE_054）。

保存、复验通过、采用、发布与授权分别报告。失败、停止或超时保留已提交部分，不伪造引用或成功，不将失败当零。版本冲突后重读目标再复验；同一明确决定不反复确认，旧决定不能授权新内容。采用只能经界面按钮，不能用固定口令、自然语言确认或模型自填字段触发。

## 会话与模型上下文

会话跨页长期保存，可新建、重命名与归档，完整消息可分页回看（FEATURE_047）。任务事件已持久化；结构化卡片与系统事件的浏览由 FEATURE_046 承接。切页不切会话、不取消运行。

模型窗口独立：身份 / 通用 / 当前模式提示词、企业与工作版的短摘要、待处理数、当前引用、会话摘要、最近 12 条或 12000 字、按需对象详情。默认不含工具定义 8000 token，超限裁剪摘要，不删除数据库历史。来源原文、全企业定义、检查清单不自动装入。发送时冻结引用和视图，后续浏览不改已发目标。

提示词按“身份 / 通用规则 / 构建模式 / 问答模式”四层装配，Skill 按需加载。FEATURE_036 只更新身份和通用规则，保留当前单一模式；独立模式层后续接入。工具名与目标运行工具集、页面名称持续做一致性检查，方法中不得引用不存在的能力。

## 执行、停止与成本

交互池按会话各并发 1，后台池并发 1；不同会话可并行，后台文档、重绑、批量命名和外部委托排队执行，不暂停交互；同对象写入由版本检查处理。会话运行中再次发送时提示等待或显式停止；切模式不停止在途任务，新消息使用新模式。上传文件进入后台池。会话、窗口与分池已接入 FEATURE_047，批量命名与双模式分别由 045、048 承接。

宿主先撤销写入资格，再请求 SDK abort，提交前后核查资格；取消不回滚已提交成果。停止 / 240 秒超时的执行卡列出已完成步骤、已保存变更、未执行部分与继续按钮。继续是带原目标和真实成果的新运行（FEATURE_046）。

问答每轮最多 24 次读取、512 KiB 工具结果、每次 20 个对象，聚合最多 1000 组；预算用尽交付部分结果。每次运行记录 token 与费用估算，执行卡显示成本；设置支持每轮和每日上限，达限停止（FEATURE_064）。

## 当前接入事实与实施边界

- Node HTTP / Web，KodaX embedded/inline，临时 SDK session；不是进程沙箱。SDK 依据只在[能力台账](KODAX_CAPABILITY_LEDGER.md)维护。
- v0.2.3 基线按页面装配工具并共用运行槽。未发布的 FEATURE_047 已改为长期跨页会话、完整分页历史、有界摘要上下文和交互 / 后台分池；每个实际池句柄由独立 KodaX runtime 执行，页面由标签页保存。真实标题与上下文对比见[047 验收](experiment/V030_047_2026_10_19.md)。独立双模式、统一结构提议、完整执行卡、缺口卡与成本上限仍待对应 Feature。
- 基础结构由程序构建，现有服务只允许 Agent 修正已有定义；当前提示词不得新增概念或关系。放开结构提议由 FEATURE_040、041、048 落地，不能绕过现有结构锁。
- 已有基础 / 文档 / 网页读取回执、映射、取证与局部纠正继续通过共同服务执行。旧回执说明与限制保留在[历史验收](experiment/README.md)；新能力用当前测试和真实运行证据验证。
- 当前工具、页面和内置方法通过 [prompt-contract.test.ts](../tests/agent/prompt-contract.test.ts) 检查装配；模拟 driver 只证明合同，真实模型行为另行记录。

旧运行设计及 SDK 调研见[2026-09-07 历史档案](archive/AGENT_DESIGN_2026-09-07.md)。实现与验证只按[当前票](features/v0.3.0.md#feature-036)推进。
