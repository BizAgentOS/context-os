# 企业记忆画布

2026-09-08，依据用户手绘草图及随后确认的产品定位。T003-04 / T005-04 已交付前三页；用户随后增加第四页“数据消费”，归属 FEATURE_007，现已实现并完成真实模型、浏览器和客户端的整条体验验收。本文及[消费治理设计](DATA_CONSUMPTION_DESIGN.md)共同描述当前交互，替代旧工作台的三栏聊天布局与任务导航。

## 产品目的

DataEngine 用本体组织企业级记忆，通过 Agent 的协助创建这套记忆。用户交互的成果是企业信息、资料、定义和对象；这些内容构成产品页面。对话只承担创建和修改的入口。

判断一项界面元素是否保留：它是否帮助用户建立、检查或纠正当前企业记忆。默认不展示运行日志、会话/任务编号、工具名称、进度百分比、历史任务、无关解释和产品宣传。

## 四个页面

| 页面 | 空白时的引导 | 随交互形成的内容 | 进入下一页 |
|---|---|---|---|
| 企业 | 这家企业是什么，主要做什么？ | 企业名牌，以及逐步形成的业务、服务对象、职责、目标和流程认知 | 企业名称、业务已实际保存，当前必要问题已解决后进入数据页；不强制完整问卷 |
| 数据 | 需要接入哪些数据和资料？ | 真实来源、用途、接入结果与缺口，按需打开原文或表格 | 已有本轮可用于对象映射的业务数据，Agent 检查完成后进入本体页 |
| 本体 | 从这些资料里，需要先建立哪些业务对象？ | 有依据的概念、关系、映射、实例；可查看和调整 | 关键定义采用绑定具体候选；后续可进入数据消费页，不自动发布或授权 |
| 数据消费 | 哪些应用需要使用这些企业记忆？ | 调用方、允许读取的对象、字段和关系、必要接入信息、真实访问记录 | 持续管理授权与撤销，检查谁在使用记忆 |

本轮接入 CSV、Markdown、TXT；对象映射需要有记录的 CSV。空文件、解析失败或只有介绍文档时说明实际缺口，不能为了跳页伪造“接入完成”。外部接口仍需对应连接器，聊天不会凭空赋予接入能力。

已有企业记忆继续可读取；不因为改版重新导入或删除。导航为企业、数据、本体、数据消费四个轻量位置入口；采用本体后解锁数据消费，可以回到已到达页面；打开或切换页面本身不产生模型调用。报告与记忆更新页面本轮不展示。

## 画面与对话

整屏为黑白画布，不把草图的外框做成额外的大边框。空白时保持留白、一句当前引导及底部输入框。有内容后，企业信息、资料或本体成为画面的主体。

画布从导航下方延伸到屏幕底部；对话和输入框属于前景浮层，与背景按前后层次叠放，不占独立的底部布局行。底部居中一个输入框，内含发送，以及实际运行中的停止。前三页保留资料入口；数据消费页隐藏上传，资料仍从数据页接入。模型连接放在小型设置入口。没有虚假的语音按钮或尚未接入的能力入口。

输入框上方只显示最近少量对话，越往上越淡直至消失。浮层容器和对话区域透明，只有输入及相关操作接收点击，透明部分的点击与滚动传给背景画布。对话区域有固定高度上限，不能随历史增长挤压画布。非空内容末尾保留可滚动的留白，随浮层实际高度调整，最后一项也能滚到输入框上方查看；空态不加入这段留白。用户主动打开的原文或实例详情可占据画布，此时保留清楚的返回入口。

每页只有一份交互上下文。不显示“新建任务”、历史对话列表或可切换的多个 Agent。用户切回页面时继续该页，不额外创建用户可见会话。

## 消费画布

数据消费空白时询问哪些应用需要使用企业记忆。有草稿后，画布呈现“企业记忆 → 调用方”的连接，卡片显示名称、用途、对象范围和授权状态。点开调用方才展开具体字段、关系、接入方式与最近真实调用。

Agent 只提出草稿；待确认草稿的具体版本上显示“启用访问”。用户启用后，调用方 API Key 只在独立窗口交付一次，关闭即清空。已启用调用方显示“停用访问”，旧凭据立即失效；调整范围通过对话重新整理并确认。页面不模拟请求或访问统计。

管理页面首次使用本机启动链接；地址中的管理凭据片段读取后移除，合法请求建立浏览器管理会话。消费方使用自己的 Bearer 凭据调用独立只读接口，不能利用管理预览接口获取完整记忆。

## 对话寿命与企业记忆

页面原始聊天使用明确的数量和长度上限，超出时移除最早内容。真实模型输入采用同样的有界页面上下文，不只在界面隐藏旧消息、却继续让 SDK 累积历史。每轮从这份上下文与当前企业记忆构造执行输入；KodaX 的执行会话是内部细节。

公司、资料、本体及已经保存的用户陈述不会随旧聊天裁剪删除。跨页读取已经建立的企业记忆，不把上一页完整聊天复制过去。用户陈述的引用原话保留在已保存的事实中，供必要时核查。

内部继续保留现有的执行有效性与版本检查：停止或换页后旧运行的迟到写入不能覆盖新工作；模型说“完成”不等于完成创建。页面推进只依据真实保存、程序检查和当前阶段完成动作。仅收到数据或者建出未经检查的候选，不触发正式本体采用。

## 实现与验收边界

复用当前 KodaX SDK、来源解析、企业记忆和本体对象工作区。前端根据实际结构化成果形成页面，模型不能把任意 HTML 或脚本当作已经创建的企业记忆。原来的报告/任务 API 可以为历史数据保留，但不成为新产品流程入口。

沿已有的“用户输入 → 真实工具执行 → 已保存成果 → 再次打开”公共边界检查：

- 从空白企业输入实际信息，画布出现企业名牌与信息；只在条件满足后自动进入数据页。
- 从数据页上传实际资料，看到来源与内容；坏文件有清楚缺口，不能推动假完成。
- 从本体页创建、预览并决定具体候选，看到真实关系、实例与证据。
- 一页一份上下文；跨页不串用原始聊天；旧消息裁剪后企业信息仍在。
- 最近对话向上淡出，长对话不遮挡画布；没有任务列表、历史聊天栏、报告和更新页。
- 暂停、换页、重开和失败保留真实成果，明确候选采用仍遵循版本检查。
- 数据消费页通过对话提出范围，用户确认后真实读取；未授权的字段、关系与管理入口被拒绝，页面出现真实访问记录。
- 停用后下一次调用失败，密钥不进入模型、聊天或访问日志。消费链实测见[运行与验收](experiment/CONSUMPTION.md)。

自动检查覆盖状态/数据契约，浏览器检查实际画布、淡出和输入交互，真实模型检查语义工具和页面推进。无需新增完整平台或通用页面生成引擎。
