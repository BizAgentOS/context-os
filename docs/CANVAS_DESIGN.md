# 三页画布与本体可视化设计

更新：2026-09-22。本文负责三页的人类界面、工作步骤与可访问交互；产品需求见 [PRODUCT](PRODUCT.md)，架构见 [DATA_ENGINE_DESIGN](DATA_ENGINE_DESIGN.md)，实施与四页迁移见 [THREE_PAGE_PLAN](THREE_PAGE_PLAN.md)。

这是目标设计：当前已实现三页导航与合页迁移；在线本体关系/属性/实例的消息工作上下文已接入；进一步可视化、融合与治理仍在 FEATURE_013—016 中实施。本文不把旧运行验收视为新方案完成，不另维护任务状态。

## 0.2.0 当前页面

当前入口为数据、本体、发布与接入；首次模型→来源两步初始化，可暂不接数据。保留现有主题、三维本体与共享输入框，新增工作任务、实际检查问题、候选采用和发布版本操作。模型任务切页继续执行，停止是独立明确操作。第三页按工作差异、发布记录、调用方绑定版本组织；升级展示当前绑定版与目标版的真实差异。详细交互与验证见[0.2.0验收](experiment/ENGINE_WORKBENCH.md)。下文保留既有共同画布与局部编辑约定。


## 1. 共同界面与导航

最新尺寸调整（2026-09-15）：输入与“最近一条”字号为 12px，与顶部三个导航标题一致；默认横条缩为 260×40px，展开最大宽度 620px，文本行高 20px。以下历史尺寸以本条为准。

目标导航为“企业与数据 / 本体工作区 / 消费与治理”，对应 `setup / ontology / consumption`。三页始终可以查看和往返；首次使用建议依次进行，但不要求填完企业问卷或接完全部来源才能查看本体。第三页缺少可执行内容时展示缺口，不启用相应消费范围。

保留黑白灰、全高画布与底部居中助手。2026-09-15 按用户补充截图调整：默认显示 300px 宽、48px 高的紧凑输入横条；点击输入区后变宽至最多 740px，单行高度不变，第二行开始随内容增高。输入框上方“最近一条”可展开白色历史面板；下方收起按钮在鼠标移入或键盘焦点进入时显示，触屏始终可见。完全收起后保留底部入口，点击恢复紧凑横条。历史正文完整展示并在面板内滚动，不再渐隐或透出背景文字。面板外仍可操作画布，长内容末尾可滚出覆盖区域。

下方收起按钮隐藏整个助手；Escape 从历史退到输入、再退到收起。收起保留草稿、引用与运行，不触发停止或取消。发送时展开历史以显示回复，之后用户可主动收起；轮询不会擅自重新展开。画布引用和追问自动展开输入框，错误也应可见。历史只展示服务返回的当前页面会话，旧页面迁移历史继续由原入口按需读取。展开状态是纯前端 UI 状态，不进入本体或模型上下文。设置与详情按需轻量展开，不增加任务、历史会话、报告或更新专页。

界面始终区分加载、失败、未保存和真实结果。颜色不是唯一状态表达；使用文字、图标和线型。缩放、布局和面板状态由前端管理，业务操作通过共同服务完成。

## 2. 第一页：企业与数据

### 2026-09-22 企业初始化

空空间先进入居中五步向导：连接模型、认识企业、选择行业本体、连接资料与系统、准备开始。原企业概览作为完成后的目的页，存量空间从“完善初始化”进入，不重置数据，关闭或刷新后可继续。向导仅显示居中五步进度、当前表单及前后步操作，隐藏品牌、全局导航、能力/设置入口、额外说明栏和底部助手；清除这些区域的占位。完成后进入主页才恢复完整界面，研究状态与错误就地显示；普通企业概览保留原有深色样式。

企业名称和行业必填，地区/官网辅助消歧，业务与目标可选；研究需用户明确点击，复用同一 KodaX 和公开研究方法。20 个基础模板优先覆盖 14 个金融细分行业，选择时可删减概念、修改定义，采用只创建可追溯的起步定义，不创建业务实例。接入步骤按行业显示资料、MCP、只读 API 与已有飞书登录，未接入内容不显示为成功。最终核对实际概念、关系、已读取资料、未映射项和构建失败/待处理项；来源可稍后补充。

进度由服务端持久保存；浏览器仅保留非秘密表单草稿。企业提交同时核对档案版本，防止存量或并发更新被旧草稿覆盖，历史字段规范化不丢版本历史。模型密钥保存在本机独立凭据文件，支持留空复用和显式删除，切换端点按地址与协议隔离。详细范围和验证见[冷启动验收](experiment/ENTERPRISE_ONBOARDING.md)。

### 页面与起步路径

上部为企业名牌和基础定义摘要：企业身份、主要业务、产品/服务、服务对象、当前问题、基础概念与待补项。人可直接纠正，展开基础本体摘要，或携同一引用进入第二页。

主体为统一来源目录，按“知识与文档 / BI 与指标 / 业务记录”筛选。来源卡显示名称、用途、获准能力、可读取范围、检查结果和关联概念；详情展开连接设置、负责人、限制、样本或片段、时间与映射状态。API、MCP、上传是接入方式，独立于内容类别。

底部 Agent 根据企业定义、选中来源和业务目标，在同页继续基础建模、资料读取和连接检查。保存企业名称与业务描述不自动切离本页。

[基础本体 Skill](COMPANY_FOUNDATION_SKILL.md) 支持三条路径，形成同一种可查看、可修正的候选：

1. **对话：**记录可引用的用户原话，形成少量有用概念与关系，只补问影响下一步的问题。
2. **资料：**实际解析上传或获准读取的企业资料，展示定义对应片段、冲突与缺口。
3. **公开信息：**确定企业名称与身份后搜索并读取资料；明确无歧义的用户输入即可作为名称确认，同名、简称、集团/子公司混淆时先消歧。搜索摘要不冒充正文，公开信息不补造内部流程或实时经营数据。

候选统一呈现企业认知、核心概念、关系、业务词汇、依据、状态、未决问题和下一步来源建议。候选实际保存后才能作为成果；具体生成方法与完成条件只在 Skill 规格维护。

基础本体可在没有结构化来源时采用。未绑定概念保持“未映射”，不生成虚构实例；后续来源为原概念添加绑定，不另建一套无关本体。公司基础采用、来源可读、映射可执行分别显示。

### 来源接入与可见限制

来源状态分别表达连接可用、能力获准、内容可读、映射待检查、映射可执行；单次读取失败不等于资料不存在，连接成功不等于融合完成。

| 内容类型 | 首轮入口 | 展示与保留的语义 |
|---|---|---|
| 知识与文档 | 现有受支持文件、一类 HTTP/MCP 查询与分段读取来源 | 文档 ID、标题、段落/章节、版本或读取时间、出处与可见范围 |
| BI 与指标 | 一类已定义的只读指标/结果 API 或 MCP 能力 | 口径、维度、粒度、单位、期间/时区、过滤、刷新时间与覆盖范围 |
| 业务记录 | HTTP GET / MCP 记录源及按明确业务键匹配的附源 | 稳定身份、字段、单位、状态、分页、关联键与各来源时点 |

首轮依据实际 API/MCP 契约，不宣称兼容未指定的知识库或 BI 厂商。开发可用独立模拟服务验证，企业认证、工具和字段仍按真实接口确定。已有 CSV/Markdown/TXT 可继续使用；PDF、Word 等未接解析器时明确提示不支持。

发现或批准通用 MCP 工具，不会自动将其登记为本体来源；还需识别内容、输入输出、只读边界与证据能力。凭据只进入受控设置，不进入 Skill、模型上下文或消费说明正文。

## 3. 第二页：本体工作区

### 2026-09-17 动态三维空间（当前在线实现）

本节覆盖此前浅色卡片、固定输入框与定义/对象页内切换方案，企业页和消费页保持既有样式。基础本体默认以暗青黑色三维球体网络呈现；概念、实际定义关系和依据分别有稳定引用。中心按已有定义连接数选取，仅用于初始构图，不推断业务重要性、上下级或关联强度；金色主关系与青绿依据线通过粗细区分，粒子移动是交互反馈，不表示实时数据传输。

节点球体保留原先金/紫/粉色，表面有轻微磨砂。环绕球体的波纹管具有厚度、明暗与投影，并发出向外渐隐的光束。外圈疏密只编码真实关系中不同相邻概念的数量，重复关系与依据不重复计数；更多连接增加管线层数与波纹频率，密集程度有渲染上限。光束与环绕运动是视觉反馈，不表示实时业务流量。

点击概念进入局部聚焦；再次点击概念、关系或依据进入具体内容。局部与详情不是独立页面，没有三态切换标签。点击空白、关闭或 Escape 逐级返回；查看邻接概念时保留原聚焦的返回位置。支持拖动旋转、缩放、复位、暂停动态和减少动画偏好。查找目录提供键盘等价入口，图形环境不可用时沿目录继续操作。

底部继续使用原 textarea、草稿、消息和引用服务：全局右下，局部居中展开，详情与右侧内容栏对齐，宽度、位置和样式连续变化。只查看图不改变已固定到消息的引用；“引用到对话”才调用共同工作上下文。历史、错误、停止和模型状态仍据实显示。窄屏压缩图的水平布局、减少辅助标签，以可滚动详情取代横向扇区，保留输入与关闭入口。

版本、未知、冲突与未映射状态沿服务投影；不添加参考视频中的百分比、业务指标、时间线或不存在的节点。“工作区”保留定义/映射/采用、实际对象与共同取证；离开场景释放渲染资源，旧文件详情恢复普通页面的滚动。实现与验证见 [三维本体验收](experiment/ONTOLOGY_SPACE.md) 及根目录 [视觉核对](../design-qa.md)。

### 原目标布局（保留领域职责，视觉以上节为准）

### 可视化布局与解释

顶部为业务搜索、候选/已采用版本和“定义 / 对象”视角；左侧可收起的类型与问题目录；中央为局部图或等价表格；右侧为当前目标详情。底部保持原前景输入浮层。窄屏以列表、局部图和详情顺序展开，保留同一引用与操作。

默认从基础本体或当前业务问题展开少量相关内容，不铺满企业大图。未知、冲突、候选和已采用状态可辨；样本、分页截断或未知数量明确标注，不显示成全量计数。

| 视角/层次 | 人应看到什么 | 可以做什么 |
|---|---|---|
| 定义视角 | 业务类型、属性、关系定义、说明、约束和未映射概念 | 编辑含义，检查关系方向、身份规则与关联来源 |
| 对象视角 | 实际融合对象、各源属性、局部关联、未知和冲突 | 查询/筛选、展开邻居、比较对象、查某值依据 |
| 含义解释 | 字段、状态、关系和计算口径代表什么 | 追问或提出定义修订 |
| 映射解释 | 来源字段 → 业务身份/属性 → 实际结果及所用规则 | 检查匹配键、覆盖、未匹配/歧义项并修订映射 |
| 证据解释 | 实际记录/片段、读取或有效时间、规则/方法版本与推导依据 | 查看获准原文，纠正具体断言或报告缺口 |

映射和证据在所选对象详情中展开，不增加顶层页面。来源连接配置不充当实际值证据。关系定义与具体关系使用不同引用种类和标题，避免把局部错配修成全局规则。文档片段、BI 聚合结果与明细记录保留各自含义，不统一伪装成普通记录。

### 选择、编辑与差异

图、表格、详情和 Agent 使用同一领域引用，UI 节点 ID 独立管理。选中节点、属性或关系后，输入旁显示可取消的引用；发送时固定目标、基础版本、筛选范围和相关草稿，之后选择变化不改变已发送目标。具体上下文与事件契约见 [AGENT_UI_DESIGN](AGENT_UI_DESIGN.md)。

直接编辑和对话编辑调用同源操作。Agent 可以请求打开证据或差异，不能覆盖用户未保存输入；正在阅读其他目标时提供结果入口，不强行切走。

修订分别选择局部断言纠正、映射调整、身份规则调整、业务定义变更。差异就地展示新增、移除、改值、受影响实例、检查结果与未检查范围；抽样检查只能声称样本结果，不能等同于现实业务正确性。

以“投诉关联错楼栋”为例，完整流程如下：

1. 选中具体关系，确认两端对象、当前值和适用范围，查看证据入口。
2. 读取源记录、映射与规则，判断是源事实、局部匹配还是全局定义问题。
3. 保存最小修订候选；并列显示现值、建议值、依据、基础版本和影响范围。
4. 运行检查及影响预览；需要业务决定时针对具体候选处理，已有明确授权且满足条件的普通操作直接执行。
5. 提交由共同服务核对；版本冲突时保留候选、展示变化并重新检查，不覆盖较新修改。
6. 依据真实回执显示已保存、已采用、冲突或失败及实际新版本；源系统仍只读，不能把内部纠正称为源记录已修复。
7. 沿同一 `changeRef` 到第三页查看消费者影响，处理发布/迁移与授权，再回到原对象位置。

本页负责内容修订与采用；第三页负责消费发布、迁移与权限。跨页不复制候选，也不重复批准同一决定。源记录有误时可保存范围明确的纠正依据或反馈；来源变化后检查其是否仍适用。

首轮治理在接入检查、用户请求、查询异常和修订检查时触发，按共同问题汇总证据与建议。没有默认常驻巡检，不声称发现未观察到的远端变化；Agent 运行规则见 [AGENT_DESIGN](AGENT_DESIGN.md)。

## 4. 第三页：消费与治理

### 2026-09-17 MCP 数据集工作台

在线第三页以“让本体，成为 Agent 的数据”为主线，沿用前两页的深青黑背景、白色细网格、浅青主按钮与暖金色重点。顶部解释选择范围、启用数据集、连接 Agent 三步；左侧展示已采用本体和实际计数，右侧展示数据集、开放范围、固定版本及真实读取时间。候选本体只引导回第二页采用，不自动发布。

创建弹窗逐项选择概念、关系和可选业务字段；关系两端必须同时选择，依据需单独授权。侧栏核对字段及依据，提交后立即显示一次性密钥，再加载可复制的本机 MCP 配置。配置加载失败仍可保存密钥并重试；连接测试使用真实 MCP 客户端，明确其验证范围。停用后及时更新状态，长列表保持关闭入口可见，窄屏单栏，减少动画偏好关闭过渡。原许可与迁移保留在“管理已有访问范围”，离线演示保留原消费展示。此小节覆盖下文旧默认布局；数据合同见 [消费设计](DATA_CONSUMPTION_DESIGN.md)，验收见 [MCP 数据集](experiment/ONTOLOGY_DATASETS.md)。

### 建立消费入口

主体为消费者、许可范围、语义版本、待处理变更及实际调用。详情包含接入配置、限制、生成的契约说明、凭据交付、撤销与迁移影响。初期仍是本地单企业空间，不把员工身份、记录级隔离或公网托管画成已具备能力。

用户按以下步骤建立可用消费视图：

1. 选择已采用且已检查可执行的本体子集，明确用途、调用方、类型、字段、关系及可开放证据；未就绪项显示原因。
2. 查看实际获准的描述、查询、关系与证据/解释能力及语义版本，核对范围。
3. 从实际契约生成 API 说明、OpenAPI 描述和 MCP/HTTP 示例，完成受控凭据交付。
4. 用真实调用检查结果、范围、时间与证据，再查看调用记录或撤销入口。

说明与示例不能列出未实现方法、扩大许可或带入密钥；本轮不靠模型自由生成接口代码。新增融合/证据使用版本化统一契约，现有 `/v1`、`/v2` 读取语义保持兼容。端点、响应和授权规则只在 [DATA_CONSUMPTION_DESIGN](DATA_CONSUMPTION_DESIGN.md) 与 FEATURE_016 维护。

### 同一变更的消费影响

第二页采用新本体后，第三页沿同一 `changeRef` 展示已采用内容、受影响消费者、字段、关系和方法。用户指定目标版本，检查兼容与授权后决定迁移；内容采用不自动迁移消费者，新字段不自动授权。需改内容时返回第二页原变更，不另造候选。

旧消费者按旧契约工作；旧来源不兼容或权限撤销时明确失败，不承诺旧版本永远可用。源事实按读取策略刷新，语义版本和权限变化单独展示；在线各来源读取时点不冒充跨源原子快照，来源无历史能力时不承诺历史回放。

源连接权限与消费者权限分别管理。字段、身份、关系端点、文档片段、指标和证据均受返回范围控制；schema、示例、计数和错误也不能泄露范围外内容。访问与变更记录只保留必要依据，不默认保存完整原文或密钥。

## 5. 无障碍、恢复与验收

无障碍树的借鉴是从同一领域状态表达身份、角色、名称、状态、关系与动作。Agent 直接获得业务引用与接口；浏览器使用标准 HTML/ARIA、焦点和状态播报，不将完整本体塞进页面标签或通过读自己 DOM 取得业务数据。

关系图提供可键盘操作的等价列表和详情；选择、加载、错误、未保存和提交状态可感知。窄屏不能只保留浏览而丢失修订入口；需验证实际键盘路径，必要时使用屏幕阅读器，不能只检查 ARIA 属性存在。

页面、运行、资产与业务完成分别显示；保存草稿、采用内容、发布消费不是同一状态。停止/切页保留已完成成果，恢复依据持久回执与当前权限；规则见 [AGENT_UI_DESIGN](AGENT_UI_DESIGN.md)。

四页迁移保留旧入口、成果引用、历史依据与现有授权，不全量拼接企业/来源对话。旧草稿只有浏览器内存，先保存仍可读取的两份再分别恢复；已卸载内存无法恢复。新版增加草稿恢复，演示、离线分享和旧快照兼容按 [THREE_PAGE_PLAN](THREE_PAGE_PLAN.md) 实施。

验收覆盖空态与存量，三条基础起步路径，各类来源的实际读取，定义/对象及图/表一致，字段映射/证据与范围，局部/全局修订差异，同一变更的采用和消费迁移，桌面/窄屏/键盘，以及停止、冲突和恢复。只报告实际覆盖，不用旧文件样本演示替代在线链路验收。
