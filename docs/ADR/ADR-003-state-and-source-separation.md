# ADR-003：来源、语义与各类工作状态分离

- 状态：Accepted（设计决定，非实现完成）
- 日期：2026-09-11
- 部分替代：结构化记录的复制与发布一致性由 [ADR-004](ADR-004-managed-snapshots-and-pinned-releases.md) 决定。

## 背景

企业数据、已采用本体和一次 Agent 会话具有不同生命周期，也受不同权限与更新频率约束。
把它们放进同一份上下文或运行变量，会造成失去会话就失去业务、恢复旧状态就恢复旧权限的问题。
多源融合还需要区分来源读取时点、业务有效时间与本体版本，不能用一个版本号代替全部含义。

## 决定

1. 来源记录保留其外部系统身份和来源约束；原始数据按授权按需读取，不自动全量复制。
2. 语义状态独立保存已采用定义、映射、身份对齐及治理记录；来源记录、人工陈述、候选与推导结论分别表达。
3. 治理任务状态承载候选、待处理事项、进展和执行回执；任务恢复不能将候选当作已采用事实。
4. 运行状态承载单次循环的变量、对象句柄与执行进度；REPL 或代码变量不作为企业长期记忆。
5. UI 状态承载页面选择、布局和未提交草稿；页面选择变化不能重新指定已发送任务的操作目标。
6. 各层通过稳定对象与变更引用关联；恢复时重新核对当前权限、版本和来源可用性。
7. 语义、映射、方法、源读取、权限与工作上下文的版本或时点分开表达，不承诺跨源原子快照。
8. 属性与关系保留相应证据和有效时间；未知、冲突、截断与无权限不得统一表达为否定事实。

## 取舍与替代

不把完整企业数据加载进 Agent 上下文，也不依赖聊天历史重建权威业务状态。
不承诺绝对零复制；必要缓存与证据保留按具体需求确定范围、权限和生命周期。
分层会增加引用和恢复校验，但避免用失效句柄、旧权限或旧来源数据继续提交。
不因为需要溯源就承诺任意历史回放；来源未提供历史且未保留证据时，应明确不可恢复。

## 后果

按需上下文从稳定引用展开，遵守字段、关系、分页和证据预算；上下文摘要不是事实底座。
一次消费回执需要表达真实来源读取与完整性，语义版本相同不保证来源内容相同。
事实修正、规则修改和源系统写回分别记录影响；当前只读来源范围不会由治理记录自动扩展。
UI 草稿是否持久化按具体任务实现；不能承诺恢复已经丢失且未保存的历史内存。
治理采用与对外消费升级是关联但独立的决定，不因保存本体就自动升级已部署客户端。

## 重议条件

获准任务明确要求离线消费、证据保留、历史重放或更强一致性时，针对范围与成本重新决定。
重议需说明保存什么、保存多久、何种身份可恢复及失效处理，不以“长期记忆”统称不同状态。
