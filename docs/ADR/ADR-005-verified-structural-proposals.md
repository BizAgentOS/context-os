# ADR-005：结构提议经确定性复验与人采用

- 状态：Accepted（设计决定，非实现完成）
- 日期：2026-10-19
- 关系：延续 ADR-001、002、004；取代 v0.2.3 目标中“程序是唯一结构来源、Agent 永久只改名称说明”的限制。当前结构锁在对应 Feature 完成前继续有效。

## 背景

只依赖发现程序会遗漏业务关系、身份对应与非显然映射；让模型直接决定结构又无法证明身份、字段、匹配与影响。需要让程序、人、Agent 使用共同流程修复可解释的缺口。

## 决定

1. 本体为显式语义、绑定、数据与查询分层模型，Helix 等程序只是结构提议者之一。
2. 程序、人、Agent 均可提出实体、属性、关系、绑定与身份规则 / 决定的变化。Agent 提议须附业务依据，程序提议保存规则与数据特征。
3. 提议经同一确定性服务复验、展示影响与查询前后预览，再由人采用。Agent 无结构采用工具，不能用提示词、自填批准或文本确认越过领域服务。
4. 文档不生成实体、属性、关系结构，只补名称、别名、说明、依据、未知与冲突，并用于问答检索。
5. 自动采用仅按 ADR-007 的有界规则执行；结构复验通过不等于业务语义真实。

## 取舍与替代

拒绝让模型直接保存生效结构，也拒绝将所有关系永远限制为程序能发现的规则。接受统一变更、复验与人审的成本，换取可追溯的修改和对遗漏关系的修复能力。

## 后果

需要稳定语义身份、统一变更、检查与预览回执；源或基线变化后重新复验。现有修订工具不能在这些服务落地前绕过结构锁。当前提示词继续禁止通过旧入口新增结构，不将目标能力写成已可调用工具。

## 实施关联

FEATURE_036 同步文档与提示词；FEATURE_040—044 落地显式模型、变更、身份与队列；FEATURE_048 接入构建工具。状态和验收只在[台账](../FEATURE_LIST.md)与[设计块](../features/v0.3.0.md#feature-040)维护。

## 重议条件

有真实证据证明特定结构变化可由确定性规则安全自动采用，或试点需要不同职责审批时，另行记录适用范围和验收，不能从“检查通过”直接推出自动采用。
