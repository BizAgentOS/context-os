# ADR-007：自动结构采用只限首次构建与同结构重绑

- 状态：Accepted（设计决定，非实现完成）
- 日期：2026-10-19
- 关系：补充 ADR-004、005；收紧自动接入任务的结构生效范围。

## 背景

首次接入需要尽快形成可查询结果，但后续同步中出现新关系、新合并或实体降级，不能未经审阅改写企业含义。单凭任务被称为“自动构建”不能授予无限采用权限。

## 决定

1. 工作区没有已采用本体时，首次构建中检查全部通过的部分可自动采用；失败或不确定部分进入待处理。
2. 后续同步只有结构不变的重新绑定可自动采用；身份规则、身份决定与结构变化不能伪装成重绑。
3. 新关系、新合并、实体降级等后续程序结构变化，以及 Agent 结构 / 身份提议，必须进入待处理，由人采用。数据质量熔断必须由人决定。
4. 名称、别名、说明是非结构普通编辑，可按授权自动采用；首次构建后的批量命名仍作为一项待处理由人确认。这项例外不允许借说明编辑改变端点或身份。
5. 人在界面提议结构时可显式选择“复验通过后立即采用”；决定绑定具体内容和基线，变化后须重新复验。该项是人的提前决定，不是 Agent 自动采用。
6. 每次采用单项或一批变更形成一个工作版，有完整决定、操作者、复验与影响回执。文本口令不能采用。

## 取舍与替代

拒绝所有同步结果自动生效，也不要求每次同结构刷新都让人确认。保留冷启动速度，将语义变化与数据更新分开。

## 后果

服务必须比较结构与身份变化、确定是否首次、保留不确定项，并在事务内检查基线。数据问题保留旧快照继续服务。名称变化不应强迫结构重建或扩大自动采用范围。

## 实施关联

FEATURE_041 统一采用规则与状态；043、044 处理说明 / 命名 / 待裁决；060 提供质量熔断。现有程序自动路径仍需按这些票收敛，本 ADR 不证明所有分支已实现。见[语义合同](../SEMANTIC_CONTRACTS.md)。

## 重议条件

出现经实测可自动处理的新变化类别时，明确变更类型、失败回退、影响与误改率，再修订边界；不得因模型自信或结构校验通过直接放宽。
