# ADR-002：共同本体操作服务与多客户端

- 状态：Accepted（设计决定，非实现完成）
- 日期：2026-09-11

## 背景

人类用户治理本体，外部 Agent 按任务消费，内部 Agent 协助建模与修正。
三个入口若各自实现业务逻辑，会产生不同证据、不同权限和互相矛盾的操作结果。
前端无障碍树与 NOOA 提供表达方式的启发，但不能成为企业业务执行或授权边界。

## 决定

1. 本体引擎负责业务定义、映射、稳定身份、融合、查询及证据关系；领域规则以可检查的实现执行。
2. 共同操作服务负责真实授权、版本和前置条件检查、提交、后置条件验证及执行回执。
3. 前端、内部 Agent 对象环境、外部 HTTP/MCP/SDK 是不同客户端，复用同一套领域能力。
4. NOOA 风格对象是这些能力的引用与调用表达；类型、发现结果或方法可见性不授予权限。
5. 服务按当前调用身份限制对象、字段、来源和操作；同源契约不意味着每个客户端可见内容相同。
6. 组合工具中的每次业务操作都经过服务检查；外层 Hook 或前端按钮状态不能代替该检查。
7. 操作描述可包含前置、效果、后置和完成条件，但方法实现及确定性规则不能靠模型生成文本冒充。
8. 外部常规读取直接消费授权服务，无需打开产品页面，也不依赖内部 Agent 的模型推理。

## 取舍与替代

不让内部 Agent 操作页面来完成本产品已经具备的领域能力，也不让各入口独立修改本体存储。
统一服务增加契约协调成本，但能统一证据、并发、幂等和失败语义。
这是逻辑职责划分，可保持在当前单服务中，不要求拆成微服务或建设完整本体推理平台。

## 后果

业务操作需返回可核对的结果；结构化返回与校验通过均不等于现实事实正确。
来源连接凭据与对外消费权限分开；发现来源或知道对象引用不足以读取其内容。
前端由共同语义形成面向人的视图，HTML/ARIA 继续服务真实无障碍，不承载完整本体。
契约、客户端描述和 SDK 应同源；客户端发布升级、服务实现与当前权限仍需分别落实。
取消、幂等及并发控制在实际效果边界生效；不能依靠提交后的 Hook 撤销已发生的副作用。

## 重议条件

实际接入对象无法通过共同服务表达，或出现经验证的性能、隔离需求时，评估适配或服务拆分。
任何旁路必须说明如何保持相同授权、证据和提交保障，不能以客户端类型作为免检理由。
