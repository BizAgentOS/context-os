# ADR-001：KodaX 单循环与产品宿主分工

- 状态：Accepted（设计决定，非实现完成）
- 日期：2026-09-11

## 背景

Data Engine 的内部 Agent 协助建立和治理企业本体，KodaX 已承担模型与工具执行循环。
NOOA 的对象与方法组织方式有助于渐进发现，但不要求再引入一套 Agent 运行框架。
需要固定运行层与产品层的职责，避免重复调度、停止控制和相互冲突的执行状态。

## 决定

1. 内部 Agent 使用一个 KodaX 模型与工具循环；产品不再包一层独立的模型决策循环。
2. KodaX 承担其实际支持的运行、工具调用、事件及停止控制；通过适配层接入产品。
3. 产品宿主绑定工作区、执行身份、任务目标、上下文范围与工具集合，并将运行结果交付界面。
4. NOOA 用于指导领域对象引用、类型、方法说明、按需发现和受限组合；不要求采用其 Python 运行时。
5. 业务授权、版本校验和实际效果由共同领域服务负责，宿主与运行钩子调用这些服务。
6. 产品运行 Skill 组织任务方法和完成判据，不自行取代连接器、持久化或权限执行。
7. 尚未核实的 KodaX 能力先进入能力登记与适配评估，不因文档存在就视作已接入。

## 取舍与替代

不采用 KodaX 与另一套 Agent 框架共同调度同一任务，减少双重重试、取消和会话状态。
也不在产品层复制完整通用运行框架；代价是需要适配 KodaX 已公开且实际可用的接口。
领域对象的表达独立于运行框架，保留未来替换适配器的空间，但不预建第二套运行实现。
不照搬参考产品的 Electron、daemon 或权限等级；部署形态以本产品需求为依据。

## 后果

一次任务的身份、范围及停止信号需要沿调用链传到真实业务提交点。
工具成功和模型回复均不能代替业务完成回执；错误与中断必须反映实际效果。
运行能力归属查 [能力登记](../KODAX_CAPABILITY_LEDGER.md)，任务方法归属查 [内置 Skill 约定](../BUILTIN_SKILLS.md)。
具体适配与内部 Agent 行为由 [AGENT_DESIGN](../AGENT_DESIGN.md) 细化。

## 实施关联

[FEATURE_012—016](../features/v0.1.0.md) 继续沿用既有 18 张票，不因本决定新增运行框架任务。
012 承接工作上下文与迁移；013 承接基础本体任务方法；014—016 通过共同服务提供业务能力。
当前运行四页、目标三页的差异由 [三页计划](../THREE_PAGE_PLAN.md) 管理，不代表 Agent 重建。
[产品主设计](../DATA_ENGINE_DESIGN.md) 保持高层分工，本记录不冻结 SDK 调用签名。

## 重议条件

已获准的任务出现现有 KodaX 接口与适配层无法满足的明确运行需求时重议，并附实际限制证据。
更换底座或引入第二运行循环须说明状态归属、停止传播和兼容迁移，不能仅以框架偏好决定。
