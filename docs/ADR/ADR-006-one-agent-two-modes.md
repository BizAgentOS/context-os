# ADR-006：一个 Agent，构建与问答两种模式

- 状态：Accepted（设计决定，非实现完成）
- 日期：2026-10-19
- 关系：延续 ADR-001 的唯一 KodaX 循环；模式取代页面作为工具和数据视图的主要边界。

## 背景

页面工具集将观察、修订与消费混在一起，业务问答可能触发治理写入，切页又被误认为切换 Agent。问答验证和构建修复需要连续交接，同时保留不同权限。

## 决定

1. 一个 Agent、一个跨页会话体系，构建与问答两种模式。页面只决定默认模式与焦点，用户切换模式，Agent 只能建议。
2. 构建可观察原始来源、提议、复验、预览与普通名称说明编辑；不能自行采用结构。问答只读工作版 / 指定发布 / 发布 + 接入方范围，只允许额外创建缺口单。
3. 宿主按模式装配工具、视图与写入资格，执行服务继续复核；不靠 Prompt 实现只读边界。问答无原始源、快照 SQL、待处理或提议工具。
4. 问答无法回答时保存可重放缺口，经用户触发转构建；采用后由用户触发复问，复问成功才标确认。
5. 提示词为身份、通用规则、构建模式、问答模式四层；完整历史长期保存，模型上下文单独裁剪。

## 取舍与替代

不为三页或问答分别创建独立 Agent / 事实库，也不让同一工具全集仅靠文字提示区分权限。接受模式隔离和交接状态的实现成本，保持同一企业语义和用户会话。

## 后果

需明确视图与模式标签、独立工具合同、缺口状态和执行回执。切页不换会话，不停止运行；模式切换只影响新消息。当前按页面的单一模式在 FEATURE_048、052 前保留，不能把本 ADR 描述为已实现。

## 实施关联

FEATURE_036 先更新身份与通用层；046、047 提供面板 / 会话；048、052 提供模式层；053、054 实现回答联动与缺口。见[版本设计](../features/v0.3.0.md)。

## 重议条件

有试点证据要求独立管理身份、审计主体或不同模型时重议运行装配，仍须保持共同语义与服务端权限；不因 UI 页面数量增加拆分事实库。
