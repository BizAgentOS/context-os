# ADR-004：受管数据快照与发布锁定

- 状态：Accepted（设计决定，非实现完成）
- 日期：2026-10-15
- 关系：替代 [ADR-003](ADR-003-state-and-source-separation.md) 第 1 点"原始数据不自动全量复制"及第 7 点"不承诺跨源原子快照"中关于结构化记录的部分；其余各点继续有效。

## 背景

用户确认 ADE 的工作方式是：来源数据持续更新，人借助内部 Agent 持续修订本体，第三页按版本发布数据底座。
v0.2.0 的发布只固定本体、映射与契约，事实在消费时实时回源（`on_demand_not_atomic`、`historicalReplay:false`）。
因此同一发布版本的内容会随来源变化；来源结构变化会直接破坏已发布版本；发布前无法展示数据差异，事后无法复现结论依据。
本体构建只在有界样本上做关系与身份判断，也无法给出全量匹配率。

## 决定

1. 结构化记录来源（HTTP/MCP 记录能力、上传 CSV）默认同步为本地不可变快照：DuckDB 读入后写成 Parquet，每版附完整列画像与指纹。实现复用 Helix Foundry 执行器（Apache-2.0，见 `third_party/helix-foundry/`）。
2. 每个数据集可设为 `snapshot`（默认）或 `live`。`live` 数据集、知识片段与 BI 指标继续按 ADR-003 实时读取，并在回执中标注。
3. 指纹不变不新增版本；字段结构变化的新版本进入待确认，已采用版本继续服务；唯一性丢失、空值上升作为问题报告，不自动修复。
4. 本体发现、映射检查与验证在快照全量上执行；覆盖不完整（达到行数上限）时明确报告，不视为全量。
5. 发布版本固定"本体修订 + 映射 + 各快照版本"。旧发布的消费者继续读取其锁定快照；`live` 部分仍按实时读取表达。
6. 被任一发布引用的快照不清理；其余每个数据集保留最近 5 版，更早的文件删除且不可恢复。
7. 快照只存放于本地状态目录，与来源凭据分离；执行在最小环境的子进程中运行，仅允许单条只读查询，禁用外部文件访问。

## 取舍与替代

接受本地数据副本带来的存储、同步与数据安全成本，换取可复现的发布版本、全量构建质量和数据差异。
不引入 HelixDB 图存储或 Helix 的模型循环与权限体系：对象按需从锁定快照查询，身份、治理与授权仍由 ADE 共同服务负责。
不承诺来源的业务时点历史：快照时间是同步时间，不等于公告或业务生效时间。
不承诺 DuckDB 跨版本指纹稳定；升级 DuckDB 后首次同步可能产生一次内容相同的新版本。

## 后果

快照来源的消费回执可引用 `{datasetId, snapshotId}`，`historicalReplay` 在快照范围内为真。
发布检查需纳入快照版本；待确认的结构变化阻止发布，直到用户确认或改为实时读取。
已发布版本的数据保留时间由发布引用决定，撤销全部引用后才进入普通保留策略。

## 重议条件

需要多租户隔离、远程对象存储、行级增量同步或按业务时点选择版本时重新决定。
