## 集成边界与修复

分层读取和新提议持久化不重写历史模型。名称、说明按稳定语义 ID 投影，绑定本身不因措辞变化重新生成；旧单列映射入口不能表达复合 / 中间表关系或别名归属歧义时，明确拒绝修订。独立回归验证无关属性编辑保留复合外键的租户隔离。

业务单键保留实际字符串、数字或布尔类型，复合键保留多个属性的顺序；业务身份与适配器行身份不同时使用有类型的对象编号，直接 `id` 与 `where.$id` 共用解码，查询回查不按错误的适配器类型转换；外键仍可通过明确暴露的适配器行号属性关联复合身份对象。主 / 补源行过滤贯通样本、融合与快照检查，不能从范围外取值。

工作版通过稳定 ID 投影当前名称与说明；同一模型 ID / 版本的旧发布固定其原语义定义，新发布保存新的语义投影。发布工厂从真实发布重新计算语义与快照权威，调用者传空值、错误快照或 `fixedSemantic=false` 均不能降为实时；显式实时例外仍按发布策略读取并固定语义。

局部纠正的查询、提议基线、检查和采用共同按稳定关系 ID 识别，当前名称优先于历史别名；交换关系名称不会串用决定，已检查的旧候选也不能覆盖改名后新采用的决定。候选保存原模型定义，来源事实变化仍要求重新提议。

中间表查询遵守同一快照集合与来源版本，保留局部纠正。缺失目标、无效关联键或读取预算未覆盖部分不能报告完整；孤儿目标回归返回已有对象以及 `complete=false / unmatchedTargets`。已有发布与 v4 的固定语义、快照、撤销和来源许可由独立回归核查，不在真实空间补造发布或接入。
