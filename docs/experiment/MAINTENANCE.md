## 本次交付

- 四页始终可进入。首次可以按企业 → 数据 → 本体引导，回到已完成页面后在原页维护。空白导航不调用模型、不创建企业成果、不自动判定完成。

- 验证问题由真实 Agent 转为已有受限对象方法，保存实际结果、覆盖范围、模型/来源版本和证据；用户可以确认符合预期或需要调整。重新验证明确使用最新资料，旧结果不覆盖。
- 来源详情可编辑用途、负责人和限制对外使用的列。分类单独保存，不制造原始数据版本变化。最新限制同样约束旧授权中的字段、编号查询与关系连接，历史授权仍使用的旧列也能分类。
- 失败、冲突、新来源、新版本和待确认留在画布。查看/滚动画布时近期聊天淡出，聚焦输入或发起对话时恢复。输入框继续是全高画布上的前景浮层。

## 运行

沿用 `npm start` 和本机管理链接，默认端口 8788；本次用户当前 8792 服务已保留原有运行目录并重新加载新实现。隔离验证空间为 `local-state/maintenance-verify`，验证时使用 8793；它不覆盖用户当前企业记忆，也不提交到 Git。

页面操作：

1. 企业页输入名称/业务，或点击已有陈述直接编辑。
2. 数据页上传 CSV、Markdown 或 TXT。点来源进入“用途与使用范围”编辑说明、负责人和敏感列。
3. 本体页从文档讨论少量概念，再用实际记录形成并检查映射。需要采用时在具体候选上决定。
4. “验证”输入一个具体问题。点结果查看实际对象、业务判断与来源；可以继续打开本次快照中的对象及关系。
5. 同名上传更新来源；回到验证页重验。新旧结果并列保留，旧记录标注资料或定义已有变化。
6. 连接页继续管理已有明确授权。确认验证结果不会扩大授权，也不会改变消费者固定的数据版本。

新行为使用公共应用、Workspace 和真实 HTTP 边界做有意义的先失败/后通过检查：

- 空白四页自由往返、非空文档检查后推进、空/未读来源不假完成。
- 文档概念引用实际来源，空白文档/无记录 CSV/失败来源不能支持概念，草稿不能被采用或查询成对象。
- 业务验证来自真实对象执行；不支持的操作、错误对象、未检查候选不会保存为成功结果；空集保留来源范围，分页结果保留部分覆盖语义。
- 同一页面普通追问保留调查快照；明确重验使用新版本且不改旧记录。同一问题执行编号稳定，重复写回不增加执行编号，审核旧结果不制造最新待办。
- 验证对象查看使用保存的准确模型/来源快照，旧记录读 v1，新记录读 v2；普通本体视角仍读定义保存时的版本。
- 业务判断和来源使用范围只能从管理入口保存，过期版本被拒绝；重启仍保留结果、说明和敏感列。
- 当前/历史敏感列、编号过滤、关系两端连接字段及目标字段均限制真实消费，旧凭据即时受最新分类约束；不相关的已授权投影仍可读取。
- 用户直接确认保留原值后冲突提醒消失，历史冲突及证据保留，模型不能伪造该用户决定。

## 真实模型与浏览器记录

使用真实 KodaX + DeepSeek，在隔离空间从空白开始创建“澄川热力”，主营居民供热，目标为查证投诉办结后的回访依据。前三份资料是刻意保持很小的开发样本：一份业务口径 Markdown、两条投诉 CSV、最初一条回访 CSV。资料及验证运行文件保留于忽略目录，不作为模型质量基准。

真实模型读取文档并保存“投诉/回访”概念草稿；接入两份记录后提出映射、修订并预览。开发者通过管理接口对准确候选执行采用；采用版本为 9，生成两类对象和两条关系。这是开发验收中的确认，不代表实际业务方已确认本体含义。

同一业务问题：“投诉 C1 已办结（closed），办结后是否有供暖恢复的客户回访依据？”实际得到：

| 检查 | 采用的本体 | 回访来源 | 实际执行结果 |
|---|---|---|---|
| 第一次 | 同一本体 v9 | v1，F1 为 not_recovered | negative_callback_evidence；只有未恢复反馈 |
| 浏览器同名补资料后重验 | 仍为同一本体 v9 | v2，保留 F1，增加 F2 recovered | conflicting_callback_evidence；同时存在未恢复与已恢复反馈 |

第二次由浏览器“验证这个问题”实际发起，并使用最新资料。旧验证仍引用回访 v1，结果未改变；新验证引用 v2，问题原文相同，执行序号从 1 到 2。没有用新增事实自动重写本体。由于此小样没有足以判定最终状态的时间规则，结果保留冲突，不能推断小区/楼栋最终恢复。

浏览器实际检查：

- 从空白自由进入数据消费与本体，空态解释缺口；文档概念、映射定义和对象可见。
- 点击验证记录查看字段、回访判断与证据，并打开该次快照中的具体对象。
- “符合预期 → 需要调整 → 符合预期”连续修改均可保存，操作不会永久禁用。
- 直接编辑企业名称；来源用途填“关联投诉处理进度与回访依据”、负责人“客服部”、phone 限制勾选保存成功，原始投诉来源仍为 v1。
- 通过真实文件选择器上传同名回访 CSV，资料升为 v2，原页显示更新提醒；重验并确认后保留两份结果。
- 1280×900 与 390×844 页面检查。窄屏页面宽度等于视口 390、无横向溢出；画布底部仍是 844，输入层 position=absolute。
- 查看画布时对话 opacity=0，聚焦输入恢复到 1；原内容不因淡出删除。透明区域仍由背景接收交互，长内容有可滚动尾部空间。
