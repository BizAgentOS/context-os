# 自定义模型 API（T017-01）

2026-09-15；基线 `14dfa5b` 加本票改动，当前本地单企业范围、未发布。

## 使用

顶部模型设置选择“自定义 API”，选择 OpenAI 或 Anthropic 兼容协议，填写 API Base URL、模型 ID 和 API Key。OpenAI 兼容一般填 `https://example.com/v1`，SDK 追加 `/chat/completions`；Anthropic 兼容一般填 `https://example.com`，SDK 追加 `/v1/messages`。按网关说明保留其路径前缀，本地模型可以使用 `http://127.0.0.1:端口/v1`。

点击“测试连接”会先保存设置再发起模型请求；成功后点击保存关闭。这里测试的是基础模型回复，不保证上游模型具有本体治理所需的完整工具调用能力。它也不是任意 REST API 的适配器。不支持自定义请求头、OAuth、匿名接口或 Responses 专用协议。

地址/协议/模型持久化到当前企业设置，API Key 仍仅在服务进程环境中；完整服务进程重启后需重填自定义密钥。标准化 Base URL 和协议共同决定凭据标识；切换到未配置的新地址或协议时显示未配置，连接测试不会发出请求。回到同进程已经配置过的相同地址/协议可以复用其原密钥。

URL 仅接受 HTTP/HTTPS；拒绝 URL 账户密码、查询参数、fragment 及完整生成路径。不要把密钥放进 URL。保存无效配置不会替换已有配置，服务错误会隐藏已知模型密钥。

## 接入与实际验证

复用已安装 KodaX `0.7.96-beta.2` 的 公开 `registerModelProvider` 与原生 OpenAI/Anthropic 兼容基类，不升级 SDK，不增加另一套模型循环。内部 provider 名称按工作区和端点区分；原有固定厂商与 GLM 路径保留。连接测试与正常聊天走相同 KodaXDriver，领域工具和权限仍由宿主管理。自定义客户端通过公开 `buildClient` 扩展点配置 fetch，强制不跟随重定向；3xx 转为明确失败，固定厂商和数据连接器的传输保持不变。

公共 HTTP 回归 `tests/agent/custom-model.test.ts` 使用真实 KodaX Runtime 与独立本地 SSE 协议夹具，无模拟 driver，无真实模型费用：

- 实际收到自定义路径、准确模型名和 Bearer/API-Key 认证；OpenAI 与 Anthropic 两种协议均通过。
- URL 或协议变化后无对应密钥时阻止发请求；不同地址的所有观测请求均使用各自密钥。
- URL、协议与模型在服务重开后恢复；无效 URL 被拒绝且不改变现有设置。
- 上游 401 返回包含测试密钥的错误时，管理 HTTP 回执隐藏密钥。
- 两种协议收到 307 到另一独立 origin 时均失败，另一服务未收到任何请求。修复前真实复现 Anthropic `x-api-key` 被转发，新增反例先红后绿。
- 空查询/片段分隔符（尾随 ?/#）也被拒绝，不能绕过完整生成路径检查。

测试开发中发现 KodaX 会对已结束运行发起后台 learning review，因此断言显式区分连接检查消息与后台消息，同时对全部收到的请求检查端点/密钥对应，不把请求总数错误地等同于前台运行次数。测试夹具不是“真实模型兼容性已证明”；用户自有网关仍需要填写密钥测试。

浏览器在独立临时企业使用 8 秒延迟测试 driver 复现并修复时序问题：测试中 URL/协议/厂商/模型/密钥及关闭按钮锁定，Escape 不关闭，测试结束恢复操作。此项是 UI 等待/回执测试，不是模型传输证据；传输证据来自上面的真实 KodaX + HTTP 夹具。

最终验证：`npm run check`（类型检查、122 项 Node）、22 项 Python、HTML 导出、JavaScript 语法及浏览器检查通过。Standards / Spec 独立复核均为 0 项未解决发现；仅本地提交，未发布。状态以功能台账和本票设计块为准。
