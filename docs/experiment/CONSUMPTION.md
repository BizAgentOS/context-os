# 数据消费：运行与验收

2026-09-08，FEATURE_007 / T007-01、T007-02。第四页已完成本地 MVP 链路：对话提出调用方与读取范围，用户查看后启用，独立客户端读取，页面查看真实记录，停用后拒绝下一次请求。

## 运行与体验

在项目根目录运行：

```sh
npm ci
npm start
```

服务仅监听本机 `127.0.0.1:8788`。首次打开终端给出的管理链接；其中 `#access=…` 是本地管理员入口，页面读取后立即移除地址片段并建立 HttpOnly 会话。以后同一浏览器可直接重新打开普通地址；换浏览器或清除会话后重新使用管理链接。管理凭据在本地状态目录的 `admin-token`，不交给消费方，也不输入模型对话。

模型沿用已有设置：可在右上角配置，或使用服务进程的 `DEEPSEEK_API_KEY` 等环境变量。调用方使用的 API Key 与模型 API Key 是两种独立凭据。

1. 完成企业与资料创建，在第三页查看并采用一个本体。第四页此时解锁；采用本体不自动开放访问。
2. 进入“数据消费”，例如输入：“让客服助手查询投诉编号和状态，不给联系电话，也不需要关系。”助手读取当前本体，保存对应授权草稿。
3. 点开调用方，查看允许的对象类型、字段、关系及绑定的本体版本。只有当前待确认的具体版本提供“启用访问”；助手不能自行签发权限。
4. 启用后单独显示一次调用方 API Key；关闭窗口即清空，不写入聊天、模型输入或访问记录。遗失时先停用，再登记并确认新授权。
5. 用独立客户端访问下面的只读 API。画布和调用方详情会显示真实成功与拒绝记录；展开记录可看原因与有依据的版本信息。
6. 点击“停用访问”，下一次请求立即失效。停用先写入授权状态，不等待模型成功停止，也不排在可能等待模型的导航请求后面。

界面保持四个黑白画布、底部一个输入框，以及至多三条逐渐淡出的近期对话。消费页不提供文件上传、任务列表或报告页面。

## 最小客户端

以下以授权中确实存在的中文类型“投诉”为例。把启用时保存的调用方密钥放到客户端环境变量 `DATAENGINE_CONSUMER_KEY`；不要使用管理或模型凭据代替。

```sh
curl --get 'http://127.0.0.1:8788/v1/objects' \
  --header "Authorization: Bearer $DATAENGINE_CONSUMER_KEY" \
  --data-urlencode 'type=投诉' \
  --data-urlencode 'fields=$id,状态'
```

| 参数 | 用途与限制 |
|---|---|
| `type` | 必填，必须是授权的本体类型 |
| `fields` | 可选，逗号分隔的明确字段；省略则返回该类型获授权的字段。`$id` 也必须显式获授权 |
| `id` | 可选，读取一个对象；需要起始类型的 `$id` 权限 |
| `relation` | 可选，从 `id` 指定的对象沿授权关系读取；起点编号、两端类型和连接字段均须获授权。此时 `fields` 指目标类型字段 |
| `offset` / `limit` | 有界分页；响应包含下一页位置，不提供未开放的统计入口 |

成功返回 `items`、`page`、所用 `model` 和来源版本。每个对象只包含允许的字段；未授权编号时不返回 `id`。不会附带原文、来源行、完整证据或隐藏字段。未声明参数、重复参数、未授权关系、写入、统计与业务方法都被拒绝。授权固定本体与来源版本，后续更新不会偷偷增加已有调用方权限。

所有 `/api/` 是管理接口，含既有的对象/原文预览；消费凭据不能访问，去掉消费凭据也不会获得匿名管理权限。消费请求身份来自凭据摘要校验，不相信客户端自报名称或 `consumerId`。

## 本次真实运行结果

独立状态目录 `local-state/consumption-verify/`、端口 8792。通过现有 Workspace 上传和采用流程建立两条虚构投诉的最小验收夹具，随后由真实 KodaX SDK `0.7.96-beta.2` 与 `deepseek-v4-flash` 通过对话生成两个调用方；未预置调用方或模拟访问记录。运行夹具和客户端输出只留在被 Git 忽略的本地状态目录。

| 相同请求 | 客服助手：编号、状态 | 状态看板：仅状态 |
|---|---|---|
| 默认读取投诉 | 200，返回编号与状态 | 200，仅返回状态，没有编号 |
| 指定 `id=T1` | 200，返回一条投诉 | 403，编号未授权 |
| 请求联系电话 | 403 | 403 |
| 停用客服助手后读取 | 401 | 200，原范围保持有效 |
| 再次重启后读取 | 401 | 200 |

其他真实请求：未授权类型返回 403，原始证据入口返回 404，管理 bootstrap 返回 403，伪造 `consumerId` 参数返回 403。第四页显示真实允许/拒绝记录；浏览器实际完成客服助手的启用、凭据窗口关闭、停用与拒绝原因展开。API Key 关闭后 DOM 为空。

模型首次创建客服助手成功。状态看板的前两次尝试分别抄错本体标识、自造草稿标识，均被程序拒绝，没有保存错误授权。由此补充工具的新建/修改参数说明，以及精确区分本体引用和草稿引用的纠错提示；再次通过实际模型创建成功。失败记录保留，没有把模型文字上的“完成”算作保存成功。该体验证明了本轮可运行的消费链，不代表模型建模准确率或方法必要性的普遍结论。

升级并重启 8788、8790、8791、8792 四个已有/验收空间后，比对企业信息、来源、本体与调用方的内容摘要完全一致，当前页也未变化。8788 保留用户已有企业与一份资料；8790 保留 17 份来源与已采用本体，并解锁消费页。没有往用户企业空间注入实验调用方。

## 当前边界

这是单个本地企业空间的只读 API 实验。权限按类型、字段和明确关系控制，尚无按员工、片区或单条记录隔离；调用方身份代表密钥所属应用，不能推断具体操作者。页面显示最近的真实访问记录，不提供完整审计检索或告警。公网、多租户、完整 IAM、权限迁移、消费写入和远程 MCP 服务仍属后续工作。FEATURE_009 已补齐本地 MCP stdio 桥、许可结构发现与明确的数据版本发布，见[最新接入说明](AGENT_CONNECTION.md)。
