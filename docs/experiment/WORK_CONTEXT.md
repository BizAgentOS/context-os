## 本次交付

在线本体图可把类型、属性或关系明确引用到对话，实例列表可引用一个对象或其关系。前端提交空间、模型 ID/版本、类型与成员、查询范围、草稿 ID/修订号；服务解析真实定义并核对来源能力。图上的连线序号仅用于布局，不成为业务身份。

输入旁和消息结果提供引用入口；前端与内部 Agent 的 `context_read` 使用同一服务读取。固定的是引用、版本和范围；实例读取仍取当前源事实，回显读取时间及覆盖，不宣称历史快照。浏览动作不替换未发送草稿的讨论目标，明确引用操作保留文字。

新格式的未决请求完整保存在当前企业/页面的浏览器草稿中；响应丢失后重试原请求，后续输入和选择保留。旧格式没有完整请求，升级后只按原 ID 查询回执，不猜测执行。消息回执跨重启保留，绑定冲突拒绝。领域写前检查并发版本；本轮真实写入回执允许继续使用自己保存的新版本，消息仍显示原始目标。停止后迟到写入继续由宿主阻止。

实际接口与字段见[协作契约](../AGENT_UI_DESIGN.md#2-消息固定的-workcontext)，不在本记录复制完整规格。

## 自动验证

`npm run check`：类型检查与 90 项 Agent 测试通过。新增 5 项公开管理/领域边界测试，覆盖：

- 浏览器与 Agent 得到同一个关系引用，重复发送只启动一次，修改同 ID 的目标被拒绝。
- HTTP 投诉源与 MCP 回访源沿 TS002 → HF002 读取；源结果从“未改善”改为“已经改善”，同一引用重读得到当前值；分页、空间冲突、伪造字段、对象过滤冲突、版本变化被检查。
- 停止后迟到 `live_propose` 不落库；重启重试原消息不重放，原引用可恢复；来源停用后新请求被拒绝。
- 引用企业信息后合法更新版本，同一次写入重试返回同一结果，后续 `task_ask` 不被自己的新版本阻挡。
- 旧待发送请求可只查原回执；未收到的 ID 不启动运行，跨页 ID 被拒绝；升级期间的新旧客户端指纹都能只查回执。

测试先观察失败，再实现对应路径：缺少上下文 HTTP 入口、对象编号未解析到真实来源字段、自身版本变化阻挡后续工具、缺少旧回执读取分别出现过 RED，修复后 GREEN。未为低风险文字和样式单独新增测试。

`python3 -m unittest discover -s tests`：22 项既有数据/图谱回归通过。`npm run export:html`：真实 esbuild 单文件导出成功。变更 JS 通过语法检查，变更源码通过 Prettier 与 `git diff --check`。

## 浏览器验证

使用隔离企业与两个独立模拟源服务，通过实际管理 HTTP 和真实 Chrome 操作；产品资料未改动。验证用确定性 Agent driver 调用真实 `context_read`，不将固定回复冒充真实模型推理：

1. 图上选“回访记录”并引用，编辑输入后刷新；关系、版本和输入同时恢复。
2. “查看引用”读到起终点与字段映射；发送的 WorkContext 与服务端解析目标一致，用户与助手消息回显原引用。
3. 模拟服务已收到消息但响应断线；再换为“状态”属性、修改文字并刷新。重试仍发送原关系和原文字，驱动运行计数保持 1，新属性草稿不丢失。
4. 发送属性时绑定 `kind=property/member=状态`；取消引用保留输入；具体投诉与关联回访可查看，并以对象关系引用再次读取 HF002。
5. 桌面与 390×844 窄屏核查引用详情；键盘 Enter 选择图关系并引用；跨页往返保留草稿。引用按钮可点击，阅读淡出时不会留下透明点击区域。

旧格式未决请求的接口测试已通过；浏览器补测多次发生自动化会话断开，未取得该补充路径的完整 UI 验收结果，不计为通过。上列关系/属性、实例、新格式重试、窄屏和键盘路径已有实际通过记录。
