# DataEngine Agent：运行与验收

这是 FEATURE_003 的本地实验实现：一个主 Agent、一个企业空间，通过真实 KodaX 模型运行建立企业理解，接入资料，提出并预览本体，使用对象方法形成报告。主入口为 Agent 对话，业务产物保存到 SQLite，可独立查看与继续使用。

## 启动

需要 Node.js 22.18+ 和 npm；本次实际验证环境为 Node.js 25.9.0。

```sh
npm ci
npm start
```

打开 <http://127.0.0.1:8788>。旧浏览型实验室仍使用 `python3 scripts/lab_server.py` 和 8787 端口。

设置里选择 provider 和模型名，可填写 API Key 并测试连接。默认 `deepseek / deepseek-v4-flash`；也提供 OpenAI、Anthropic 的 SDK 配置入口，本次真实运行只验证 DeepSeek。优先读取宿主 `DEEPSEEK_API_KEY`、`OPENAI_API_KEY` 或 `ANTHROPIC_API_KEY`。界面输入的密钥仅留在服务进程内，重启后重新填写；配置只持久化服务商与模型名。

数据保存在被 Git 忽略的 `local-state/agent/`；其中 `memory.sqlite` 保存企业成果和任务，`runtime/` 保存 SDK 会话。可以通过 `DATAENGINE_PORT`、`DATAENGINE_STATE_DIR` 设置独立端口和实验空间。不要同时用两个服务进程打开同一个空间。

## 体验一条完整链路

1. 从首页开始对话，或选择“接入澄川热力示例”。Agent 会读取实际来源、保存企业理解，并针对缺口提问。示例只导入固定样本清单中的 17 份来源，不导入旧本体包、私有评测或未来事件。
2. 在企业理解中逐条纠正陈述。保存时检查正在编辑的版本；后续模型更新不能覆盖用户已编辑内容，冲突单独保留。
3. 让 Agent 为一个具体问题建模，例如：“建立投诉、回访、室温测量三类对象，以 ticket_id 关联回访和测温，提出候选并预览。”右侧可以检查概念、映射、关系、实例、检查结果和依据。
4. 查看实际候选后，点击“采用这一版定义”；也可以对当前等待项明确回复“采用这版”。宿主检查候选版本、来源版本与基础模型，成功才切换并续接任务。普通“好的”不会自动采用。
5. 让 Agent 调查一个问题并保存报告，例如：“复查 CS-014 的回访证据，说明哪些可以确认、哪些仍未知。”报告区可按同一快照浏览对象、展开关系并回查具体来源版本和行。
6. 上传新的 CSV/文档或纠正企业理解，再继续调查。新资料生成新版本；已有报告保留原依据。其他任务维持其首次调查绑定的本体和来源，需要迁移时明确选择“使用最新资料继续”。

文件先支持 UTF-8 CSV、Markdown、TXT，单份最多 5 MB。同名文件上传形成新版本。坏 CSV 保留原文与解析错误，修正后可重新上传；它不会进入可计算对象。PDF、Word、腾讯文档、知识库/API 连接器尚未接入。

## 实现方式

| 部分 | 当前实现 |
|---|---|
| 模型与执行循环 | 固定 `@kodax-ai/kodax@0.7.96-beta.2`；embedded/inline，SDK 管理 session/run/tool/event/abort |
| Agent 配置 | `config/agent/system.md`；企业理解、接入、辅助建模、调查报告、维护五种方法 |
| 对象工作区 | 本体决定类型、字段、身份、关系和注册方法；对象/集合句柄可以在单次运行中组合访问 |
| 组合执行 | `describe/query/get/related/evidence/aggregate/call`，每次最多 12 步；集合有服务端登记的引用和覆盖范围 |
| 语义方法 | `recovery_evidence` 判断关联回访的正向、负向、冲突、未知或缺失证据；不判断整栋楼恢复 |
| 保存 | SQLite 成果版本、任务、消息、事件及操作去重；SDK 会话和企业记忆分别保存 |
| 工作台 | 原生 HTML/CSS/JS；主对话、任务/资产导航、右侧原文/本体/对象/报告、模型设置与版本编辑 |

这里借鉴 NOOA 的对象环境与方法组合，不嵌入 NOOA Python Runtime，不提供任意 CodeAct、代码、SQL、命令或网络工具。类型对象在宿主工作区内保留，模型收到有界结果和可复用引用；这不是完整的 NOOA 零拷贝对象语义。

首次对象调查把模型及来源版本绑定到任务；普通续接从这组依据重建对象环境。当前任务上传资料、采用本体或明确刷新才解除绑定。报告固定自己的依据，查看旧报告不会触发模型运行。分页统计返回 `partial` 和 `coverage`，当前页不能冒充全量。

停止时先使当前任务修订失效，再请求 SDK 停止；迟到操作不能写入。请求补充/完成后也关闭该运行的领域操作入口。SDK 结束只说明本次运行结束，任务是否完成取决于实际保存和任务控制。连续工具写入重试返回原成果；不同逻辑写入不合并。HTTP 消息重试使用同一消息 ID。


确定性测试使用可控模型驱动，只测试边界；以下另有实际 SDK 和 DeepSeek 调用，未用静态回复冒充模型执行。

这次运行不是一次无错误调用：建模期间出现候选版本引用错误和对象引用格式错误，工具拒绝后模型重新读取并修正，错误事件保留。复查期间还出现类型、字段和跨快照引用错误，均被拒绝。一次模型运行只说“准备保存”便结束，没有保存报告；系统正确保留 paused，明确继续后才真实保存并完成。报告是模型生成的草稿；程序检查来源存在、版本一致、对象身份和方法执行，不能证明每段解释的语义正确，也没有自动实现所有指标口径。

维护使用的是独立空间里的显式测试纠错，不更改固定数据文件、不读取生成器未来事件。首次接入摘要没有充分说明新回访相对旧记录的变化，后续定向复查才交付版本差异；这是继续改善 Agent 接入工作方法的具体观察。

代码评审按 CodingSkills 双轴独立执行：Standards 累计 5 项均修复，最终剩余 0；Spec 的坏 CSV、聊天采用、固定调查依据、对象查看及分页能力问题均修复，最终剩余 0。

当前连通结果只支持“这条产品链可以执行并留下可检查产物”。没有完成独立业务评分、准确率/成本优势对照、完整本体演变回归或规模验证；不能据此宣称方法已被全面证明。
