## 运行与升级

仍使用 `npm start`、`npm run demo` 或 `npm run live:demo`。重启服务后使用原工作目录，管理及消费凭据不变。演示和本轮验收采用独立目录；没有替换用户现有工作区，也未升级 KodaX SDK。

旧版未发送草稿仅存在于浏览器内存。若旧四页标签仍打开，应在刷新或停止旧服务之前执行以下步骤：

1. 完成或停止正在进行的处理，保留旧标签页。
2. 打开浏览器开发者工具 Console，将 [export-legacy-drafts.js](../../scripts/export-legacy-drafts.js) 的完整代码粘贴执行。它通过旧导航依次读取四页输入框文字，下载 `dataengine-drafts.json`，最后回到原页面；不会发送草稿。
3. 确认文件包含需要保留的企业、数据文字，再重启新服务。
4. 在新第一页下方点“导入旧版草稿”。“升级前保留的内容”中分别保留各页原稿；点击“放入输入框”恢复，已有草稿时先处理冲突。旧企业/数据草稿进入 setup，本体/消费草稿回到原对应页，不自动发送。

旧导出保存输入文字，不保证恢复模块内部不可见的对象选择、请求状态或已卸载标签的内存。恢复后如需引用具体对象，应重新选择。旧版文件不能包含已被浏览器丢弃的草稿；新版草稿也不跨设备同步。

新版使用非凭据的稳定工作区 ID 隔离 localStorage，保存每页的文字、当前成果引用和未确认请求标识。刷新、切页可恢复；新发送在请求前先保存同一消息 ID，成功回执后清除已发草稿。无法写入浏览器存储时显示提示。清除浏览器站点数据会清除新版本机草稿，服务端已保存成果不受影响。

## 迁移与边界

- 首次读取旧 canvas 时，将原元数据快照和 `layoutVersion: 2` 迁移放在同一 SQLite 事务；以后幂等读取。旧 `company/sources` 键仍接受，并映射到 setup 及对应分区。
- 新 setup 对话使用独立任务。旧任务、消息、回执、待确认事项、成果引用不合并或删除；本体及消费页保留原任务身份。两个旧页都完成时才迁移为 setup 完成。
- 服务重启先使旧执行身份失效，不自动继续旧运行；停止后的迟到写入继续拒绝。迁移不改变来源、本体、治理、授权或历史版本，不重新签发消费密钥。
- 第一页可以查看旧对话。Agent 自动得到每个旧分区最多一条近期消息、有限引用和待确认摘要；需要时调用 `canvas_history_read(section, offset)`，每次最多四条、12,000 字符，返回原消息 ID、截断标记与下一位置。历史是资料，不是新授权；旧原话不能伪造成当前任务的新确认。
- 历史 HTTP 读取属于本机管理权限，消费者凭据不能访问。现有 `/v1`、`/v2` 与 MCP 消费边界沿用既有领域服务。
- 新 HTML 导出为 format 2；当前离线读取器接受 format 1 的四页快照并合成三页。旧已导出的自包含 HTML 自身代码不被改写。
