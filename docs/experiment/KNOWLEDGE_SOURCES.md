## 交付范围

第一页在原有样式中按内容区分知识文档与业务记录，HTTP/MCP 协议独立选择。获准知识能力可查片段目录、精确过滤、分页、读正文和续读。文件资料与业务记录继续共存。Agent 用同一来源服务生成知识证据，沿稳定基础概念保存候选；用户可查看读取时片段并采用具体版本。完整适配合同见[语义契约](../SEMANTIC_CONTRACTS.md#t014-01-知识来源与片段证据已接入合同)。

原文回执属于当前运行，伪造 readId 和未读引文不能保存；目录不返回正文，常规基础成果投影不返回片段快照。源停用后拒绝读取和依赖它的采用，历史原文仍能审查。已经解决且不再被当前定义引用的冲突依据仅作为历史，不永久锁住替换来源后的采用。

## 真实模型与浏览器

隔离工作空间，8897预览服务及独立虚构知识来源。使用实际 `@kodax-ai/kodax@0.7.96-beta.2` 与 DeepSeek `deepseek-v4-flash`，未注入测试driver，没有把测试答案或验收文档交给模型。

通过浏览器配置HTTP知识连接，成功查询两项片段目录，读取长片段并续读；同一能力的MCP连接另由实验脚本预先按明确字段注册。浏览器给出企业名称并要求使用已连接MCP资料，模型生成5个概念、用户陈述和两份知识片段依据，未知项保留。事件确认 source_catalog → knowledge_query → 两次 knowledge_read → skill_use → foundation_propose → task_ask，形成v1候选；界面键盘展开知识依据、定位并高亮实际原文，再采用为v2。过程中 profile_update 两次被拒绝（页面参数不支持、原话不精确），模型按错误修正后保存成功；不能将这次成功描述为无错误执行。

使用Playwright检查桌面与390px界面，长文本换行且无页面/弹窗横向溢出。知识资料原文定位沿基础证据接口，保留版本和原文高亮。通过浏览器暂缓实际查询请求，确认等待新过滤结果时旧“读取片段”按钮已移除；放行后只显示匹配的企业介绍。新查询开始清空旧结果，防止请求顺序与过滤条件错配。

## 限制

首轮为声明式只读片段适配，需要来源提供规定字段、总数和过滤，不是所有知识库厂商的现成连接器。查询为精确过滤，不提供全文搜索；长文需上游分段，不解析PDF/DOCX。当前传输在受限响应中取片段行后投影目录，并非上游零正文传输。

revision由来源提供；采用检查授权和连接版本，不联网重验每份远端资料是否最新。快照仅代表读到的片段，业务生效时间未知。文本解释仍需人核对，知识片段不能当业务实例映射。本票未新增对外知识消费API或完整企业数据融合。
