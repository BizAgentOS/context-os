# 飞书知识库文本附件读取修复

日期：2026-09-17，归属 FEATURE_019。用户把 Markdown/CSV 上传飞书知识库后，将具体文件的 wiki URL 填入“连接飞书”，被旧 docx 链接校验拒绝。

## 定位与实际验证

- 通过已保存账号对应的固定 profile 核验应用、用户身份和现有权限，未重新登录或扩大授权。
- 官方 `wiki +node-get` 证明用户指定节点底层为 file，名称“01-仓配门店与库存快照.md”，不是在线 docx。
- 官方 `drive +download` 成功下载；实际回执为绝对 saved_path 与 size_bytes=1054。CLI 要求 --output 为工作目录内相对路径，因此适配器使用自行创建的私密临时目录，不接受用户指定路径。
- 新的完整 FeishuConnector.readDocument 已读取 622 个字符，format=markdown、coverage=file、revision=null。原文未写入测试、文档或仓库。
- 重启本机服务后，浏览器用用户原 wiki 链接点击“读取文档”，显示同名标题与 622 字符正文，无控制台错误；结果保留在右侧弹窗。

## 边界与回归

支持具体 docx 链接及具体 wiki 节点。wiki docx 保留原版本校验；wiki 上传文件只允许 md/markdown/txt/csv，UTF-8，最多 250 KB / 60000 字符。下载过程中监测大小，读取时校验普通文件、路径、回执大小与编码，结束清理临时目录。错误节点、未授权、其他格式、目录有明确失败信息；不递归、不批量读取。

在现有公开连接器接口上，新增 wiki Markdown 回归先失败，再实现通过。共 10 项飞书测试覆盖原登录/取消/账号变化/docx，以及 wiki 文件、CSV、在线文档、错误节点、非支持格式、缺失权限、超限和在途断开。完整 `npm run check` 154 项通过，类型检查、前端语法与 `npm run export:html` 通过。
