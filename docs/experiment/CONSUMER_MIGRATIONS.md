# T016-03：变更影响与消费者迁移验收

日期：2026-09-15。基线：`a1b6b1c`，本地 `codex/mvp`，未发布。实现合同见[消费设计](../DATA_CONSUMPTION_DESIGN.md)。本轮完成指定视图迁移；T016-04 的三页整链仍待实施。

## 实际交付

- 第二、三页使用同一 mapping changeRef；按20份消费视图分页核对影响，从差异/样本进入迁移预览与确认，历史列表各40条。
- Agent 只读变更和迁移记录、保存指定预览；管理员确认后服务端原子切换指定 consumer_view，保留 ID、密钥和精确 grants，增加版本。
- 旧文档/BI背景默认阻止迁移；用户明确同意后移除全部旧背景，旧动态证据清除。其他消费者及 v1/v2 不自动迁移。
- 迁移后对象/类型/证据要求 viewVersion；发现接口仍可不带版本。HTTP、生成 OpenAPI、stdio MCP 和实际行为一致。

## 公共边界验证

`npm run check`：类型检查与119项Node测试通过；`python3 -m unittest discover -s tests`：22项通过；`npm run export:html`：单文件HTML导出成功。项目没有 lint 脚本。

新增迁移 HTTP 测试先暴露缺失端点，再实现通过。公共边界覆盖：

1. 两个独立密钥读取原映射，预览不改变数据；提交仅切换指定视图，原 grants 保持。
2. 在途查询跨迁移返回409；竞争预览提交、过期 viewRef 和同幂等键不同请求拒绝；相同提交重试返回历史回执。
3. 漏带或携带旧 viewVersion 拒绝，新版本读取新口径；独立 stdio MCP 同样执行。
4. 旧动态证据和旧文档/BI引用失效，移除背景需显式决定；停用当前视图继续403。
5. 新关联依赖未获准字段时迁移不兼容、提交失败，旧视图及关系读取保持有效，不补授字段。
6. 提交 HTTP 回应中 canvasState 与保存回执的视图版本一致；迁移后 OpenAPI 三条读取操作的版本参数必填。

独立评审另行重启实际 HTTP 服务验证：同密钥保留新版本、漏版本409、当前版本新值200，另一个消费者继续旧值。迟到记录选择的实际 UI 组件 DOM 反例验证：后选 B 先返回后，先选 A 的迟到响应被丢弃；分页/刷新后旧预览不再抢占确认。

## 真实 KodaX 与浏览器

使用已安装 `@kodax-ai/kodax@0.7.96-beta.2`、配置的 DeepSeek、现有唯一循环。基础本体与已采用映射变更由实验 fixture 建立，本次真实模型只负责发现、理解影响并生成迁移预览，不把实验答案或评测脚本交给模型。

独立 HTTP 投诉源、MCP 工单源，以及知识/BI来源构成试验数据。客服与审计各有独立许可视图；客服绑定两份历史背景。已采用规则将“实际反馈”从工单 outcome 改读 status。

通过浏览器发送明确要求：只为“客服迁移验收”生成预览，明确同意移除两份旧背景，“审计保留旧版”保持原版，不提交。实际 run `run_mu223mhp_25129e3e` 依次调用 `mapping_change_list`、`consumer_view_list`、`mapping_change_read`、`consumer_migration_impact`、`consumer_migration_preview`。产生预览 `ac3dfd33-e46e-4cad-98b7-0c466cfbe78a` v1，与变更 `826b2a03-a5bf-4e47-a03c-7988b09ff659` v3 对应。模型报告与实际预览一致，未提交，也未修改审计视图。

在浏览器第三页打开同一变更，查看两份消费者影响、规则差异和两条代表性样本；从记录打开 Agent 预览，核对目标、权限和两份移除依据，点击确认得到迁移回执。1440×1000 桌面、390×844 窄屏检查可读、可操作；视图原样式保留。

关闭浏览器后，独立 HTTP 与 stdio MCP 实测：客服视图 v3 读 TS002“实际反馈”为“未办结”，审计仍为“未改善”；客服漏版本和旧版本均409，旧动态/背景依据均403，目录背景数量0。密钥沿用且未进入日志、截图或文档。真实源值与自动测试使用的正常/冲突场景不同，结果分别记录，不混称同一次验收。

本地忽略的视觉证据位于 `output/playwright/migration-preview-desktop.png`、`migration-preview-mobile.png`、`migration-receipt-mobile.png`，外部结果为 `migration-external-result.json`。验收使用临时8897服务；未改动用户8899演示。

## 边界和评审

样本是原变更检查时的有界读取；迁移兼容校验不探测上游实时可达、不证明业务事实、没有跨源原子快照。局部纠正保留原模型且不对外发布；不提供批量迁移、自动背景重绑、自动补授字段或回滚协议。企业IAM、公网托管及全量性能评测未覆盖。
