# v0.3.0 数据接入与问答集成验收

日期：2026-10-21。开发分支：`codex/engine-workbench`。包与最近已发布版本仍为 v0.2.3；本文记录未发布实现，完成状态只在功能台账维护。

## 本次实现

- 文档批次只在 finalize 后进入后台池；真实读取回执验证引文，定义保留引用，完整原文快照留在证据库。新资料与已确认含义不同会形成待裁决，不能静默覆盖。
- 统一待处理中心提供全局计数、类别/来源/对象筛选、同类变更批量决定，以及裁决、问题缺口、同步数据问题的专用详情。
- 构建与问答模式固定到每条消息。问答只使用获准语义工具；工作版、发布版、接入方范围均由服务固定。回答中的依据、版本、覆盖和数据截至来自实际读取回执。
- 回答结果可在本体图和详情联动查看，退出联动不再查询来源。多跳返回实际中间对象；聚合组成员来自同轮有界读取，不能由界面另取一批数据冒充本轮结果。
- 缺口保留原问题与可重放查询，构建修复必须复验并比较前后；采用后仍等待用户主动复问。问答与构建工具均无自行确认缺口的能力。
- CSV/Excel 保留原始字节及解析参数，支持多工作表、GBK/GB18030、分隔符与表头调整。完整行读取和快照不受预览行数限制。
- PostgreSQL/MySQL 使用只读来源身份，表与字段按真实合同同步为快照。分页 API、短期 OAuth、嵌套内容和 MCP 目录通过同一来源边界读取。
- 调度、增量更新和质量候选与当前采用快照分开；异常数据保留为待确认快照，原数据继续服务。质量决定必须填写理由，旧结构确认入口不能绕过这一门禁。

## 公共边界与真实来源

表格验收覆盖 50,001 行、跨页完整读取、多工作表及空 sheet、合并单元格、中文编码、前导零、日期和缓存公式；畸形/超限文件不替换原来源。对应 `table-files*.test.ts` 与 `table-files-http.test.ts`。

数据库使用隔离 PostgreSQL 16 与 MySQL 8.4，执行 `node scripts/verification/database-chain.ts`：HTTP 连接向导合同、真实表列举、来源侧只读权限、DECIMAL、原生 WHERE 增量只读回一条变化、合并后保留未更新记录、历史快照、结构确认、容量覆盖和撤权均有断言。容器为本次测试专用；测试不会停止其他项目的数据库。

059/060 邻接定向 40 项通过，包含游标/页码/Link 短页、多于 2 MiB 且不超过 20 MiB 响应、401 刷新、重试耗尽、分页断点、增量合同不遵守、HTTP 字段增加/删除、大小写字段与空值、已排除字段、并发上限、调度重启和质量决定。

全量回归曾发现原始 CSV 仅因外键名含 `_id` 被误施加身份约束，导致星桥人员表被隔离。已删除这一猜测，只对明确声明/批准的身份字段执行身份熔断；星桥 8 来源整链重新通过。重复身份的原映射验证断言保留，异常原始快照须先经过显式质量决定。

## 真实模型

使用当前配置的 DeepSeek `deepseek-v4-flash`，通过真实 KodaX 循环运行，未注入问答答案。

1. 工作版查询：实际调用 `session_title`、`ontology_search`、`ontology_describe`、`objects_query`，返回隔离来源的两位人员姓名，报告真实快照时间、2/2 行完整覆盖和未读取字段。
2. 接入方范围：仅授予人员姓名；要求同时读取邮箱并修改实体名。模型实际查询获准姓名；未授权的依据读取被服务拒绝，伪缺口登记也被拒绝。最终答案不包含测试邮箱或构建历史私密标记，本体变更记录数和版本保持不变。

提供方本轮没有返回 token/费用统计，因此运行卡显示“未知”；没有按字数或未经核对的价格生成账单。这两次模型试问不代替星桥完整命名、关系修复和 FEATURE_068 的最终整链验收。
