# MCP 便捷接入验收

日期：2026-09-17。范围：FEATURE_021；基线 `ddce13c`，KodaX SDK 仍为 0.7.96-beta.2。本轮只优化 MCP / 飞书接入，HTTP API 保持 FEATURE_020 的 Swagger/OpenAPI 导入。

## 使用路径

1. 企业与数据 → MCP 接入 → 添加 / 管理，或从顶部“能力”进入同一连接界面。
2. 飞书可直接点企业页的服务行。有已保存账号时直接提供文档链接读取；新账号沿官方 CLI 页面授权，向导显示创建应用、登录授权和核验步骤。官方网页显示“创建成功”后回到 Context OS 继续。
3. 自定义 MCP 粘贴 URL → 连接并发现能力。名称自动生成，默认自动检测 HTTP/SSE；需要时展开 Bearer / API Key 验证，其他请求头与旧版 SSE 留在高级设置。
4. 搜索并勾选工具、资源或提示词 → 保存可用范围。首次连接不默认授权、不执行业务工具。目录超过一屏时内部滚动，关闭与保存按钮保留在可见区域。
5. 重新打开连接可调整范围、重新发现或断开。重新发现立即清空旧授权；发现失败也不恢复旧授权。断开只移除 Context OS 的本地连接。

企业页显示已保存的 MCP 服务及已授权能力数量，按服务地址与旧业务来源去重；飞书是官方 CLI 账号，不计入 MCP 数量。连接成功不代表文档已读取、数据已导入或本体映射已采用。未适配的其他国内服务仍明确为“待支持”。

## 验证结果

- `npm run check`：类型检查及 142 项 Node 测试通过。
- `npm run export:html`：离线 HTML 构建通过；改动的前端模块通过 Node 语法检查。
- 新增 5 项公共边界回归覆盖 URL 自动发现、无默认授权、显式许可和重启保留、管理员目录鉴权、凭据不回显、重复/并发连接、旧版本授权拒绝、不可达与 401 后重连。测试连接真实本地 MCP 服务，使用临时目录和合成凭据。
- 独立浏览器工作区在真实本地 MCP 上发现 48 项能力，搜索第 45 个工具 `read_44` 后勾选保存；企业页计数变为 1、显示授权 1 项，重开仍保持。重新发现后授权清空；断开后计数回到 0。
- 浏览器桌面与 390×844 窄屏检查：内容没有横向溢出，长目录内部滚动，标题、关闭与保存按钮可见；X、Escape、背景关闭均通过。Swagger 导入仍显示文档导入、接口与认证、测试保存三个步骤。
- 本机已有飞书账号的复用入口已确认，未重新授权、未读取用户的私有文档。登录、取消及读取的宿主状态机沿原有自动回归；真实飞书文档读取仍属于 FEATURE_019 的待验收范围。

## Standards

独立规范轴检查了后台并发、凭据边界、关闭等待、账号取消、连接生命周期与新 UI；无可行动发现。收尾补充检查固定弹窗操作、旧来源入口的更新回调和状态读取失败提示。

## Spec

独立需求轴发现 1 项 P2：SDK `getCatalog(forceRefresh)` 在网络失败时可回退旧缓存，同一 URL 重连会被误报成功。已先用不可达与 401 测试复现，再改为 `startServer` 实时发现成功后读取目录；刷新也走同一真实发现路径。两项回归及独立复核通过，无未解决发现。

## 当前边界

自定义 MCP 支持远端 HTTPS、本机 HTTP、无认证或请求头凭据；尚未提供通用 OAuth 跳转、stdio 配置、任意厂商自动适配或聊天中的连接编排。能力描述来自上游，只读标记是服务声明，实际可用范围由宿主保存并检查。高级业务字段映射仍在原来源配置入口；本轮没有改变来源、融合或消费合同。
