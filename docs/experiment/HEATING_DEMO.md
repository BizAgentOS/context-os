# 澄川热力四页演示

用户本次希望先看到填好 mock 数据的产品效果。本演示复用当前四个黑白记忆画布，以虚构澄川热力解释“企业是谁 → 有哪些资料 → 如何形成业务对象与依据 → 谁能使用”。

## 启动

```sh
npm ci
npm run demo
```

打开终端输出的管理链接。默认 `http://127.0.0.1:8794/`；首次管理链接建立本机浏览器会话，随后移除凭据片段。无需配置模型 API Key，不调用外部模型。`DATAENGINE_DEMO_PORT` 可选择端口，`DATAENGINE_DEMO_DIR` 可选择独立状态目录。

演示保存到 `local-state/heating-demo`，不会覆盖 `npm start` 的空间；重启保留用户在演示里的编辑。首次仅向空空间写入样本，指定已有数据的目录时不覆盖它。需要一份全新演示，可设置新的 `DATAENGINE_DEMO_DIR`，不用删除现有空间。

## 查看路径

1. **企业：**澄川热力购买外部热源，为北城区 2 座换热站、4 个小区、12 栋楼的 1,200 户提供供热服务，总面积 12 万平方米。点企业事实可以修改；底部示例问题可以查看企业介绍。
2. **数据：**查看设施台账、投诉、维修工单、回访及业务文档。打开资料可看原始表格、用途、负责人和限制对外使用的字段。
3. **本体：**“定义”查看类型、映射与关系；“对象”打开具体投诉，继续查看关联工单、回访和原始行；“验证”检查改善、未改善与缺少依据的差异。点击试问“哪些投诉还缺恢复依据？”会实际执行本地对象方法并保存一份新的验证。
4. **数据消费：**查看模拟应用的授权范围和本地生成的允许/拒绝记录。调用方可停用；居民联系方式受来源敏感分类限制。

## 真实性边界

- 公司、业务记录和调用方均为虚构演示内容，非真实客户接入；样本是为产品展示缩小整理的数据，不是原 738 条记录的完整导入，也不是方法准确率实验。
- 本体和初始验证由种子脚本预先建立，不能将此过程宣称为 Agent 自动完成建模或用户正式批准。
- 页面右上角标记“演示数据”，输入框标记“模拟问答”。固定示例问题由本地脚本处理；任意新问题不会被假装回答，新上传资料也不会被宣称已自动建模。
- 对象/关系读取、来源证据、验证方法、编辑持久化、字段权限与访问日志复用实际服务。消费记录由本地模拟客户端调用权限处理器产生，不代表外部应用已接通。
- 原产品 `npm start` 仍使用 KodaX SDK 和用户配置的模型；演示入口与实际模型入口分别启动。
