## 已构建的企业

从 [公司经营与分工说明](../../data/samples/chengchuan-heating/sources/company/company-brief.md) 阅读企业本身：外购热源、单片区、两座换热站、四个小区、三个业务部门。公司及全部资料均为虚构，人口、面积和时间范围属于实验设定。

主流程为接诉、派单、调查、处理、测温/回访、周复盘。第一批资料在 [样本目录](../../data/samples/chengchuan-heating/README.md)，包含结构化记录与业务文档。

固定小样、来源说明和校验入口已交付；T001-02 的生成与回放入口见 [使用说明](GENERATOR.md)。原始 Agent 基线的工具、冻结题与运行入口见 [基线说明](BASELINE.md)；已生成 [对象技术试样](ONTOLOGY_REVIEW.md)，其早期建模过程见 [本体建模流程设计](ONTOLOGY_MODELING.md)。这些记录不证明方法优于对照组；当前工作顺序以[三页实施计划](../THREE_PAGE_PLAN.md)为准。

## 第一批公开开发问题

以下均为开发用题面，供人核查和后续调试；不是留出评测题。默认查询时点为 2026-01-19T00:00:00+08:00。

1. 1 月 14 日收到的投诉分别涉及哪些换热站？对每项关联给出地址与设施依据。
2. 育新站当日有哪些监测变化？现场记录支持哪些解释，哪些投诉仍不能确定根因？
3. 对 1 月 14 日收到的投诉，分别计算客服办结率与回访确认改善率，给出分子分母、未接通和尚未回访数量。
4. 哪些证据表明维修后某些住户有所改善？是否足以宣告全部小区恢复？
5. 清河站两周小时监测覆盖是否完整？缺失对热量汇总的解释有什么影响？

人工核查材料存放在本地忽略目录 `data/private/chengchuan-heating/`，不提交标准答案。T001-03 已将上述五题登记为公开开发集，另冻结五道留出题和评分依据；公开五题不充当独立评测。

## 后续变化设计

分别准备普通记录新增、监测标签改名以及正式业务制度变化。前两类验证事实与 Mapping 维护；第三类应提供充分的业务依据，让 Agent 判断是否需要新的概念、关系或计算定义，而非强制匹配预填本体。

具体未来情节和完整历史留在作者侧。T001-02 已实现按时点导出及文件变化包；T001-03 通过限定模型工具只访问当前快照验证输入边界，详见基线说明。对照组同时得到新事实、规则及计算机会，允许各自维护并记录投入。

## 数据核查与范围

运行 `python3 scripts/validate_heating_sample.py`，检查固定来源包的清单、来源 ID、行数、哈希、引用、时间、面积和监测数量关系。复核以实际来源为准，不能仅检查目录存在。

原始资料中保留业务所需的台账关系、交接依据与源系统内关联，但不提供统一对象表、标准本体或故障事件答案。后续各组可见同样的来源目录与业务规则，避免以缺少导航的原始组作为弱对照。

本批不实现物理热网仿真、设备调控、收费系统或完整企业应用。导出按可见时间过滤，基线 Agent 的工具只访问当前快照内存副本；本地评测进程仍是受信任进程。
