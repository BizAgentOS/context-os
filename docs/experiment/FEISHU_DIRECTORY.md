# 飞书目录读取验收

2026-09-17，FEATURE_019 / T019-06。

## 问题与改动

原链接指向目录下第一份文件，单文件读取只保存该文件，界面没有列出兄弟文件的入口，导致用户以为目录内容读取不完整。

现支持“查看所在目录”和输入 wiki 链接“查看目录中的文件”。使用固定官方 lark-cli 1.0.92 的 `wiki +node-get` 和 `wiki +node-list`，校验账号、用户身份、空间、父节点和分页回执；不请求新权限。目录每页最多 20 项，仅发现直接子文件。UI 勾选后逐份调用现有读取保存接口，显示逐项成功与失败；关闭后不再派发下一项。内部 Agent 使用同一 `feishu.directory.list` SDK 方法。

同一对象的 wiki/docx 入口不按 URL 字符串视为不同来源；保存与目录状态共用服务端远端身份（域名、对象种类和文档 ID）。未读目录不标为已读正文，分页不标为全量，不递归子目录，也不跟随 CSV/Markdown 中的链接。

## 实际验证

- 用户指定“数据”目录实际返回 3 项：`01-仓配门店与库存快照.md`、`02-补货与收货登记.md`、`page-links.csv`。
- 经真实浏览器勾选读取，3 份分别保存 622、404、57 字符。第一份内容未变，复用快照 v1；另两份新增快照 v1。刷新后仍显示“已读取资料 · 3 份”，每份均可打开正文。未保存用户正文或远端标识到本记录。
- `npm run check` 通过：类型检查及 159 项 Node 测试。新增验证涵盖目录列表与显式分页、权限不足、上级边界、外部域名/外来子节点拒绝、不支持类型、坏分页回执、断开在途结果、跨入口已保存匹配与跨域隔离。
- `npm run export:html` 通过；本仓库没有独立 lint/build 脚本。Standards / Spec 评审发现的 URL 匹配问题已修复并回归，剩余 0 项。
- 本轮只补齐读取与可见性；主环境仍未配置模型，未生成、采用或发布本体。

接口依据：[飞书获取知识空间子节点列表](https://open.feishu.cn/document/server-docs/docs/wiki-v2/space-node/list)，以本地固定 CLI 的实际帮助和用户目录回执核对实现。
