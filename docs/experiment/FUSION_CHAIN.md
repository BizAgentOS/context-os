## 可复现入口

```sh
npm run verify:chain -- --real
# 若需要继续浏览器检查，保留独立实验服务：
npm run verify:chain -- --real --keep-open
```

使用当前已配置模型与已安装 KodaX（本次 0.7.96-beta.2 / DeepSeek）。`--real` 会产生模型费用，未纳入 `npm run check`。脚本创建临时企业和独立 HTTP/MCP 来源，输出无密钥的阶段信息与 `acceptance.json` 路径。保留模式的浏览器认证、消费密钥文件仅在本地私有目录中；不要分享或提交。正常退出关闭服务，删除临时浏览器认证和消费密钥文件；实验工作区和报告仍保留。关闭失败会记录并返回失败。

脚本不覆盖用户已有企业或 8899 演示。来源沿用公共协议夹具，是实际独立 HTTP/MCP 服务，内容并非真实企业接入。网页公开研究未在这条链中重新执行，保留 [T013-03 真实研究验收](FOUNDATION_WEB.md) 与本轮测试结果。

## 实际整链与边界

1. 上传只含企业事实的 Markdown；真实 Agent 读取片段并使用基础本体 Skill，生成居民、投诉、工单、供热站四个概念和关系。管理员经管理 HTTP 采用；未映射定义仍保留。
2. 真实 Agent 读取 HTTP 投诉与 MCP 工单样本，建立同实体附来源融合及工单对象。保留明确声明的历史错误连接作为治理起点。TS002 的状态冲突、反馈未改善与上门次数 0 都经过接口断言，0 不作缺失。
3. 真实 Agent 共同读取该对象、固定知识片段 r1（不超过 100 字）和清河站 2026 年 1 月指标（80%，最多一行）。断言对象身份、请求字段、读取成功、指标站点/期间及 context_only；背景指标不能代表个体恢复。
4. 创建两个独立密钥的许可视图：服务 Agent 有两份背景依据，审计 Agent 无背景依据。未许可字段和跨视图证据引用返回 403。
5. 真实 Agent 读取连接问题，保存并检查 `投诉.业务编号 → 工单.投诉编号` 修订，管理员采用。新映射关联 WO02，旧消费视图仍为 0 条。
6. 真实 Agent 只为明确指定的服务 Agent 生成迁移预览；按已明确决定移除旧模型的两份背景，管理员提交。原密钥继续有效；服务 Agent 必须带 viewVersion=3，漏带返回 409，旧证据返回 403；审计 Agent 保持旧模型。
7. 源反馈变化为已改善、上门次数 2 后，独立 stdio MCP 和另一消费者 HTTP 都读到新事实。源失败时外部属性为 null/uncertain，证据 match 为 unavailable，不能以旧值假装成功。重启后密钥及视图隔离仍有效。固定映射版本不意味着源数据历史快照。

## 失败与修复记录

前四次未作为最终成功证据：RQGcWg 发现脚本读取不存在的 canvas.task；JkKOnj 发现对外失败状态应断言 uncertain；Pf2Rzk 的初始宽松脚本放过了对象取证失败（模型混淆对象 ID 和业务编号、遗漏融合字段），复核后原报告改记失败；HlaYFr 发现脚本不应把 UI 动态绑定投影当作基础定义变化。均保留原因，未抹去失败记录。

强化脚本的对象、字段、来源、时间/维度和结束回执断言；产品工具和运行身份补充对象 ID、主来源过滤能力及完整证据要求。最终严格复跑通过。评测断言、未来来源变化和预期答案不进入模型资料。

浏览器还发现并修复：

- 已采用基础本体引用的资料仍提示未纳入。现在只按已采用定义真正引用的文档版本判断；资料更新仍提示核对，未采用候选不会清除提醒。公共测试先失败、修复后通过。
- 同名当前/历史采用映射难辨认。卡片显示角色、版本、ID，并将旧解释标记为建模时的依据。
- 离线导出将打包脚本作为 replacement string，`$&` 被替换为 HTML，造成 SyntaxError。改为回调插入；新增实际导出产物的 JavaScript 解析回归，先红后绿。仅构建命令成功不足以证明文件可用。
