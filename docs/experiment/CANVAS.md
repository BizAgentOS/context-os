# 企业记忆画布：运行与验收

2026-09-08，T003-04 / T005-04。当前定位和界面以[画布设计](../CANVAS_DESIGN.md)为准。

## 启动

Node.js 22.18+，在仓库运行：

```sh
npm ci
npm start
```

打开 <http://127.0.0.1:8788>。右上角设置模型，或沿用宿主环境变量。API Key 只留在服务进程，数据库仅保存服务商和模型名。当前真实验证使用 DeepSeek 和已固定的 KodaX SDK。

默认企业记忆保存在 `local-state/agent/`。`DATAENGINE_PORT` 和 `DATAENGINE_STATE_DIR` 可指定独立实验空间；同一个空间只运行一个服务。旧的 8787 浏览实验室不是主产品入口。

## 从空白开始

1. 在输入框说出企业名称及实际业务。也可先只提供名称，由助手补问缺少的业务信息。保存后出现名牌，创建完成后自动进入数据页。
2. 上传一份 UTF-8 CSV、Markdown（.md）或 TXT，每份最多 5,000,000 字节。可点击来源查看实际表格或原文。只有介绍文档、空表或坏 CSV 时仍需补充有记录的 CSV。
3. 助手实际检查可用记录后进入本体页。说明先建立哪些业务对象；页面出现来自资料的定义候选及关系。点击概念查看映射、实例和来源，再决定是否采用这组定义。
4. 顶部返回企业或数据页面，继续说明要修改什么或补充资料。画布显示新保存内容；浏览历史证据时维持其原版本。

每页只有一个输入框和上下文。画面只保留最多三条近期对话，越远越淡。原始聊天最多保留 12 条、合计 12000 字，每次实际模型运行使用这份有界上下文，不复用无限增长的 SDK 聊天。单条输入最多 6000 字。保存的企业事实、原话引用、来源、本体和对象独立于聊天寿命。

模型可提出建议，但企业画布将其标成“待确认”。用户有依据的原话可以纠正自己的陈述；来源或模型建议不会覆盖已确认内容。候选只有程序检查、真实预览和具体版本的用户决定齐备后才能采用。

## 当前范围

仅支持上述文件上传，尚未接入腾讯文档、知识库/API、PDF 或 Word。图和对象由实际保存的结构化成果渲染，不执行模型生成的任意页面代码。报告与完整演变能力留在历史实现中，不出现在当前创建流程。此次证明这条产品链路可运行，尚未验证本体方法的普遍优势或企业规模效果。

## 前景浮层纠偏

2026-09-08，用户通过浏览器标注明确：聊天与输入框属于前置图层，与内容是前后叠放。初版上面的“内容和输入区各自占用空间”已被本次实现替代。

- 背景画布从导航下延伸到屏幕底部，聊天与输入绝对定位于前景；对话透明，保留由近到远的淡出。
- 只有输入及相关操作接收点击；对话空白区域的点击和滚轮传给背景。没有新增底部白色面板或分隔线。
- 非空画布末尾有随浮层高度变化的可滚动留白，确保最后内容也能滚到浮层上方；空态不增加留白，不制造多余滚动。
- 实际浏览器 713×837：修改前背景高 483px、底部交互独占 276px；修改后背景高 759px 并延伸到 y=837，浮层仍位于原来的底部位置。输入增高到 110px 时背景底部不变，留白随浮层调整到 338px。
- 点击命中检查确认透明对话位置落到背景，输入位置仍命中输入表单；在对话区滚动画布到底后，最后内容底部 y≈523，小于对话顶部 y=561。空态 scrollHeight 与可见高度同为 759，无额外滚动。
- 本次只改布局与高度同步，未调用模型或改写企业成果；临时输入未发送并已清空。`node --check web/agent/app.js`、`git diff --check` 通过，独立 Standards / Spec 复核各 0 项发现。沿用既有媒体规则，并取消会把短屏输入框推到屏外的强制最小页面高度；本次不宣称另跑了手机或短屏实机验收。
