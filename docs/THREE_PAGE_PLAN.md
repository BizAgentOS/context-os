## 1. 实施目标与需求归属

跑通企业基础本体 → 分类来源接入 → 概念/身份/关系对齐 → 融合对象与证据 → 可视化检查和修订 → 独立 Agent 获准消费的完整链路。保留原黑白灰画布、前景输入和近期对话样式。

三页是同一领域 Agent 的工作入口。实施顺序按可验收成果安排，不为每一页另建 Agent、工具规则或状态真相。Agent 可在一个目标中调用多种方法，确定性业务操作由共同领域服务承担。

## 3. 四页迁移与兼容


| 旧页面键 | 新目标 | 保留内容 |
|---|---|---|
| `company` | `setup` 的企业区 | 企业资料、消息依据、候选及实际可读取的未发送草稿 |
| `sources` | `setup` 的来源区 | 来源、权限、资料、候选及实际可读取的未发送草稿 |
| `ontology` | 第二页本体工作区 | 定义/实例引用、版本、检查与草稿 |
| `consumption` | 第三页消费与治理 | 消费者、密钥、授权、调用记录和现有接口 |

采用可重复执行的迁移，停止旧运行后迁移页面进度和任务映射，保留原成果 ID/版本及历史消息引用。两个旧页的聊天不全量拼接；新第一页使用摘要、待处理事项、成果引用和有限近期消息，原历史按需读。旧版草稿仅保存在浏览器内存；仍打开的会话需先导出或持久化实际可读取的两份草稿，再迁移并分别恢复，不覆盖、不自动发送。已卸载的旧内存无法恢复。新版为未发送草稿建立恢复机制。

同步迁移页面提示词、工具可见范围、运行门禁和完成条件。把两页能力合并到同一界面不自动扩大来源授权。首次到达与实际完成分别记录，不因名牌保存立即跳到第二页。

演示驱动、种子状态、在线体验、离线分享与 HTML 导出同步适配三页；旧导出快照可读。已有页面入口映射到相应分区，业务导航按领域引用实现。迁移不重新签发消费密钥，也不修改源系统数据。

## 4. 可复用能力与实现缺口

当前代码基线、SDK 版本和已接入范围见[能力接入记录](KODAX_CAPABILITY_LEDGER.md)，模块接点见 [HLD](DATA_ENGINE_DESIGN.md#3-当前部署与代码接点)。本轮不升级 SDK，也不采用 Space 的 daemon 或桌面结构。

基础定义已支持文档/网页片段依据；主要缺口是：远程文档/BI 内容契约；同实体多源属性与细粒度证据；真实修订差异；新消费版本、契约说明与迁移。已有跨源关系、文件快照、MCP 发现和四页验收不能替代这些能力。

## 5. 集成验收


沿用既有公共验证边界：管理 HTTP/领域工具 → 实际源读取与保存 → 浏览器查看结果 → 独立 HTTP/MCP 消费。复用现有测试服务、隔离临时目录和真实客户端；不新增只检查内部私有函数的测试边界。

选用虚构热力企业及独立来源：投诉 API、回访 MCP、文档来源、BI 指标来源。增加与投诉同业务身份的附源记录，既验证同实体属性融合，也验证投诉→回访的跨类型关系。不同来源需要有可控制的缺失、重复键、冲突、版本变化和读取失败。

必验行为：

1. 对话、已有格式资料、确认企业后的公开研究均能形成有依据的基础候选；无来源时允许未映射概念，不生成假实例。
2. 实际文档/指标/业务记录各读一次并保留正确语义；同一投诉从两个来源取得属性，逐字段可查依据。
3. 图、表、详情与 Agent 指向同一对象/关系；切换选择、过滤或页面不会让旧操作改错目标。
4. 一次局部纠正和一次全局映射修订分别检查、采用并获得回执；并发、重复键、撤销和停止后的迟到写入行为明确。
5. 两个独立消费者读取不同获准范围；证据和契约说明不能绕过权限。源值变化与语义迁移分别验证，旧版本失效如实说明。
6. 浏览器关闭仍可消费；页面、授权和成果重启后可恢复；旧四页持久数据、迁移前成功保存的草稿及离线快照可读，新版草稿可恢复。

每张实现票先验证其新增行为，再运行相关回归；受影响的类型检查与必要完整检查按实际改动执行。最终集成验证包含真实 KodaX、桌面/窄屏/键盘和独立客户端。若模型或企业来源不可用，明确记录未覆盖项，不把模拟测试当真实验收。

评估同时记录跨源任务正确性、证据覆盖、人工处理时间、建议采纳与误改/漏检，以及模型上下文与工具成本。不能只凭图能显示或工具调用成功判定融合有效。

## 6. 范围与后续能力


本轮建设本地单企业的完整三页闭环。具体厂商连接器根据真实接入需求补充；通用自动 OpenAPI/SQL 适配、全量实体模糊消歧、完整 OWL 推理、任意 CodeAct、全企业后台巡检、源系统写回、多租户/SSO/记录级权限、公网部署和计费不作为这批任务的完成条件。

按需读取不等于零缓存承诺，证据保留也不等于复制全企业。存储和历史策略应明确最小用途、保留范围和权限；来源未提供历史且未保留证据时，不能保证旧值回放。

## 7. 维护与开工入口

先读当前票及它引用的主契约，再核对真实源码和 KodaX 接入记录。后续实现根据实际影响更新产品、运行、Skill、领域或交互的对应文档，不把所有设计重复写回本计划。

开工和完成依[开发流程](DEVELOPMENT.md)记录。历史 FEATURE_002/004/005 尚未覆盖的验收继续保留；新票覆盖旧行为时复用同一实现与证据，不重复建设或提前勾选。
