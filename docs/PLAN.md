## 六个部分

| 顺序 | Feature | 对应内容 |
|---|---|---|
| 1 | [001](features/v0.1.0.md#feature-001) | 企业设定 → 样本与生成器 → 隔离评测与原始基线 |

前端可以在 002 可用后开始，维护页在 004 接入；评测从 001 和 002 积累记录，006 汇总，不需要等待完整前端才能运行脚本。

## 第一项的具体入口

**FEATURE_001 / T001-01：企业设定与最小业务样本。**

先写清企业业务、三类来源、第一批问题、口径分歧与计划注入的变化，配一组能相互核对的样本，再据此开发生成器。

## 开发方式

按 [CodingSkills 开发流程](DEVELOPMENT.md)逐项推进：登记 Feature → 补齐设计 → 细化当前任务 → 实现与验证 → 更新状态及本地提交 → 维护变更日志。用户可以直接指定 Feature ID 或票号。
