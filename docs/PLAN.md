## 每部分的交付与检查

| 顺序 | 做什么 | 交付物 | 最简单的检查 |
|---|---|---|---|
| 1 | 企业设定、三类来源、样本、冲突、未来变化和评测问题 | 企业说明、生成脚本、初始数据、变化包与隔离的答案 | 人能沿原始记录核对一个跨源问题；运行原始基线 |
| 2 | 发现本体与 Mapping 候选，确认并建立对象、函数和只读 MCP | 本体 v1、对象数据、查询接口 | 外部 Agent 回答初始问题并给出证据；保存静态及专用表对照 |
| 3 | 核对 Runtime，接入稳定对象引用、按需读取、工具执行和任务记录 | 可运行内部 Agent | 真实调查一个映射或语义问题，并给出有依据的建议 |
| 4 | 候选变更、基础验证、人工确认、新旧版本保存及重算 | 一次可重放的本体演变记录 | 变更后目标问题改善，原有问题回归；能恢复旧版本结果 |
| 5 | 用简单页面或标签连接来源、本体、对象、Agent 与结果 | 本地工作台 | 能看清“原始数据怎么变成本体、Agent 改了什么、答案怎么变” |
| 6 | 跑四种主要对照，扩展同一案例数据，记录失败与成本 | 结果表和实验结论 | 判断本体和维护 Agent 的收益，而非只展示成功演示 |

## 执行约定

- 每次推进当前的一小项；完成后记录产物和验证结果，再更新勾选状态。
- 用简单脚本、文件和最少组件启动，技术选择在实际开发时确定。
- 原始基线从第 1 部分开始；外部 Agent 与静态比较在第 2 部分接入，不等到最后。
- 初始建模先接最小模型能力；第 3 部分再建设完整内部维护 Agent。
- 查看页面随数据与本体逐步接入；第 5 部分负责连成完整工作台。
- 模拟回复不算 Runtime 接通；预先写好的答案不算本体推导结果。
- 不按旧方案默认追加生产平台功能；本轮范围以 [MVP 目标](MVP.md) 为准。

## 下一项：企业设定

先完成一份短文档，回答：

1. 这家虚构企业做什么生意，总部与门店分别关心什么？
2. 有哪些业务系统，哪些记录需要跨系统关联？
3. 第一批要回答的业务问题是什么，哪些口径需要明确？
4. 准备注入什么变化，检验本体维护能力？

然后定义来源 Schema 和少量样本，再编写生成器；避免一开始就批量生成缺少业务联系的数据。
