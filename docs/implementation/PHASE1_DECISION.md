# Context OS 第一阶段实施决定

状态：第一阶段实施基线。原始范围已完成机制与合成样本验证；2026-11-02 补齐决定见 §11，真实企业效果验收仍待开展。依据：《现状评估与持续推进流程》及本次沟通。后续改变范围需记录理由，不沿用旧项目限制。

## 1. 本阶段交付什么

交付可运行、可检查的新知识核心最小闭环：接入一份结构化样本与一类文档，生成候选本体、发布类型定义，抽取并融合带证据和时间的声明，查询对象及历史，通过反馈纠正后再次同步，结果仍符合规则。

本阶段覆盖总体路线 P0、P1 及 P2/P3 的最小纵向实现，不尝试一次做完所有行业和完整平台功能。采用单企业实例，不做多租户；直接使用 PostgreSQL，不迁移旧 SQLite 状态，不要求旧接口兼容。

默认采用“企业—合同—负责人”作为工程验证样本，不把它当作已经选定的商业行业。数据不足时建立公开可检查的合成样本；合成样本只验证机制，真实抽取质量另用获授权的真实或脱敏资料评估。

## 2. 已决定的技术与架构

| 事项 | 本阶段决定 |
|---|---|
| 应用 | 继续使用 TypeScript / Node，单应用模块化，不拆微服务 |
| 数据库 | PostgreSQL 是新知识核心的权威存储；使用异步事务访问，不受旧同步接口限制 |
| 存储方式 | 固定关系表承载身份、引用、时间和状态，JSONB 承载灵活属性定义、值及参数 |
| 原始资料 | 开发环境文件目录加数据库元数据，接口允许将来替换为对象存储 |
| OO 本体 | 元数据定义类型，不为每个行业类型编写代码类；ObjectType、PropertyDefinition、LinkType、ActionType 分层 |
| 知识 | 独立对象 ID + 不可覆盖的来源声明/修订历史 + 可重建对象视图 |
| 查询 | 对象、关系、证据、双时间查询；第一版不依赖图数据库、向量库或自由 SQL 生成 |
| 后台任务 | PostgreSQL 持久化任务，一个 worker 起步；状态、尝试次数、幂等键可查，失败可重跑 |
| 模型 | 独立模型适配接口，复用可用的现有提供方接入；fake 用于确定性测试，真实模型验证单独记录 |
| 修改入口 | UI、Agent、外部调用统一进入领域服务；事实修改必须经过 Action 的校验、事务与审计 |

原有 SQLite 可以暂时服务仍需复用的界面会话；这不构成新知识核心依赖，也不要求长期维持两套持久化。只有在选择复用该界面时才处理会话存储，不为它延迟本阶段闭环。

## 3. OO 元模型及领域服务

类型定义采用版本化配置：

- ObjectType：稳定 type_id、名称、描述、可用属性。
- PropertyDefinition：稳定 property_id、数据类型、必填、枚举等约束；金额采用 decimal 字符串或精确十进制表示，避免浮点金额。
- LinkType：稳定 link_type_id、端点类型、方向、基数和有效时间支持。
- ActionType：参数 schema、适用目标、校验与授权规则、受信任实现标识；不执行模型提供的任意代码。

首批内置 Action 为 CorrectProperty、RejectAssertion、CorrectValidity、PublishOntologyVersion。身份合并/拆分的数据结构保留修订能力，完整交互及通用拆分引擎放到后续阶段；本阶段自动匹配仅在明确标识成立时执行，不做难以撤销的模糊合并。

领域服务：OntologyRegistry、ObjectRegistry、AssertionStore、EvidenceStore、ActionService、ProjectionService；接入、抽取和任务模块调用这些服务，不直接散写数据库。

## 4. 最小数据设计

| 数据组 | 内容与关键约束 |
|---|---|
| ontology_versions / ontology_members | draft/published 状态；发布版本不可原地修改；稳定成员 ID 与定义版本分开 |
| sources / source_record_versions | 连接或文件身份、记录外部键、版本、哈希、读取时间、文件位置；旧版本可定位 |
| objects / object_identifiers | 平台生成 object_id；来源标识映射到对象；名称不充当强身份键 |
| assertions / assertion_revisions | 主体、谓词、标量值或对象引用二选一；本体版本、业务有效区间、系统记录区间、来源类别、采纳状态 |
| evidence / assertion_evidence | 来源版本与结构化字段，或文档偏移/页码/章节；一条声明可有多份证据 |
| action_events | 操作 ID、调用身份、参数、目标修订号、原因、结果及产生的声明修订 |
| object_projections / projection_dependencies | 当前展示结果、冲突状态、支持及反对声明、融合策略版本、输入修订号 |
| ingestion_runs / extraction_runs / jobs | 本体、模型及提示版本，输入版本、尝试与失败信息、幂等键 |

来源内容哈希用于判断变化，不单独作为全局身份。不同来源给出相同值时仍保留独立证据；同来源同版本同抽取配置重试不能重复插入。是否替换旧抽取输出必须通过明确重处理操作，不因一次重试自动改变历史。

系统时间由数据库事务写入；业务时间取自数据或明确反馈。采用左闭右开区间，未知业务起止允许为空，但必须记录时间已知/未知及精度，不能将“未知”解释成“永远有效”。历史查询须同时接受业务时点与系统获知时点。

## 5. 接入、本体生成和抽取

第一条结构化路径：CSV 上传，经现有解析器读取，保留文件版本、记录键和列定位，再按映射生成声明。CSV 用于尽快验证结构化语义，不宣称已验证数据库连接器。真实数据库连接接入放在闭环后，沿用相同输入契约。

第一条非结构化路径：有文本层 PDF，复用已验证的解析及页码定位。复杂表格、扫描件 OCR、图片理解暂不纳入验收；DOCX 可复用但不作为本阶段额外必做入口。

本体生成与事实抽取分为两次受控任务：

1. 读取字段描述及有界样本，模型提出类型、属性、关系、来源映射和支撑依据，保存为本体草稿。
2. 用 schema 和样本检查重复概念、悬空引用、属性类型、身份映射及关系端点。第一版由操作者查看、编辑并发布，不要求每个抽取结果人工审批。
3. 固定发布本体版本和来源版本，运行映射/抽取，产生候选声明及原文引用。
4. 程序验证类型和引用位置。引用找不到、类型不符或对象不确定时进入待处理结果，不进入已采纳视图。
5. 通过身份解析及融合策略构建对象视图；来源为知识文档并不妨碍产生对象和事实，但必须走声明校验路径。

第一版对象匹配只接受明确的来源映射或可信业务标识（例如合同号、统一企业标识、员工编号）。仅有同名实体保留候选关联，不自动合并；没有结构化来源的文档可独立创建对象。

## 6. 冲突、时序与反馈的默认规则

- 单值属性在可比较的有效时间内出现不同值时保留冲突，不采用“最后同步的值必胜”。时间不可比较时标注不确定，不静默确定唯一值。
- 同值声明聚合支持证据；来源优先级只有显式配置并记录策略版本后才生效。
- 多值属性和 N:N 关系按定义允许并存，不能统一按单值冲突处理。
- CorrectProperty 创建人工声明及审计，不修改原始来源。操作者必须明确有效范围和持续方式：直到撤销，或仅覆盖指定来源版本；默认直到撤销，并在界面明示。
- 后续同步保留来源新声明，人工覆盖按上述策略生效；与人工值不同的新来源证据仍显示争议及待复核提示。
- RejectAssertion 和 CorrectValidity 创建修订，保留系统历史；人工修正不能回写成“系统过去已经知道”。
- 每次修改按 expectedRevision 检查并发，在事务中写入修订、审计和重算任务。当前范围优先同步重算受影响对象；读取发现视图落后于输入修订时重算或明确返回未就绪，不静默提供旧值。
- 本阶段维护“来源版本→声明→对象视图”的直接依赖；任意多跳推导及答案缓存失效留到引入这些能力时实现。

## 7. 最小可用接口与界面

服务接口覆盖：导入来源、查看任务、生成/编辑/发布本体、运行抽取、查询对象、查询关系、查看声明证据、双时间查询、提交 Action。写入操作携带幂等 operation_id 和必要的 expectedRevision。

界面只实现三个可检查入口：资料与任务、本体草稿/发布、对象详情。对象详情展示属性/关系、冲突、证据、时间和修正入口。优先复用能直接适配的组件，阻碍新流程的旧交互可替换。不要求完整图谱画布、自然语言问答或 Agent 自主操作全部流程。

## 8. 实施任务顺序

| 任务 | 具体产出 | 依赖与验收 |
|---|---|---|
| F1 契约及样本 | 元模型、声明/证据/Action schema，结构化与 PDF 样本、期望结果 | 必须覆盖冲突、交接、迟到信息、纠错；期望答案与模型输入隔离 |
| F2 数据与事务 | PostgreSQL 初始化、开发数据重建、领域 repository、基础任务 | 全新库可初始化；约束、原子写入、修订并发及幂等通过集成测试 |
| F3 来源与证据 | CSV / PDF 版本化接入、记录和正文定位 | 两类来源均可回到指定版本的字段/原文 |
| F4 本体与抽取 | 模型适配、候选本体发布、确定性映射和文档抽取任务 | fake 验证流程；真实模型单独执行并记录错误，不以 fake 代替效果验收 |
| F5 对象和时间 | 独立身份、声明融合、当前及双时间查询 | 文档能创建对象；跨源匹配、冲突、历史结果正确 |
| F6 反馈与重算 | 四类 Action、审计、覆盖策略、依赖更新 | 修正、并发、重试、再次同步、来源修订符合语义 |

F1–F7 是第一阶段内部任务，不是要求完成全部设计后再一次性联调；每项完成即运行相关集成链路。已有能力通过新契约验证即可复用，历史限制不自动进入新实现。

## 9. 第一阶段完成标准

必须同时满足：

1. 不依赖旧 SQLite 状态，空库能够重建整条样本链路。
2. 能提出、修改并发布候选本体；新增一种简单对象类型不修改核心业务代码。
3. 结构化与文档来源都能形成对象、属性或关系，并准确定位证据版本。
4. 合同金额冲突不丢证据，当前结果能解释采纳或争议原因。
5. 迟到的交接信息支持分别查询业务时点和系统获知时点；未知时间不伪造。
6. 人工纠正后再次同步按覆盖策略执行，旧声明及旧系统视图仍能追溯。
7. 来源修订后直接依赖的声明及视图按规则失效或重算，不混用旧证据和新原文。
8. 并发修改、重复执行和任务失败不产生无声覆盖、重复声明或半次提交。
9. API/页面写入有可信调用身份和服务端授权，证据读取按本阶段实际内部权限检查。
10. 机制验收全部通过；真实模型的本体生成及声明抽取分别记录正确率、遗漏与错误引用，并人工复核冻结评测集。未完成真实模型评测时只标记“机制闭环通过”，不得标记完整第一阶段效果验收通过。

真实模型指标阈值在 F1 冻结评测集时依据试点要求写定；若尚无真实数据，先完成合成数据机制验收，并将真实效果作为明确未完成项，不虚构生产可用性。

## 10. 本阶段暂缓项

全量连接器、任意行业全自动无人审核发布、模糊实体自动合并与通用拆分、任意多跳推理、向量检索、完整图谱编辑器、知识驱动的业务执行 Agent、共享 SaaS 多租户、生产集群与高可用、旧数据库迁移及历史接口兼容。

暂缓不代表否定；每一项进入下一阶段前须由已验证的业务需求驱动。第一阶段的架构检验是“同一套对象、声明、证据、时间和 Action 能否跑通”，而不是展示页面数量。

## 11. 2026-11-02 补齐决定（本轮实施基线）

本节补充原决定，保留对象式语义层、声明修订和派生投影；继续在 feat/knowledge-platform-phase1 开发。

### 11.1 本轮实现

1. **语义隔离**：声明增加 polarity（affirmed/negated）、modality（actual/planned/hypothetical）、condition（原文条件文本，不执行）。否定、非实际、有条件、inferred 声明保留证据并进入 pending，不作为普通事实。布尔属性 false 仍可表示本体明确定义的取值。提示要求识别这些维度，但程序不能保证模型不漏标，真实评测必须覆盖。
2. **可比口径**：属性和声明可记录 comparison（unit/currency/scope）；CSV 映射显式配置口径。不根据数字猜币种，不自动换算。参与当前采纳的声明口径不同或缺少本体要求的口径时标记 incomparable，不选值。既有无口径工程样本保持兼容；真实金额资料接入前必须配置口径。
3. **最小身份纠错**：管理员 RematchIdentity 携带旧对象修订、明确标识、选中的来源声明、目标对象修订（或新建同类型对象）。事务内改绑未来解析标识，仅移动人工选中的声明及关系端点；保留旧声明、证据、系统历史、绑定修订和迁移映射。未选择的不猜归属。通过反向新 Action 纠错，不删历史。通用合并拆分及候选匹配队列暂缓；原“保留修订能力”落实为这条受限路径，原“同名候选关联”收窄为保留独立来源身份，不声称已实现候选队列。
4. **修正依据**：CorrectProperty / CorrectValidity 可关联来源版本和定位器，服务端逐条验证。改值创建新人工声明，不继承原值证据；修订新增依据绑定修订号。证据查询可指定 revision，旧历史不能看到未来新增依据。无文档依据时保留操作者与理由，明确是人工判断。
5. **溯源**：新融合语义使用新策略标识；返回声明语义、口径及隔离理由，不声称能重放任意旧算法。任务记录耗时、输入规模及提供方可用 usage；未知费用保持未知，不保存密钥。
6. **评测与权限**：提供冻结评测集规范和成本/负载记录模板；真实资料及业务阈值未确定前只标机制验证。仍为单实例 admin/editor/viewer 权限，明确所有授权用户能读实例资料；需要部门隔离的资料必须等细粒度权限完成后接入。

### 11.2 继续暂缓

- 自动推导、规则引擎、支持组、递归失效：正式开放派生知识时成组实施；即使一步推导当前也只作 pending 候选。
- 通用合并拆分、模糊身份候选队列：根据真实身份误差和审核量决定；事件记录不等于完整拆分引擎。
- 部门/字段/证据权限：试点有隔离要求时是接入前置项，单企业不等于不需要内部权限。
- 自动单位换算、条件求值、多版本并行、任意旧策略重放、生产容量优化：按试点另行实现。

### 11.3 任务与验收

公共验证边界为领域 API、HTTP 和对象投影，沿已有已授权测试边界执行。

- [x] S1：否定/计划/条件隔离；同值不同币种、不同税口径及缺失口径不可比；布尔 false 正常保留。
- [x] S2：修正新依据可定位、错误定位回滚、旧修订不见未来依据、无证据人工判断有明确标识。
- [x] S3：选中声明和关系可改绑，未选中不移动；历史绑定、幂等、过期修订拒绝、反向纠错及再次同步正确。
- [x] S4：增量 schema 初始化保留已有开发数据；HTTP 与界面入口一致；运行指标与评测/权限边界可查。

## 12. 自动生成链路补齐（2026-11-02 用户授权实施）

手动发现的自动生成→审核→执行缺口纳入首期，不用预制本体验收替代自动链路。基线为 cb8b79b，保留环境、诊断与日志改动。按项目 implement / tdd / code-review 技能，在领域 API、HTTP、映射执行和工作台边界验证。

本轮采用独立版本化构建计划：固定本体、来源版本及覆盖、模型/提示，保存 CSV 多对象/显式双端点映射和 PDF 候选声明；每个属性/关系有独立时间规则。用户逐项审核或排除候选、确认时间和口径，服务端预检后批准。批准需已发布的同一内容本体；计划改动、来源更新或本体定义变化使预检失效。来源抽样范围与全量执行校验分别展示。

跨源身份只建议同类型、相同原始编号的精确候选，由用户明确批准相同、保持独立或排除相关声明。批准固定具体来源版本、依据及范围；后续新版本需重新审核，不创建自动扩大适用范围的模糊合并规则。同一来源集合/编号的后续批准可引用此前相同 canonical identity，使再次同步保持对象身份。身份决定与构建计划均走服务端事务和审计；不是修改命名空间即获授权。既有对象误绑仍使用受限 RematchIdentity。

系统支持 CSV 单行内多类型对象、正反关系端点、直接字段及白名单标量转换，不执行任意模型代码或跨表 join。PDF 抽取结果先进入构建计划，不直接变成正式声明；时间依据与解释需审核，未知不补日期。生成本体后独立生成计划，避免一个超大调用且允许失败续接。

批准后的构建以来源为事务单位，使用冻结输出和固定幂等键，不再付费抽取。明确显示每源完成/失败；新计划构建会替代所选来源的旧来源声明（人工覆盖保留），必须在批准时告知，旧系统历史可查。旧低层单源映射 API 保留作工程兼容入口；新自动链路不能靠 raw mapping 绕过计划批准。

### 12.4 发现链路的证据与语义门禁（2026-11-03）

本轮修改 discover 业务链路，不推翻 BuildPlan 或现有运行控制。程序从实际样本生成不可任意改写的证据目录（CSV 单元格、PDF 精确片段），模型只返回 evidenceId；程序组装 discoveryEvidence 并校验新增/变更的类型、属性、关系覆盖。未变基础成员可沿用依据，定义、端点、ID 等仍做最终结构检查。目录最多 3000 项，正式发现输入最多 180KB，超预算显式报错，不静默省略。证据存在不证明业务含义。

新增 discovery.validation 与逐项语义审核记录（复用现有 discovery JSON，不增加数据库版本）。自动候选必须确认类型范围/身份范围、属性必填与基数、时间含义、关系方向及模型不确定项后才能发布；审核理由、定义指纹与操作者写审计。编辑定义或通过页面复制自动候选会清除审核，发布时再次定位原文与检查成员依据。旧自动草稿缺少新契约时要求重新生成。正式发布不标记模型语义已自动验证正确。

口径在新写入、预检、提交与发布边界检查：未知用缺省值和审核说明，拒绝“未知/未声明”等解释污染比较键，拒绝“金额”作单位；币种使用当前运行时支持的代码，新增币种需明确扩展。保留历史宽松读取，便于修正旧错误值。模型没有权力把字段共现推成雇佣、所属、业务有效期或唯一性约束；提示采取保守默认，业务人员仍需核实。

对比脚本与正式任务共用候选目录和校验器，单独写校验报告，generation completed 仅代表模型运行完成。真实原文支持率、召回、人工修订成本、速度收益仍需相同冻结样本复验。没有实现自动语义证明、全量 ID 程序分配或任意行业模板。本轮只完成静态检查，新增验证用例未执行，也未发起模型/数据库操作。


### 12.5 人工介入原则修正：节点与异常驱动（2026-11-03）

本节取代 12.4 及先前说明中“逐类型/属性/关系确认”“每次身份延续都需审核”的要求。人工在重大节点作决定，不能退化成逐项审批抽取结果。

- 自动发现只为首次启用、既有成员删除/语义改变/属性归属改变、动作变更和新增硬约束生成汇总事件；普通可缺省属性等新增不要求确认。已发布基础本体作为差异基准，编辑会按差异重算事件。首次发布是一次整体业务范围确认，不逐成员打勾。
- uncertainties 中真正含义不明的成员暂缓；依赖项一并暂缓，保留原候选和证据。若修改既有成员存在歧义，保留基础定义而不覆盖。其他明确候选继续推进；全部类型暂缓时明确返回无可采用内容。人工主动恢复暂缓项时作为业务决定处理。
- 保留证据目录、覆盖检查、口径及版本校验；定位失败、非法口径、端点错误由系统拒绝，不转成“勾选即可通过”的人工任务。旧 v1 逐项问题在读取草稿时按新规则重新计算，既有审计历史保留。
- 构建计划普通来源/映射/声明不再要求 reviewed；include 保留为可选排除操作。首次跨源身份对应仍需决定，绑定未变的已批准对应自动延续；绑定冲突、重绑/拆分沿旧受限纠错流程。
- 预检汇总同主体单值属性/单值关系的不同值在已知有效期内重叠的潜在冲突（含已有未替代来源），以及固定时间假设。unknown 时间、计划、否定、条件、inferred 不按普通确定事实制造冲突。缺必要口径保持不可比，不因缺失信息要求逐项批准。
- 新重大构建事件按摘要记录理由和事件指纹；相同已批准事件可沿用决定并记录来源计划。无新增重大事件时理由可空。本体已发布且预检就绪时自动冻结批准计划，审计 auto_approved；启动构建仍为显式操作，不自动触发模型或网络调用。首次本体发布权限保持 admin，普通编辑权限不被提升。

上述机制不能自动证明所有业务语义。模型未报告的含义错误仍需冻结样本发现与规则改善；本轮没有宣称零幻觉、完整语义证明或自动推理引擎。已更新门禁与用例，仅完成静态检查，未运行数据库、测试或模型。


### 12.6 发布后的一次开始、批量决定与问题分类（2026-11-03）

本轮修正实际手动验证中仍然偏多的人工介入：三组具体身份对应不应分别强制填写理由，金额值冲突也不应导致金额属性被暂缓。

1. 身份对应增加 POST /api/plans/:id/identities 批量决定：统一 same/separate 与理由，可指定单组例外；服务端校验本批候选指纹、来源版本与现有绑定，仍按具体编号分别保存决定和审计，不生成永久匹配规则。旧单组保存时可继承本轮理由，避免填完总理由仍反复阻断。网页批量决定与下一构建任务在同一事务提交。
2. uncertainties 分类为 definition、fact_conflict、missing_context、time_attachment。仅 definition 暂缓成员；来源金额不同保留属性和各自证据，不选择胜者。口径缺失保留属性并声明 comparisonRequired 维度（unit/currency/scope），不编造期望值。时间附着未知保留已知属性，实例有效时间 unknown；字段本身业务归属不明仍属 definition。
3. 投影 semantic-conflict-v3-context 支持只要求比较维度、而不预设值。必要口径缺失显示 incomparable；冲突预检也不把这类事实当已可比的不同值要求人选胜者。旧比较字段保持兼容读取，不修改已发布定义或既有历史。
4. 主入口“开始构建知识”提交 autoBuild 计划任务。候选计划与后续预检/构建任务原子落库；后台自动预检、批准、构建。需要业务决定时 stage=awaiting_decision，自动结构/证据等校验失败为 blocked_validation，不能把系统错误包装为逐项审批。继续构建使用冻结计划，preflight=true 的 build 任务不再调用模型；不隐式重新抽取或付费重试。
5. 页面每四秒只读刷新活动任务进度，不触发模型、不覆盖计划表单。分步保存、预检和仅生成计划保留在高级入口。原本缺失金额的已发布版本不会被代码自动篡改，需基于原始资料生成新版候选并发布后再构建。

无需新增数据库迁移（复用 jobs、plan_events、discovery 等结构）；新可选 comparisonRequired 不改变旧定义的解析指纹。已补金额保留、缺失维度不可比、批量身份快照与一次开始/暂停/自动继续用例。只做静态检查，未运行测试、数据库初始化或真实模型；实际流程仍待验证。
