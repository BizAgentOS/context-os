- 刷新使旧对象事项缓存失效并提示重读；事项显示双时间，定位时恢复其查询范围。构建审核从输入事件即保护未保存编辑；未载入JSON不会被刷新覆盖，也不能继续构建旧方案。

## 新增读取契约

沿现有Bearer认证与`authorize`：

- `GET /api/browse/ontology`：最新已发布本体或null。
- `GET /api/browse/objects?type=&query=&offset=0&limit=30`：有界目录与本页当前投影摘要、hasMore及覆盖说明；搜索当前业务编号。
- `GET /api/objects/:id/neighbors?validAt=&knownAt=&offset=0&outgoingOffset=0&edgeOffset=0`：双时间一跳图、节点真实标识、入向/出向/图边分页与截断说明。
- 构建方案列表补充保存预检的错误、就绪状态和未决定身份数，不向统一事项传输完整候选输出。

所有展示投影复用`KnowledgeCore.object`及既有融合规则，不改领域语义、存储、身份和发布门禁。目录摘要按有界页面读取；未进行生产规模性能验收。

## 范围与限制

- 全局对象/问题总数没有可靠全库接口时不显示。统一事实事项仅覆盖当前已查询的对象，不声称全库无冲突；刷新后重新查证，不维持假“处理完成”。
- 领域构建回执提供声明数和涉及对象，未拆分新建/变更，也没有全量剩余事实问题数；界面明确未知，提供结果对象和真实回执入口，不把涉及数量当作新增数量。
- 当前本体没有独立领域分类元数据，因此本轮提供类型筛选，不凭名称发明领域分类。
- 搜索按业务编号；名称解析用于显示，没有加入全库名称全文检索。目录摘要仅为当前投影；历史查询在对象详情中执行。
- 浏览器验证证明合成样本的界面与机制；真实模型质量、真实业务效果、生产容量和MySQL集成不是本轮验收结论。
