## D1：领域辅助本体生成

状态：已确认方向、待实现。顺序：先完成当前自动构建链路手动验收与阻断问题修复，再实施本任务；除非用户调整优先级。

目标：在接入后的知识构建阶段，用有据的领域推断减少人工输入，并用确认后的配置指导本体生成与抽取。

| 层次 | 示例 | 用途 |
|---|---|---|
| 企业行业 | 制造、能源、金融 | 提供专业背景和术语，辅助理解资料。 |
| 业务领域 | 合同管理、采购、设备维护 | 决定采用哪套领域配置，实际指导本体建模和抽取：关注哪些对象、属性、关系、事件、时间与业务口径。 |
| 当前业务问题 | 合同金额是否冲突 | 限定本次知识构建或验收的范围和目标；问答时决定如何查询已有知识。 |

用户未填写业务目标、行业或领域时，默认从已接入资料的结构、字段注释和原文推断业务领域候选；允许多选、未知和人工覆盖，用户明确指定时优先。模型提出候选和依据，系统选择版本化领域配置，操作者审核确认。确认的领域配置要实际指导本体生成与抽取，来源证据决定能抽出哪些事实。日常问答复用已有声明和证据，不因每次提问触发重抽；发现缺口时可另提构建或复验任务。

- [ ] D1.1 业务目标、行业及业务领域均为可选输入；不填也能进入资料推断流程，用户指定优先于模型推断。
- [ ] D1.2 输出领域候选、字段/原文依据及歧义；支持多领域、未知与人工覆盖，不把模型自报分数当校准概率。
- [ ] D1.3 提供通用、合同管理两套可组合领域配置。包含术语、候选对象/关系、身份范围、逐声明时间、金额口径及错误反例。
- [ ] D1.4 区分有证据的候选与无数据支撑的建模建议；不因模板存在概念就编造资料内容，不改变对象/声明/证据/审核底层契约。
- [ ] D1.5 在发现任务指纹及声明溯源中固定领域选择、配置版本和提示版本，沿用既有本体稳定 ID，展示候选差异。
- [ ] D1.6 冻结样本对比通用提示与领域配置：概念覆盖、关系方向、时间归属、证据支持、人工修改量，以及耗时/调用成本。

第一版优先同一次 discover 调用返回领域判断与本体；若必须先确认领域再生成，则显式两步，不隐式增加付费调用。不建立全行业分类体系、不自动切换模型、不实现行业独立存储引擎。本任务记录不等于授权立即运行模型评测。
