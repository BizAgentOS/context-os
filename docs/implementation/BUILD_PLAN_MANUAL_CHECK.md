# 自动构建计划：当前验证与操作说明

更新：2026-11-03。本节为唯一当前操作流程；文末为历史记录，不再按旧步骤执行。

## 当前验证结果

用户已报告完整执行一次流程。本轮已在独立测试库完成知识核心 59/59（无跳过），并新增验证未保存排除操作不会被批量身份决定丢弃的 UI 回归。最终结果、修复及真实效果边界见 [收尾记录](PHASE1_CLOSEOUT.md)。本轮未调用真实模型、未初始化或修改业务库，未进行新的真实浏览器视觉验收。

## 启动与首次构建

1. 使用当前服务代码。仅在需要更新用户数据库 schema 时，由操作者核对目标后显式执行 `npm run knowledge:init`；保留已有数据，不运行 reset。已有 001–005 的库无需因本次收尾重复初始化。
2. 上传 CSV 与文本 PDF，选择来源，生成候选本体。发现与计划生成是独立模型任务，不因单环节失败重做已成功部分。
3. 查看重大本体节点摘要：首次启用、已有语义或硬约束变化需要决定理由，保存决定后发布。普通成员自动校验，没有逐成员勾选。
4. 发布后点击“开始构建知识”。后台依次生成计划、预检、批准并构建。等待具体身份或重大事件决定时暂停；结构、证据、口径与版本错误显示系统校验阻断。
5. 首次跨源同类型同原始编号的身份可填写一次本批理由、批量决定 same/separate，单组可设例外。绑定未变的已批准身份自动延续。两个既有不同对象不能在这里静默合并，使用受限身份纠错。
6. 若调整映射、时间、证据或纳入范围，先保存并重新预检，再决定身份。未保存的来源/声明排除会阻止批量继续，不会丢弃排除后启动旧范围。仅修改身份理由和单组例外可直接提交。
7. 对已冻结计划的继续和重试不调用模型。系统不隐式付费重试，关闭页面不取消持久化后台任务。
8. 核对对象、逐来源证据与负责人有效期，不能只看任务 completed。日期未知保留 unknown；不同值只有口径可比且有效期可比时才是 conflict，缺必要口径显示 incomparable。

## 纠正、再次同步与保护

- CorrectProperty 使用对象 ID/修订；CorrectValidity、RejectAssertion 使用声明 ID/修订。填写真实理由、明确有效范围和持续策略；不自动猜测币种或有效日期。
- 同 sourceKey 上传新 CSV，可只选择该新版本生成计划；既有未变统一绑定沿用，同编号新来源首次关联仍需决定。预期对象 ID 稳定，人工覆盖保留，不同来源值和旧系统历史可查。
- 来源更新、绑定变化或后续构建应阻止旧批准重放。通过本轮计划、身份、HTTP 与 PostgreSQL 集成用例验证；当前业务数据上的每项手动操作不由本轮测试代替。
- 保存结果恢复只适用于正常提交且可追溯的原发现输出，冻结输入与当前来源须匹配。点击“复用保存结果校验（不调用模型）”新建本地校验任务；原失败任务保留，没有保存结果时不转付费调用。

## 测试与效果边界

数据库测试只能指向独立空库，通过 `CONTEXT_OS_KNOWLEDGE_TEST_DATABASE_URL` 显式指定；不可使用业务库。真实效果评测仍按 [评测基线](PHASE1_PILOT_EVALUATION.md) 单独执行。D1 是后续任务，不作为本次工程收尾的新增功能。

## 启动准备（由操作者执行）

在项目根目录执行：

```sh
npm run knowledge:init
npm start
```

init 在配置的 PostgreSQL 上补齐 003/004/005 增量表，不清空资料；无需迁移 SQLite，也不要为本次验证运行 reset。已有服务需先正常停止再启动，避免同时启动两个实例。启动页地址及登录令牌沿用项目现有配置。

模型默认仍为 240 秒，知识模型最多 4 次迭代。需要扩大等待预算时，可在根目录 .env 设置下列变量并重启：

```dotenv
CONTEXT_OS_KNOWLEDGE_MODEL_TIMEOUT_MS=600000
CONTEXT_OS_KNOWLEDGE_MODEL_MAX_ITERATIONS=4
```

上例是可选的 10 分钟预算，不是已修改的本地配置。超时范围为 1 秒至 30 分钟，迭代范围 1 至 24。预算触发中止，底层调用的退出清理可能额外耗时；增加时间不保证模型正确提交。普通 Agent 默认运行预算不变。任务固定创建时的模型、提示版本及预算，配置变化后点击“以当前配置新建任务”，保留旧任务诊断，不自动重试付费调用。

## 首次构建

1. 上传 contracts.csv 和 contract-document.pdf，使用不同 sourceKey。先不要上传 updated 文件。选择这两份资料，生成候选本体；从完成的任务打开本体。若使用已有草稿扩展，勾选沿用基础本体，核对来源覆盖与差异。
2. 核对类型、属性和关系含义，生成构建计划。发现本体与生成计划是两个独立模型任务；仅计划生成失败时无需重复发现本体。
3. 打开计划，在表单中审核来源、CSV 对象编号列、属性、关系起点/终点；PDF 声明逐条核对原文、身份编号、语义、口径和时间。可以修改或排除错误候选，无需手写映射 JSON。排除无编号或无证据声明，不应编造编号补齐。
4. “负责合同直到某日”的日期只归属负责关系；不能作为 Contract.valid_to。没有明确时间就保留 unknown。已知时间需解释归属并选择有效原文依据。否定、计划、有条件或推断声明仍进入待确认状态，不自动成为肯定事实。
5. 逐项勾选已审核，填写本轮理由，保存并预检。首次预检会列出跨源同类型、同原始编号的身份候选。对 C001 等逐组检查来源与证据，明确选择同一对象或分别保留，并填写理由；再保存并预检。只有精确编号候选，不提供模糊匹配。
6. 金额的单位、币种、含税范围只有原文依据时直接记录；人工确认的假设需在理由中注明。缺少必要口径或口径不同的金额可能显示不可比较，不应为展示冲突而虚构口径。
7. 管理员点击“发布本体并批准计划”。两步分别持久化；若发布成功但批准失败，页面明确说明，刷新后可继续批准，无需重复发现。已批准计划冻结内容，不可原地修改。
8. 执行已批准计划，不再调用模型。刷新列表和计划状态，查看逐来源完成结果。部分来源成功时保留进度，可在输入未失效时重试同一计划；输入失效则重新生成计划。is_current 标识该次结果是否仍是当前来源构建。
9. 核查 C001 是否融合为一个对象、金额的冲突或不可比较状态是否符合口径、负责人交接是否落在关系时间、证据和系统历史能否追溯。不能只看任务 completed。

## 再次同步

使用首次 CSV 的同一个 sourceKey 上传 contracts-updated.csv。可以只选择新 CSV 版本，基于原本体生成新计划；预检会列出已有统一身份绑定，需要重新确认编号延续。也可以同时选择原 PDF 重新审核；审核金额 1100000、负责人 E002 和时间归属。已有来源身份再次人工批准延续时复用原对象，即使本次仅选择一个来源；不静默继承旧审核。原计划因来源版本更新失效；新构建替代所选来源声明，人工修正及系统历史保留。后续构建完成后，旧批准计划也不得重新覆盖新结果。

页面刷新保留未保存审核，需要先保存再重新读取计划状态。切换计划或打开其他计划前先保存当前审核。

## 遇到失败时记录

记录任务 ID、尝试编号、runId、模型/预算、最后事件和安全错误信息。区分运行超时、提交被校验拒绝、运行结束但未提交等情况。不要把密钥、令牌或完整 .env 放入反馈。日志默认 local-state/logs/context-os.log，仍是单进程诊断；未接入所有旧模块，不能称生产日志体系。

### 本轮身份补齐后的检查

- 首次融合完成，对象 identifiers 应同时包含 approved 身份与 CSV、PDF 的 source 别名，证据仍指向各自版本。
- 仅上传并选择 updated CSV，预检应显示 C001 先前对象/绑定；未确认延续不能批准，确认后对象 ID 不变。
- 既有统一绑定选择“保持独立”会阻断，不能用这个按钮拆分对象，需明确执行身份纠错。
- 构建前若有人修正来源或目标绑定，旧批准不应继续执行；重新生成/审核计划。旧批准输出缺身份快照的也需重新生成。
- 旧 extract 映射使用共享 namespace 会失败；使用 source.<sourceId> 也不能绕过已有跨源身份的重新审核。新自动构建使用计划入口。
- 目前只支持同类型同原始编号的候选；不同编号的对应不在本轮实现范围。


### 2026-11-03 发现链路操作变更

本轮无需新增数据库 schema（仍需已有 003–005），重启服务后以当前提示新建 discover 任务；旧任务不复用旧提示。模型产物是带 evidenceReferences 的候选，由服务端转换成正式本体的 discoveryEvidence；不要直接拿追踪 output.json 当可发布本体。

打开自动候选后，在“业务语义审核”逐项点“查看该项原始依据”，核查类型特化、关系含义、时间与口径。错误先修改定义并保存，重新读取后逐项确认、填写理由，再点“保存本体语义审核”，之后发布或回计划批准。任何定义编辑会清除旧审核；页面另存副本会保留自动来源并要求重新审核。证据错误或成员缺依据会阻断发布，不通过勾选绕过。旧自动草稿没有新审核契约时重新生成。

金额币种未知时删除 currency，而不是写“未声明”；口径要求是否需要设定由业务确认，不根据值猜测。程序对可定位证据的审核不代表自动证明了业务含义。本次只通过静态检查，运行、界面与真实模型仍待手动复验。


### 本轮回归检查重点

- 无异常时：一次开始后应直接看到构建完成，不需要打开计划或再次按预检/批准。
- 首次合同/公司/员工三组对应：一次统一理由和批量决定即可，每组仍有独立审计；不允许同字符串无条件自动合并。
- 若例外组要保持独立，在该组展开选择 separate，然后批量批准其余对应。
- 两个来源金额不同：候选本体仍有金额，实例保留两个值。没有必要币种/单位/口径时应不可比；确认可比后才验收冲突，不问模型“选谁正确”。
- 关闭页面后后台继续；生成计划与后续任务、批量身份决定与继续任务均有事务持久化。真正调用失败仍需显式恢复，不无限自动付费重试。
- 启动需重启服务使用 v8 提示，新建任务；本轮未新增 SQL、未运行上述验收。


### 证据恢复边界

此恢复使用原任务的 request/summary/output 追踪，必须完整保留 local-state/model-traces（或配置的追踪目录）。没有输出、发生超时或输入已变化时不支持盲目复用。缺少真正的属性或关系依据仍报错，并列出全部缺失成员；不能给一个类型的所有属性自动套同一段引文。仅复用已有有效引用，不拼造证据。候选恢复成功后仍按重大节点规则发布；这次是源资料正常、覆盖引用遗漏的修复，不代表所有语义已经正确。

### 2026-11-03 对象证据展示修正

原“证据”按钮写入对象详情末尾的公共区域，无滚动与就地反馈，容易误认为没有反应。现改为“查看证据”，在该声明下方直接显示加载、来源名称/版本、CSV 记录键/字段/值或 PDF 引文；技术定位放可展开详情，空证据和失败也就地提示。新增 evidence.js 静态资源，需重启服务并刷新页面。未修改事实或证据数据。

### 2026-11-03 修正操作目标类型

属性纠正 CorrectProperty 使用当前对象 ID 和对象修订；CorrectValidity / RejectAssertion 使用选中声明 ID 和声明修订。原“选择声明作修正目标”可把声明 ID 留在 CorrectProperty 表单，导致通用“目标不存在”。现拆分为“纠正此属性”和“修正此声明时间”，切换操作自动同步正确目标，目标字段只读；历史视图和未选声明会在提交前明确阻断。服务端区分对象 ID 不存在/类型用错与对象修订过期。金额人工纠正仍需填写已知有效范围、持续方式与理由，不自动代填币种或提交业务修改。

类型检查、JS 语法及 4 项目标选择/证据 UI 模拟测试通过。未替操作者执行人工修正，未实际浏览器或数据库写入验证。
