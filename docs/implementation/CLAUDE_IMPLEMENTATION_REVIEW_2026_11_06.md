## 证据与影响

### R01：引用循环的候选类型过期（P2，待修）

`src/knowledge/structured-compiler.ts:275`在定义阶段后重算一次references，但`:276–281`引用循环随后会修改candidates，却继续使用旧reference对象。目录每次更新；rebase刷新普通成员ref的id/name/from/to，但不会刷新targetCandidateTypes的字符串数组。

离线复现：6份原生来源、模拟模型与内存SQL回执；首个引用任务将B改为B_renamed，后续请求目录含B_renamed且不含B，referenceCandidates却仍有targetCandidateTypes=['B']。这是当前代码的实际不一致，会误导模型；宿主重新计算的绑定校验又可能拒绝依据旧候选选出的端点，导致响应已付费保存后仍无法通过。不是仅未来风险。

证据：`work/claude-review/reproduce.ts`、`reproduction.json`。仅离线夹具，真实模型0次、数据库连接0。此复现验证了同一引用循环跨任务过期；递归分页刷新也应在修复时单独覆盖，不能声称此次已逐场景复现。

### R02：抽样未匹配的结果语义不够明确（P2，待修）

`jobs.ts:222–223`和`native-coordination.ts:9–15`固定来源样本通常最多10行。`structured-references.ts:74`确实将rowLimit写1000，但同时记录checked、targetChecked、sourceLoadedRows/targetLoadedRows、sourceCoverage/targetCoverage。因此rowLimit作为检查上限并非虚报实际读取量；报告“checked永远≤10”只适用于此发现路径，不适用于直接传入更多固定数据的调用者。

离线复现：两端各加载1/100行时，checked=1/targetChecked=1/status=zero_match/rowLimit=1000。其含义是加载范围内零匹配，不能推为整表不相交。`relationship-validation.ts:42`及测试明确保留零匹配关系，程序并未实现“零重叠即删边”。更大的有界样本仍不证明不存在关系，且外键源值和目标表前N行可能完全错位；无需用任意“小样本阈值”伪造统计置信度。

建议保留匹配计数，分别记录源/目标总行、已加载、非空参与、完整性与上限，明确sample_no_match或insufficient_coverage；只有两端已确认完整覆盖才能标完整范围zero_match。更改状态须同步关系验证循环和UI（目前只识别overlap_observed/zero_match），不能把新状态误当无法执行检查。额外固定版本探测可作为独立优化，不能回读变化中的业务表或将证据数据装进模型输入。
