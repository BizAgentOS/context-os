## 独立标注与冻结流程

1. 指定业务负责人、两位独立标注者与争议裁决人，确认这三表的业务问题、授权范围及错误代价；目前均未指定，不代填姓名或签认。
2. 为标注者只提供固定来源的完整声明、原注释、已加载数据和覆盖说明。隐藏历史候选、协调输出、机械建议和当前模型结果。原始版本无法复核则停止，不能只拿协调输入中加工过的目录作完整真值。
3. 两人各自填写独立JSONL，穷举有证据支持的类、属性、关系及明确未知项；填写来源版本、列/原文位置、关系端点/完整复合列组、枚举依据类别、适用范围与应有处置。允许业务同义命名，裁决语义等价，不能按模型ID强行逐字匹配。
4. 比较独立结果，报告裁决前一致率及争议类别，裁决人逐项记理由。所有高风险与歧义项都裁决；无法确定的项保留unknown，不构造阳性关系。`annotation-template.json`仅字段模板，不能当已标注案例。
5. 按来源/业务问题/证据族划分调参集和验收集，同一关系/记录及近似重复不得跨集；三表四行太小，若无法独立留出，本轮只能报告固定案例探索性结果，不能宣称企业准确率。已被既有开发/调参使用的案例标记development，不冒充盲测。
6. 在任何真实输出产生前签认范围、指标阈值、样本数和未覆盖类别；冻结裁决后的expected、split清单与哈希，记录操作者和时间。expected放评测目录，运行输入只允许白名单的来源/候选/策略字段，禁止导入标注目录。冻结后修改答案、阈值、提示或模型须开新版本，原始失败报告保留。

准备目录将`model-inputs`（仅清单引用）与`gold`、`results`分开；目录分开本身不等于权限隔离，执行前须检查实际请求白名单及序列化信封，无expected/裁决内容。不得使用能读取整评测目录的模型工具。
