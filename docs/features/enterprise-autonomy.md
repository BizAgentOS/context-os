## FEATURE_069 MySQL 来源接入与集中决定

### Problem Statement

新知识核心仍依赖上传 CSV/PDF。企业需要一次授权 MySQL 数据源，自动探查、读取并形成可追溯知识；本体和身份等重大事项应集中处理，不能逐项打断，更不能以部分正式采用替代集中交互。

### Solution

沿现有知识核心增加原生只读 MySQL 连接、目录及分片观测存储、来源暂存/激活契约；复用现有发现/计划/预检/批准/构建和身份决定原语，新增跨阶段决定包及恢复回执。新来源是 table，不伪装 CSV，不引入 Parquet 或旧 SQLite。权限保持 admin 发布、editor 可写，后续细权限独立建设。

### Implementation Decisions

- 当前首批纵向交付 P0/M1/H1，保留后续领域、持续调度及部署工作包的明确依赖；每步实际结果记入实施记录，不将完整路线图一次标 Completed。
- 连接仅允许 admin 管理，凭据通过已有 CredentialVault 加密存储，公开接口不返回凭据。
- 表资产具有稳定 source 身份、元数据和记录主键。观测批次与不可变记录/分页内容分开保存，不整表嵌入 source_versions.content。
- 有完整稳定键和 InnoDB 一致读时执行读取；精确十进制、大整数和日期保留来源表示，异常日期不猜值。失败/超限批次不激活、不做删除判断。
- 候选暂存不立刻 retire 旧来源声明；新计划构建成功时按来源事务替代旧贡献并激活。旧操作语义保持兼容。
- 决定包复用本体 review、decideIdentityBatch、eventHash、obsolete 与签名校验；整定义编辑使旧计划整体失效。
- 发布/批准/构建步骤分别持久化回执。查询不能在新定义与旧声明不兼容时静默解释。

### Testing Decisions

沿用户已批准的领域 API、HTTP、对象/证据公共结果验证。原生 MySQL 读取用独立临时库，平台持久化用独立 PostgreSQL，模型为确定性夹具。测试不加载真实模型配置、不触碰企业库。按切片先失败后实现，不在每个微小改动后运行全量或付费链路。
