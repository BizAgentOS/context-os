## 1. 产品定义

### 1.1 一句话

**ADE 把企业不同来源的数据自动整理成一份可查证、可修订、有版本的业务本体，让人和 Agent 通过同一个 Agent 修改它、用它回答业务问题，并把确认后的版本交给外部 Agent 使用。**【已定】

### 1.2 目标用户

| 用户 | 第一阶段地位 | 要完成的事 |
|---|---|---|
| 数据维护者 | 核心用户 | 接入来源，让本体正确、完整、可发布 |
| 业务使用者 | 通过问答参与 | 问跨系统的业务问题，确认答案可信 |
| 外部 Agent 及其开发者 | 消费者 | 在获准范围内稳定读取企业对象与关系 |

第一阶段为本地单企业、单管理员。暂无指定的首批客户或行业；验证样本为星桥（研发管理）及一个独立留出样本。【已定】

### 1.3 产品闭环

```
接入数据 → 程序生成本体初稿 → 问答验证
    ↑                            ↓ 答不出 / 答错
消费反馈 ← 外部 Agent 消费 ← 发布 ← 构建修复并采用
```

闭环的关键环节是"问答发现缺口 → 构建修复 → 回到问答确认"。

### 1.4 成功指标

| 指标 | 含义 |
|---|---|
| 首个正确答案时间 | 接入一批新数据后，多久能正确回答第一个跨源问题 |
| 业务问题准确率 | 固定问题上的漏连、误连、误合并、错误版本 |
| 人工介入量 | 从初稿到可发布，需要人决定的次数与时间 |
| 可解释率 | 答案是否都说明依据、版本与覆盖；答不了时是否说明原因 |

不以功能数量、图节点数、工具调用成功率或回归测试数量代替上述指标。

### 1.5 差异化

| | Fabric IQ | ADE |
|---|---|---|
| 适合谁 | 已在微软生态、已有 Power BI 语义模型 | 来源异构、没有现成语义模型 |
| 本体怎么来 | 定义优先 | 发现优先：程序生成初稿，人和 Agent 修正 |
| 事实依据 | 源端查询结果 | 逐属性依据，冲突与未知分开保留 |
| 版本 | 本体定义版本 | 本体 + 绑定 + 数据快照一起固定，可复现 |
| Agent | 编辑与问答分在不同入口 | 同一 Agent、两种模式，问答可直接转修复，答案驱动可视化 |

### 1.6 第一阶段明确不做

继承与命名空间、OWL 推理、图数据库、任意 SQL 对外开放、源系统写回与自动执行业务动作、多租户、SSO、行级权限、公网部署、计费。【已定】

## 2. 设计原则

以下原则约束所有模块；开发中遇到本文没有覆盖的情况，按这些原则判断。

1. **用户只需要理解少数概念**：来源、本体（实体、属性、关系）、待处理、工作版、发布、接入方、会话、模式。其他内部概念不出现在主界面。
2. **程序发现、人和 Agent 修正、确定性服务复验、人决定结构**：Agent 可以提议任何结构变化，不能自己采用。
3. **一个 Agent、两种模式**：模式决定工具、数据视图和写权限；页面只决定默认值和焦点。
4. **所有变化进入同一个待处理队列**：一个审阅界面、一个采用动作。
5. **读取默认用已采用快照**：实时读取是显式选择，并在结果中标明（ADR-004）。
6. **每个结果都可解释**：依据、版本、数据截至时间、覆盖；答不出时说明原因类别。
7. **界面不暴露实现**：不显示原始 JSON、UUID、内部字段名、组件名（如 KodaX、SKILL.md）；这些只在开发者视图中出现。
8. **同一信息只有一个来源**：计数、状态、来源列表由服务端投影给出，三页共用，前端不自行统计。
9. **回执决定完成**：保存、采用、失败、部分完成都以服务回执为准，不以模型的结束语为准。
10. **长期成果独立于对话**：本体、变更、缺口单、决定、会话历史都长期保存；喂给模型的上下文另行裁剪。

## 3. 信息架构

### 3.1 用户可见概念

| 概念 | 含义 | 出现位置 |
|---|---|---|
| 来源 | 一个表格文件、文档、数据库表或接口 | 数据页 |
| 实体 | 一类业务对象（如任务、人员） | 本体页 |
| 属性 | 实体的一项特征（如状态、负责人） | 本体页详情 |
| 关系 | 两类实体之间的业务连接（如任务的负责人） | 本体页 |
| 对象 | 实体的一条具体记录（如任务 FP-TASK-3203） | 本体页详情、问答 |
| 待处理 | 需要人决定或处理的事项 | 全局角标、本体页队列 |
| 工作版 | 当前已采用的本体与数据组合，带版本号 | 本体页、发布页 |
| 发布 | 固定下来交给外部使用的工作版 | 发布页 |
| 接入方 | 获准读取某个发布的外部 Agent 或应用 | 发布页 |
| 会话 | 与 Agent 的一组对话 | Agent 面板 |
| 模式 | 构建或问答 | Agent 面板 |

**不再出现在主界面的内部概念**：基础定义、执行子集、执行模型、映射版本、附来源、身份键、快照 ID、能力（capability）、artifact、foundation、program、interpretation、bound/unbound、on_demand_not_atomic。需要时在详情的"技术信息"折叠区或开发者视图中出现。【默认】

## 4. 全局交互

### 4.1 Agent 面板

**目标**：三页共用一个 Agent 面板，用户随时知道 Agent 处于什么模式、读哪份数据、正在做什么、做完改了什么、需要自己决定什么。

**现状**：三页输入框外观和位置不同；对话记录只有系统流水，没有角色和时间；离开对象后旧引用仍挂在输入框；"继续提问"与发送按钮含义不清；超过 12 条消息被物理删除；每页一个会话。

**设计**

面板结构（展开状态）：

```
┌ Agent 面板 ─────────────────────────────┐
│ 会话：星桥关系核对 ▾        [新会话] [×] │
│─────────────────────────────────────────│
│ 消息流                                   │
│  · 用户消息                              │
│  · 执行卡（运行中 / 完成 / 停止 / 失败）   │
│  · 回答卡 / 变更清单 / 决定卡 / 缺口卡     │
│  · 系统事件（折叠显示）                   │
│─────────────────────────────────────────│
│ [构建 | 问答]   数据视图：工作版 v23 ▾    │
│ 引用：[任务 ×] [负责人关系 ×]             │
│ ┌─────────────────────────────────┐     │
│ │ 输入…                       [发送]│     │
│ └─────────────────────────────────┘     │
│ 运行中时 [发送] 变为 [停止]               │
└─────────────────────────────────────────┘
```

- **位置**：桌面固定在右侧，可收起为右下角按钮；收起时如有运行中任务或待决定项，按钮上显示状态点。窄屏为底部抽屉。三页一致。【默认】
- **模式切换**：输入框上方两段切换"构建 | 问答"。当前模式在每条用户消息上以小标签显示。
- **数据视图**：仅问答模式显示，选项为"工作版 vN（默认）/ 某个发布 / 某个发布 + 某个接入方范围"。
- **引用**：显示为可移除的标签。来源两种：用户点"引用到对话"；当前在详情侧栏中浏览的对象（以"当前浏览"样式区分）。用户切换浏览对象时，"当前浏览"引用跟随更新；明确引用的标签保持不变直到用户移除。发送时冻结。
- **按钮**：只保留一个主按钮，空闲时为"发送"，运行中为"停止"。删除"继续提问"。
- **会话**：顶部会话选择器，可新建、重命名、切换会话；会话不按页面拆分。【已定 R1】

**规则**

- 切换页面不切换会话、不停止运行。
- 切换模式不停止正在运行的任务；新消息按单运行规则先停止当前交互运行（见 8.6）。
- 模式由用户切换；Agent 只能通过"建议切换卡"建议。

**完成标准**

- 三页面板外观、位置、行为一致。
- 任意时刻能从面板看出：当前会话、模式、数据视图、已挂引用、是否运行中。
- 浏览其他对象后，"当前浏览"引用随之更新，明确引用不受影响。

### 4.2 消息类型

**目标**：用结构化卡片替代纯文本，让过程、结果、变化、决定各有固定呈现。

**现状**：只渲染用户和助手两类文本；中间文字先显示后消失；候选以"「标题」vN（id 前 8 位）"附在结尾；查询兜底输出 JSON；不渲染 Markdown；需要用户决定时只是一句话；存在"采用这版"等固定口令。

**设计**

| 消息类型 | 何时出现 | 内容 | 操作 |
|---|---|---|---|
| 用户消息 | 用户发送 | 文本、模式标签、引用标签 | — |
| 执行卡 | 每次运行 | 步骤列表（见下）、状态、耗时、成本 | 停止、展开步骤、继续（停止后） |
| 回答卡 | 问答模式回答 | 结论、依据、回执、限制（见 8.3） | 展开依据、在图中查看、复制 |
| 变更清单 | 运行中产生或修改了变更 | 每项：对象、变化摘要、复验结果、状态 | 查看差异、去待处理队列 |
| 决定卡 | Agent 需要用户决定 | 问题、原因、选项、影响摘要 | 采用 / 拒绝 / 查看详情 / 稍后 |
| 缺口卡 | 问答答不出 | 原因类别、涉及对象、数据观察 | 转到构建模式修复、标记不需要修复 |
| 建议切换卡 | 用户意图属于另一模式 | 一句说明 | 切换并带上当前问题、忽略 |
| 系统事件 | 后台任务完成、版本变化等 | 一行说明与时间 | 查看 |

**执行卡步骤**：每一步一行中文摘要，类型为"读取 / 查询 / 检查 / 提议 / 保存 / 等待决定"，例如：

```
✓ 读取 任务、账号 两个实体的定义
✓ 查询 Task.assignee 与 User.username 的匹配情况：10/10
✓ 提议 新关系「任务 → 负责人 → 账号」
✓ 复验 匹配率 100%，目标唯一，N:1
… 等待你决定
```

模型的中间文字默认折叠在步骤下，不作为最终答案显示。

**规则**

- 所有卡片内容由服务回执生成；模型只能生成结论和说明文字，不能生成依据、版本、复验数字。
- 正文支持安全 Markdown（标题、列表、表格、加粗、代码）；查询结果以表格呈现。
- 不出现 UUID 和内部字段名；对象以"实体名 · 对象名"显示，可点击跳转。
- **删除固定口令采用**【已定】：采用只能通过决定卡、待处理队列或详情中的按钮完成。
- 决定卡在本体页同步高亮对应对象和待处理项。
- 决定卡、缺口卡、建议切换卡共用同一个"决策组件"。

**完成标准**

- 一次运行中，用户能实时看到步骤推进；运行结束后能看到本轮改了什么、哪些等自己决定。
- 对话中不出现原始 JSON、UUID。
- 不存在任何通过自由文本触发采用的路径。

### 4.3 待处理中心

**目标**：所有需要人处理的事项集中在一个队列，计数全产品一致，每项都有明确动作。

**现状**：采用入口分散在七处；待核对项在概念卡上只有文字没有按钮；同一张卡上计数不一致（"2 待核对"与"10 项未知 / 8 项冲突"）；18 项待核对首屏看不到。

**设计**

待处理项分五类：

| 类别 | 来源 | 示例 | 主要动作 |
|---|---|---|---|
| 结构变更 | 程序、人、Agent 的提议 | 新关系「任务 → 负责人 → 账号」 | 采用、拒绝、让助手分析 |
| 命名 | 首次构建后的批量命名、单项改名 | 把 Task 改名为"任务" | 全部采用、逐项修改后采用、拒绝 |
| 待裁决 | 文档与数据之间、文档之间的冲突与未知 | 产品负责人：文档写陈曦，数据写 lin.yue | 选择一方、保留分歧、补充说明 |
| 缺口 | 问答答不出时创建 | "任务负责人无法回答：关系未绑定" | 转到构建修复、标记不需要修复 |
| 数据问题 | 快照质量熔断、结构变化 | tasks.csv 新版本行数下降 90% | 确认新快照、保留旧快照、查看差异 |

每项包含：标题（业务语言）、类别、来源（程序 / 人 / Agent / 问答）、涉及对象、依据摘要、复验结果（如有）、创建时间、状态。

**位置**：

- 顶栏"待处理(N)"角标，点击打开本体页并展开队列。
- 本体页右侧队列抽屉（见 6.6）。
- 图上相关节点和关系显示待处理标记。

**规则**

- N 由服务端统一计算：所有状态为待处理的项之和。前端不自行统计。
- 采用一项或一批项形成一个新工作版（见 10.3）。
- 拒绝必须记录理由（可选预设理由）；被拒绝的程序提议不再重复出现（见 10.2）。
- "让助手分析"：切到构建模式，新消息自动引用该项。

**完成标准**

- 全产品只有一个采用动作入口体系；同一时刻各处显示的待处理数一致。
- 任意待处理项都能在两次点击内被采用、拒绝或交给助手。

### 4.4 后台任务中心

**目标**：同步、构建、文档处理、外部委托等后台工作有统一可见的位置，标题能区分，失败可重试。

**现状**：右下角任务卡常驻并在窄屏压住内容；任务面板 10 个相同标签"程序构建的数据底座"；构建记录 17 条同名。

**设计**

- 顶栏"任务"按钮，运行中显示数量；点击打开任务抽屉，取代右下角常驻任务卡。
- 每个任务的标题描述"触发原因 + 动作"，例如"tasks.csv 更新后重新绑定""接入 5 份文档并补充说明""外部接入方 A 的委托：查询逾期任务"。
- 每个任务显示：状态（排队 / 运行 / 完成 / 失败 / 已停止）、开始与结束时间、产出（链接到变更或版本）、失败原因、重试按钮。
- 任务列表保留最近 50 条，更早的进入历史。【默认】

**完成标准**

- 不存在两个标题相同且无法区分的任务。
- 失败任务都能看到原因并可重试。

### 4.5 设置

| 分组 | 内容 |
|---|---|
| 模型 | 提供方、模型、密钥（加密保存）、连通性测试 |
| 成本 | 本日 / 本月用量与费用估算；每轮与每日上限；超限行为（停止并提示） |
| 凭据 | 来源凭据列表（不显示明文）、更新、删除 |
| 数据保留 | 快照保留策略、来源原文保留期 |

## 5. 数据页

### 5.1 目标

用户在这里接入来源、看清每个来源的状态和数据新鲜度、处理数据问题。每个来源只有一个主动作，高级设置收起。

### 5.2 现状

- 三页来源数量不一致（13 / 8 / 1）；CSV 被归为"HTTP API · 按需读取"；文档在数据页显示"尚未同步快照"，在本体页显示"已补充 5/5"；飞书被归在 MCP 下。

│ 13 个来源 · 12 个可用 · 1 个需要处理      [+ 添加来源]        │

│  │ 数据截至 10-18 │ │ 数据截至 10-18 │ │               │         │

**来源分类**：按用户理解分三类，不按传输协议。【默认】

| 类别 | 包含 |
|---|---|
| 表格 | CSV、Excel、飞书多维表格、数据库表、返回记录列表的接口 |
| 文档 | Markdown、TXT、PDF、DOCX、飞书文档与知识库 |
| 指标 | BI 指标来源（第二阶段与指标引用一并展开） |

接口和数据库以"连接"形式添加，连接下的每张表或每个记录接口作为一个表格来源显示。

**来源状态**：三档，由服务端统一给出。

| 状态 | 表格来源含义 | 文档来源含义 |
|---|---|---|
| 可用 | 已同步，尚未进入本体（如被跳过的中间表） | 已读取，尚未用于本体 |
| 已进入本体 | 已绑定到某个实体 | 已用于实体或关系说明 |
| 需要处理 | 同步失败、数据问题待确认、结构变化待确认、凭据失效 | 读取失败、格式不支持 |

每张卡片显示：名称、状态、规模（行数 / 段落数）、对应实体或用途、数据截至时间。

**来源详情**（点击卡片打开右侧详情）：

| 分区 | 内容 |
|---|---|
| 概览 | 状态、对应实体、数据截至、刷新周期、最近同步结果 |
| 字段与样本 | 一步可见：字段列表（名称、类型、不同值、空值、示例）+ 前 20 行样本 |
| 同步历史 | 最近版本列表：时间、行数、变化摘要（新增 / 删除 / 修改行数）、质量提示 |
| 问题 | 当前数据问题与结构变化，链接到待处理 |
| 高级（折叠） | 读取方式（快照 / 实时）、刷新周期、增量字段、快照保留、删除来源 |

**主动作**：

| 场景 | 主按钮 |
|---|---|
| 新添加的来源 | "接入并构建"：同步 → 构建 → 结果进入工作版或待处理 |
| 已进入本体的来源 | "立即同步" |
| 需要处理 | "查看问题" |

删除来源移到"高级"，需要二次确认并说明对本体与发布的影响。

**Agent 在数据页**：默认构建模式；常见用途是解释同步失败、分析字段含义、建议接入方式。

### 5.4 规则

- 数据页、本体页、发布页显示的来源数量和状态来自同一服务投影。
- 正常信息不使用错误样式；危险操作不与只读操作并排。
- 企业资料从数据页移到设置；首次引导中可选填写。

### 5.5 完成标准

- 三页来源数量一致；用户能在一屏内看出哪些来源可用、哪些需要处理、数据截至何时。
- 打开来源详情即可看到字段和样本。
- 每个来源卡片只有一个主按钮。

| 编辑内容 | 结果 |

| 名称、别名、说明 | 直接保存为一项命名 / 说明变更，自动采用（普通操作，不影响执行）【默认】 |

| 对象值纠正 | 生成局部纠正变更，进入待处理队列；采用后进入工作版和后续发布 |

- 批量操作：同一类别可多选后批量采用或拒绝。
- 选中某项时，图上高亮相关实体和关系。

### 6.8 完成标准

- 首屏能看到待处理数量和一句下一步提示。
- 本体页不再有"本体定义 / 实际对象 / 构建与修订 / 共同取证"四个弹窗入口，全部内容可在详情侧栏或待处理队列中完成。
- 实体、关系、对象详情中不出现原始 JSON 和 UUID；对象的每个属性值能看到具体来源记录；引用值可点击。
- 每个待处理项都有可执行的动作。
- 图例与图上编码一致；窄屏可通过列表完成全部操作。

## 7. 发布与接入页

### 7.1 目标

用户在这里把工作版发布为固定版本、管理接入方、在发布前以消费者视角试问。对外只有一条路径。【已定 R7】

### 7.2 现状

- 有两条对外开放的路：发布版本 + 接入方；"旧版 MCP 数据集与访问范围"可绕过发布直接创建数据集。后端 v1—v4 四代接口并存。

- 差异视图"8 项待发布变更"实为 8 个类别，单元格塞入长说明。

### 7.3 设计

```
┌ 发布与接入 ──────────────────────────────────────────────────┐
│ ┌ 当前发布 ──────────────┐  ┌ 工作版 v23 ───────────────────┐ │
│ │ 发布 v3 · 10-18 发布    │  │ 相比发布 v3：                  │ │
│ │ 2 个接入方在使用        │  │ 新增 1 关系 · 修改 2 实体说明   │ │
│ │                        │  │ 数据：3 个来源有新快照          │ │
│ │                        │  │ 待处理 2 项（不阻塞发布）       │ │
│ │                        │  │ [查看差异]  [检查并发布]        │ │
│ └────────────────────────┘  └───────────────────────────────┘ │
│ 接入方（2）                                    [+ 新建接入方]  │
│  · 研发助手 · 使用发布 v3 · 可升级到 v4 · 最近调用 10-19        │

│ 历史接入（只读，折叠）                                          │
└───────────────────────────────────────────────────────────────┘
```

#### 7.3.1 差异视图

按"本体变化"和"数据变化"两部分列出：

- 本体变化：每行一个对象，标"新增 / 修改 / 弃用"，一句摘要（如"新增关系 任务 → 负责人 → 账号"），可展开前后对比。
- 数据变化：每个来源一行，显示新增 / 删除 / 修改行数，可展开看行级差异。

#### 7.3.2 检查并发布

检查项：

| 检查 | 结果处理 |
|---|---|
| 工作版是否有待采用的结构变更 | 不阻塞；提示"以下变更不会包含在本次发布中" |
| 数据问题待确认 | 阻塞：涉及来源的新快照未确认时，提示先处理或以旧快照发布 |
| 每个实体与关系的执行检查 | 失败项阻塞 |
| 未裁决冲突 | 不阻塞；在发布说明中列出 |

检查通过后填写发布说明（可由 Agent 起草），确认发布。发布固定：语义版本、绑定版本、身份决定集、快照集（见 10.3）。

#### 7.3.3 接入方

新建接入方流程：

1. 名称与用途。
2. 选择发布版本。
3. 选择范围：实体（勾选）、每个实体的属性（默认全选可取消）、关系（两端都开放时可选）、是否开放依据。
4. 是否允许委托 Agent 调查（默认关闭）。
5. 生成配置：MCP stdio 配置与 HTTP 说明，密钥只显示一次。
6. 测试：真实握手、工具发现、一次查询。

接入方详情：范围、使用版本、调用统计、最近错误、升级、撤销。

**升级**：显示当前版本与目标版本的差异，以及该接入方范围内受影响的部分；确认后签发新密钥，旧密钥原子撤销（沿用现有机制）。

#### 7.3.4 以消费者视角试问

接入方详情中提供"以此接入方试问"：打开 Agent 面板，切换到问答模式，数据视图设为"该发布 + 该接入方范围"。

#### 7.3.5 历史接入

v1/v2/v3 消费者与旧数据集工作台移入"历史接入"折叠区：只读查看、可撤销，不能新建或修改（FEATURE_039）。接口移除在 FEATURE_067 中进行，移除时间需用户确认。

### 7.4 规则

- 发布页主按钮：工作版有可发布内容时为"检查并发布"；无变化时为"查看当前发布"。
- 本页 Agent 只能对新路径提出接入草稿（范围建议），不能创建旧版数据集。
- 已发布版本不可修改；撤销接入方立即生效。

### 7.5 完成标准

- 对外开放只有"发布 + 接入方"一条路径；旧路径只读。
- 差异视图按对象列出具体变化。
- 能以任一接入方的范围在 ADE 内试问，结果与外部调用一致。

## 8. Agent

### 8.1 目标

一个 Agent、两种模式；用户能看到过程、结果和需要自己决定的事；成本可控；不被后台任务阻塞。【已定 D1、D5、R1、R8】

### 8.2 模式合同

| 项 | 构建模式 | 问答模式 |
|---|---|---|
| 目的 | 让本体变对 | 用本体回答业务问题 |
| 数据视图 | 工作版快照、原始来源、待处理变更；可显式实时读取 | 工作版（默认）/ 某发布 / 某发布 + 接入方范围 |
| 写权限 | 提议变更、触发复验与预览、编辑名称说明 | 只能创建缺口单 |
| 输出 | 变更清单、复验结果、决定卡 | 回答卡、缺口卡 |
| 页面默认 | 数据页 | 本体页、发布页（发布页预选当前发布） |

本体页默认模式定为问答，引导"先问、发现问题、再修"。【默认，取代双模式草稿中的开放问题 1】

### 8.3 问答模式

#### 8.3.1 工具

| 工具 | 作用 | 由现有能力演进 |
|---|---|---|
| `ontology_describe` | 有界读取视图内的实体、属性、关系目录 | `ontology_outline`、`describe_dataset` |
| `ontology_search` | 按名称、别名、说明检索 | 新增 |
| `objects_query` | 按类型、身份、属性过滤、排序读取对象 | `live_query`、`query_objects` |
| `relations_traverse` | 沿关系前进或回溯，最多 3 跳；自引用路径最多 10 层 | `query_relations` + 新增 |
| `objects_aggregate` | 计数、求和、平均、极值，按属性分组 | 新增 |
| `evidence_read` | 读取结果中的依据引用 | `evidence_read`、`read_evidence` |
| `knowledge_query` | 读取已用于本体的文档片段 | `knowledge_query` |
| `gap_report` | 创建缺口单 | 新增 |

#### 8.3.2 回答卡

| 部分 | 内容 | 生成方式 |
|---|---|---|
| 结论 | 直接回答 | 模型 |
| 依据 | 涉及对象与关系，可展开到属性级来源 | 服务回执 |
| 回执 | 数据视图、版本、数据截至、覆盖与截断 | 服务回执 |
| 限制 | 冲突、未知、未覆盖；多源时说明"各来源数据截至时间不同" | 服务回执 + 模型说明 |

#### 8.3.3 答案联动可视化

| 回答类型 | 本体图 | 详情侧栏 |
|---|---|---|
| 多跳答案 | 高亮路径，其余淡出 | 逐跳展示具体对象 |
| 列表 / 过滤 | 聚焦相关实体 | 数据分区显示结果，过滤条件一致 |
| 聚合 | 聚焦被聚合实体 | 分组结果，可点开明细 |
| 答不出 | 缺失关系以红色虚线标出 | 缺口卡与数据观察 |

联动只展示回执已有内容，不发起额外查询；用户点击回答卡上的"在图中查看"触发，或在本体页时自动触发。【默认】

#### 8.3.4 答不出时

| 原因 | 行为 |
|---|---|
| 无此关系类型 / 有类型未绑定 / 有绑定未匹配 / 身份未对应 | 说明原因，创建缺口单，显示缺口卡 |
| 覆盖不足 | 说明截断范围，不创建缺口单 |
| 真实为空 | 回答"没有"，附覆盖说明 |
| 超出本体范围 | 说明本体覆盖范围，询问是否需要建模 |

#### 8.3.5 预算

每轮最多 24 次读取、512 KiB 工具结果、每次最多 20 个对象（聚合不受对象数限制，受分组数限制 1000）。超过时交付已得到的部分并说明。

### 8.4 构建模式

#### 8.4.1 工具分组

| 组 | 工具 | 由现有能力演进 |
|---|---|---|

| 复验 | `change_verify` | `engine_check`、`ontology_verify`、`ontology_snapshot_check` |
| 预览 | `change_preview_query`：用变更重放一个查询，比较前后 | 新增（基于 `ontology_preview`） |
| 待处理 | `pending_list`、`pending_read` | 合并 `mapping_change_list/read`、`relation_correction_list/read` |
| 来源 | `data_sync`、`source_catalog`、文档读取工具 | 保留 |

#### 8.4.2 写权限

| 操作 | Agent 能否直接完成 |
|---|---|
| 名称、别名、说明 | 能 |
| 结构变化 | 能提议（必须附业务依据），不能采用 |
| 触发复验、预览、同步 | 能 |
| 身份决定 | 能提议，由人决定 |
| 撤回自己提出的变更 | 能 |
| 拒绝程序或他人的变更 | 不能 |

### 8.5 缺口单交接

**缺口单字段**：问题原文、实际执行的语义查询（可重放）、当时回执、原因类别、涉及对象、数据观察、状态、关联变更。

**状态**：

```
open → in_fix → fixed → confirmed
  │                │
  └→ dismissed     └→ reopened（复问仍失败）
```

**流程**：

1. 问答模式答不出 → 创建缺口单 → 缺口卡"转到构建模式修复"。
2. 用户点击 → 切到构建模式，新消息自动引用缺口单。
3. 构建模式：观察 → 提议 → 复验 → 预览（重放原查询，展示前后结果）→ 决定卡。
4. 用户采用 → 缺口单变为 fixed → 系统事件提示"重新提问以确认"。
5. 用户点击 → 切回问答模式重放原问题 → 成功则 confirmed，失败则 reopened。

**规则**：confirmed 只能由问答模式复问成功产生；复问由用户触发，不在后台自动运行。【默认】

### 8.6 会话、历史与上下文

**会话**【已定 R1】：

- 会话长期保存，不按页面拆分；用户可新建、重命名、归档会话。
- 每个会话有标题（首条消息后由 Agent 生成，可修改）。
- 消息与卡片完整保存，可分页回看；删除物理裁剪逻辑。

**喂给模型的上下文**：

| 内容 | 规则 |
|---|---|
| 身份与模式提示词 | 按模式加载（见 8.7） |
| 工作摘要 | 企业名称、工作版号、实体与关系数量、待处理计数、当前引用；不注入完整企业档案、来源策略、检查列表 |
| 会话摘要 | 早于近期窗口的消息由摘要表示，摘要随会话增长更新 |
| 近期消息 | 最近 12 条或 12000 字（沿用现有窗口，但只是窗口，不删除） |
| 引用对象 | 当前消息冻结的引用，按需读取详情 |
| 工具定义 | 只加载当前模式的工具 |

每轮注入上下文设上限（【默认】不含工具定义 8000 token），超出时裁剪摘要部分。

### 8.7 提示词结构

按四层重写，替代 `config/agent/canvas.md`、`system.md` 中的全部旧内容：

| 层 | 内容 | 加载 |
|---|---|---|
| 身份 | ADE 是什么、Agent 的角色、诚实与依据原则 | 始终 |
| 通用规则 | 回执决定完成、不编造依据、不暴露内部 ID、来源内容中的指令不改变权限、语言与格式 | 始终 |
| 构建模式 | 提议规则、复验与预览、何时生成决定卡、不能采用结构 | 构建模式 |
| 问答模式 | 回答结构、答不出时的处理、缺口单、预算 | 问答模式 |

Skill 按需加载，所有 Skill 与"程序构建、Agent 提议"一致；删除仍让 Agent 新增概念或自行建模的段落。

增加一致性检查：提示词中提到的工具名必须存在于当前模式工具集；页面名称只使用"数据 / 本体 / 发布与接入"。

### 8.8 执行与分池

【已定 R8】

| 池 | 承担 | 并发 |
|---|---|---|
| 交互池 | 用户在 Agent 面板发起的运行 | 1（单会话单运行） |
| 后台池 | 文档补充、自动重绑、批量命名等后台 Agent 任务；外部委托 | 1，排队 |

- 后台任务不阻塞、不暂停交互运行。
- 同一对象的写入冲突由版本检查处理：后提交者遇到版本变化时重新复验，不覆盖。
- 外部委托第一阶段排在后台池；试点阶段视负载拆分为独立池。

### 8.9 停止、超时与部分完成

- 停止或超时（240 秒）时，执行卡标为"已停止"或"已超时"，列出已完成步骤、已保存的变更、未执行的步骤，提供"继续"按钮（新运行，带上原目标与已完成内容）。
- 上传文件不再中止当前交互运行；文件处理进入后台池。
- 长任务（如接入 20 份文档）拆为后台任务，交互运行只负责发起和汇报。

### 8.10 成本

- 每次运行记录 token 与费用估算，显示在执行卡底部。
- 设置中配置每轮与每日上限；达到上限时停止运行并显示原因。

### 8.11 完成标准

- 本体页默认问答模式；切换模式后工具集、数据视图随之变化。
- 问答模式在任何情况下都不能产生本体或治理写入（缺口单除外）。
- 缺口单流程可完整走通到 confirmed。
- 会话历史不再被删除；早期内容可回看。
- 后台文档处理期间，用户可以正常对话。
- 每次运行都显示成本。

## 9. 本体与语义模型

### 9.1 目标

本体成为显式的分层模型，用户看得见、改得动；程序、人、Agent 通过同一流程修改结构。【已定 D3、D4】详细字段见[语义模型规格](</Users/samharadelijiang/Documents/ChatGPT/agent data engine/analysis/ade-semantic-model-spec-draft-2026-10-19.md>)，本章列出要点与本文新增内容。

### 9.2 分层

| 层 | 对象 |
|---|---|
| 语义层 | 实体类型（名称、别名、说明、身份键、kind）、属性（值类型、单位、枚举、是否身份）、关系类型（端点、方向、基数、可自引用、可声明无环）、指标引用（第二阶段） |
| 绑定层 | 实体绑定（主 / 补充、数据集、键列、行过滤）、属性绑定（可多源，有限转换）、关系绑定（外键 / 映射表）、身份规则（same_as / belongs_to）、身份决定（match / no_match） |
| 数据层 | 各来源快照；显式实时读取 |
| 查询层 | 由语义层编译的有界查询，见第 12 章 |

### 9.3 本文新增的模型扩展

| 扩展 | 设计 | 来源 |
|---|---|---|
| 复合身份 | 实体的身份键允许多个属性组合（如单号 + 行号） | 体检 D7 |
| 中间表 | 只有两个外键列（及少量描述列）的表识别为多对多关系，以 `link_table` 绑定 | 体检 D7 |
| 大表与活动流 | 程序判断为活动流时不再静默降级，生成一项待处理"确认为活动记录"；用户确认前按普通实体处理 | 体检 D7 |
| 批量命名 | 首次构建完成后，后台池运行一次命名任务，由 Agent 为全部实体、属性、关系提出中文名称、别名与说明，作为一项"命名"待处理；用户可全部采用或逐项修改【已定 R4】 | 体检 B4 |

### 9.4 文档在本体中的位置

【默认，补齐讨论中未展开的部分】

- 文档**不产生结构**：不新建实体、属性、关系。
- 文档用于三件事：
  1. 补充实体、属性、关系的说明与别名（以命名 / 说明变更进入，普通操作自动采用）。
  2. 发现文档与数据、文档与文档之间的冲突和未知，进入"待裁决"。
  3. 在问答模式中作为可检索的知识，回答"口径是什么""为什么"类问题。
- 同一批上传的文档合并处理，产生一个工作版，不再每份文档一个版本。
- 依据外置为证据库，不计入本体定义体积；取消"200 条依据、100 项未知与冲突"的整体拒绝上限，改为待裁决队列分页。

### 9.5 指标在本体中的位置

第二阶段展开。方向：现有 MetricReader 定义挂到实体上（指标 → 实体，维度 → 属性），问答模式可回答"某产品的需求数趋势"类问题；源不支持历史口径时不承诺重算。

### 9.6 完成标准

- 本体页中每个实体、属性、关系都有稳定身份、业务名称和说明，可直接查看其数据来源。
- 星桥样本中：唯一外键、负责人字段、自引用关系可经提议、复验、采用进入本体；人员与账号以 belongs_to 对应，机器人账号以 no_match 排除。
- 上传 20 份文档不会因依据或冲突数量被整体拒绝，只产生一个新工作版。

## 10. 变更、采用与版本

### 10.1 目标

一条变更流程、一个待处理队列、两个用户可见版本概念（工作版、发布）。

### 10.2 变更状态

```
proposed → verified → adopted → deprecated / superseded
    │          │
    └→ failed  └→ rejected
```

| 字段 | 说明 |
|---|---|
| 来源 | 程序 / 人 / Agent / 问答（缺口单派生） |
| 类型 | 实体、属性、关系、绑定、身份规则、身份决定、命名、说明、局部纠正、弃用、数据问题确认 |
| 依据 | Agent 提议必填；程序提议为规则名与数据特征 |
| 复验结果 | 各项指标、通过 / 待审 / 失败 |
| 影响 | 涉及实体、关系、对象数量；是否影响已发布版本 |

**被拒绝的程序提议**：同端点、同列、同方式的候选不再重复提出，除非数据匹配特征发生实质变化（【默认】匹配率变化超过 20 个百分点或目标唯一性改变）。

### 10.3 自动采用规则

【已定 R2】

| 场景 | 是否自动采用 |
|---|---|
| 首次构建（工作区还没有已采用的本体） | 是：检查全部通过的实体、关系、绑定自动采用；未通过或拿不准的进入待处理 |
| 后续数据同步，结构不变，只需重新绑定 | 是：同结构重绑 |
| 后续数据同步，程序发现新关系、新合并、实体降级 | 否：进入待处理 |
| 名称、别名、说明变更 | 是（普通操作） |
| 人在界面上提出的结构变更 | 否：复验后由本人在待处理中采用（可在提交时选择"复验通过后立即采用"）【默认】 |
| Agent 提出的结构变更 | 否 |
| 数据问题（熔断） | 否 |

### 10.4 版本

| 版本 | 用户可见 | 何时递增 |
|---|---|---|
| 工作版 vN | 是 | 每次采用（单项或一批）形成一个新工作版 |
| 发布 vN | 是 | 每次发布 |
| 语义版本、绑定版本、身份决定集、快照集 | 否（详情技术信息中可见） | 各自内容变化时 |

- 工作版 = 语义版本 + 绑定版本 + 身份决定集 + 快照集 的一个组合。
- 发布 = 固定一个工作版。
- 绑定引用语义对象的稳定 ID，不引用语义版本号，措辞变化不触发重绑。
- 历史工作版可只读查看；支持"以某历史工作版为基础恢复"，作为一项变更进入待处理。【默认】

### 10.5 治理决定进入发布

所有已采用的变更（包括局部纠正、身份决定）进入工作版，并在下一次发布中生效、参与发布差异。不再存在只在工作区生效的修订。

### 10.6 完成标准

- 用户在任何界面只看到"工作版"和"发布"两种版本号。
- 数据同步后，新出现的关系或合并不会在无人审阅时进入工作版。
- 局部纠正采用并发布后，外部接入方读到纠正后的结果。

## 11. 数据处理

### 11.1 目标

企业常见数据能接进来；数据按周期自动更新；质量异常不会静默生效。

### 11.2 连接器

【已定 R5，按顺序】

| 顺序 | 连接器 | 范围 | 关键规格【默认】 |
|---|---|---|---|
| 1 | 表格文件 | Excel（xlsx，多 sheet，每个 sheet 一个来源）、CSV（编码自动识别 UTF-8 / GBK / GB18030，分隔符识别逗号 / 制表符 / 分号） | 单文件上限 100MB；表头行识别；合并单元格展开 |
| 2 | 只读数据库 | MySQL、PostgreSQL | 选择库与表；只读账号；经 DuckDB 扫描；单表行数上限沿用快照上限 |
| 3 | API 增强 | 分页（页码、偏移、游标、Link 头）；OAuth2 客户端凭据与令牌刷新；嵌套对象展开为字段；内网 HTTP 由管理员放行 | 有限重试（3 次，指数退避）；单次响应上限提高到 20MB；超时 60 秒 |
| 4 | 飞书多维表格 | 选择多维表格与数据表，按表格来源处理 | 复用现有飞书授权 |
| 5 | PDF / DOCX | 作为文档来源 | 文本抽取；扫描件不支持并明确提示 |

出现目标客户的系统清单时，按清单调整顺序。

### 11.3 同步

【已定 R6】

| 项 | 设计【默认】 |
|---|---|
| 刷新周期 | 每个来源可设：手动 / 每小时 / 每天（指定时间）/ 每周；新来源默认每天 |
| 增量 | 来源有可靠的更新时间字段时，按该字段增量读取；否则全量 |
| 并发 | 不同来源可并行，最多 3 个同时同步；同一来源串行 |
| 断点续传 | 分页读取中断时，从最后成功页继续 |
| 重试 | 失败自动重试 3 次；仍失败标为"需要处理"，已生效快照继续服务 |
| 新鲜度 | 每个来源、每个回答显示"数据截至"时间 |

### 11.4 质量熔断

以下情况新快照**不生效**，进入"数据问题"待处理，旧快照继续服务：

| 情况 | 阈值【默认】 |
|---|---|
| 返回 0 行（上一版本非 0） | 任何时候 |
| 行数骤降 | 比上一版本减少超过 50% |
| 身份键唯一性丢失 | 出现重复 |
| 身份键空值 | 出现空值 |
| 关键字段空值率上升 | 上升超过 30 个百分点 |
| 字段结构变化 | 新增、删除、改类型（沿用现有机制） |

用户可选择"确认新快照"或"保留旧快照"，可针对来源调整阈值。

### 11.5 读取模式

按 ADR-004：工作区、问答默认读已采用快照；实时读取需显式选择并在结果中标明；发布固定快照。当前工作区查询读实时来源的偏差在第一阶段修正。【已定 D2】

### 11.6 保留与安全

- 快照保留：被发布引用的永久保留；其余每个来源保留最近 5 版（沿用）。
- 来源原文：上传文件原文保留期【默认】90 天，之后只保留快照。
- 删除来源：说明对工作版和发布的影响；被发布引用时只能停用，不能删除数据。
- 凭据：统一加密保存，优先使用系统钥匙串。

### 11.7 完成标准

- Excel 多 sheet、GBK 编码 CSV 可直接上传并构建。
- 能连接一个 MySQL 或 PostgreSQL 库并选择表接入。
- 设置每天刷新的来源会自动更新，"数据截至"时间随之变化。
- 来源返回 0 行时，旧数据继续可用，待处理中出现数据问题。

## 12. 查询层与对外接口

### 12.1 查询能力

| 能力 | 上限【默认】 |
|---|---|
| 按类型列出、按身份读取（含融合属性） | 每页 100（对外 50） |
| 属性过滤：等值、范围、包含、空值；可对融合属性过滤 | — |
| 排序 | 单个或多个属性 |
| 关系遍历（含反向） | 3 跳 |
| 自引用路径（含环检测） | 10 层 |
| 聚合：计数、求和、平均、极值，按属性分组 | 分组 1000 |

查询以语义层 ID 表达，由服务编译为快照 SQL；不开放任意 SQL。问答模式、构建模式、对外接口使用同一查询层，差别只在范围和版本。

### 12.2 查询回执

每个结果附：读取模式、工作版或发布版本、各来源数据截至时间、覆盖（命中数、截断、未覆盖属性）、多源时间说明。

### 12.3 执行资源

所有查询（包括固定快照读取）经过统一执行器：并发、排队、超时、取消。补充来源匹配改为批量匹配，不再逐对象读取。

### 12.4 对外接口

- 唯一对外合同：发布 + 接入方 + v4 HTTP / MCP。【已定 R7】
- 在现有 6 个 MCP 工具基础上增加：`traverse_relations`、`aggregate_objects`、`search_ontology`；`query_objects` 增加范围过滤与排序。
- 工具说明由执行合同生成，与实际读取模式一致。
- v1/v2/v3 冻结，见 7.3.5。

### 12.5 完成标准

- 外部 Agent 能在一次调用中得到"某版本下逾期任务数"这类聚合结果。
- 对外工具说明中的读取模式与实际回执一致。

## 14. 首次使用流程

### 14.1 目标
