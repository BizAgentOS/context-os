# v0.2.0：ADE 数据底座工作台

日期：2026-10-14。产品开发版本为 `0.2.0-dev`，未正式发布。本版本独立于数据底座在第三页发布的业务版本。

## 版本目标与授权

用户明确授权：先完成吸收 Helix 能力后的整体前后端，再找场景验证；暂不连接业务数据。ADE 为通用本体数据底座，投研仅作为后续验证场景。保留已有三页与视觉，KodaX 为唯一内部 Agent 底座。

首次流程：配置模型 → 选择来源 → 数据页接入 → 本体页自动构建/Agent 辅助修复 → 发布与接入。数据刷新、工作版修订、对外发布及消费者升级分别表达。

本轮直接完成规格、拆票、实现、测试、评审与本地提交；用户已授权整体开发，常规实现选择不重复确认。旧 v0.1.0 的状态与未完成历史保留，不以新版本掩盖旧验收缺口。

## 公共验收与边界

管理 HTTP、真实临时来源、独立消费 HTTP/MCP 与浏览器为主要验收边界。行为测试先红后绿，UI 来自实际回执。测试空间与用户空间隔离，不复制模型凭据或自动读现有业务源。

本轮不做公网部署、多租户/计费、任意源的完整语义理解、完整 OWL 或 Helix 全部连接器。只显示实际实现的存取能力；发布定义不代表冻结源数据。场景质量验证留待本轮交付后。

## 实施依赖

025、026、027、028 可以沿现有服务并行实施，027/028 与 026 联调；029 依赖 028；030 验收前述整链。功能状态只在 FEATURE_LIST.md，票勾选只在下列设计块。

## FEATURE_031: 数据快照与执行服务

### 1. 需求概述
结构化来源同步为本地不可变快照，形成数据版本线，作为全量构建、验证与发布锁定的基础。

### 2. 影响范围
新增 `src/data/`（执行器与快照服务）、`MemoryStore.createArtifact`、`/api/data*` 接口、应用装配；新增依赖 `@duckdb/node-api@1.5.5-r.1`。

### 3. 技术方案
移植 Helix 执行器：ingest/query/materialize、单条只读语句、禁外部访问、内存/超时/输出上限、最小环境子进程（2 并发、50 排队）。HTTP/MCP 记录能力分页读完（上限 `ADE_SNAPSHOT_MAX_ROWS`，默认 100 万行，超限报告不完整）；CSV 按解析后文本写入，保留编号原样。数据集 `data_dataset` 维护 active/pending/versions；快照 `data_snapshot` 以 Parquet 文件名为身份且不可变。指纹不变不新增版本；结构变化进入待确认；唯一性丢失与空值上升报告为问题。数据集可设 `snapshot`/`live`。被发布引用的快照不清理，其余保留最近 5 版。

### 4. 接口契约
`GET /api/data`、`GET /api/data/preview?datasetId&snapshotId&offset&limit`、`POST /api/data/sync`（operationId 幂等，202 返回任务）、`POST /api/data/accept`（id、version、operationId）、`POST /api/data/policy`（id、version、materialization）。

### 5. 实现步骤
- [x] T031-01（依赖：复用 010、026）：执行器移植与快照登记，公共服务行为先红后绿。
- [x] T031-02（依赖 T031-01）：结构漂移/确认、重启中断、实时策略、执行安全及应用接口装配。

### 6. 验收标准
CSV 与分页 HTTP 实际同步为快照；相同数据不新增版本，旧版本可读；结构变化待确认且不影响当前读取；多语句、写语句、外部文件读取被拒；重启将运行中的同步标为中断。

Testing Decisions：`data-snapshots.test.ts` 5 项验证上述行为，原 199 项回归通过（共 204 项），类型检查通过。

### 4. 接口契约
