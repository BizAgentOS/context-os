# v0.2.0：ADE 数据底座工作台

日期：2026-10-14。产品开发版本为 `0.2.0-dev`，未正式发布。本版本独立于数据底座在第三页发布的业务版本。

## 版本目标与授权

用户明确授权：先完成吸收 Helix 能力后的整体前后端，再找场景验证；暂不连接业务数据。ADE 为通用本体数据底座，投研仅作为后续验证场景。保留已有三页与视觉，KodaX 为唯一内部 Agent 底座。

首次流程：配置模型 → 选择来源 → 数据页接入 → 本体页自动构建/Agent 辅助修复 → 发布与接入。数据刷新、工作版修订、对外发布及消费者升级分别表达。

本轮直接完成规格、拆票、实现、测试、评审与本地提交；用户已授权整体开发，常规实现选择不重复确认。旧 v0.1.0 的状态与未完成历史保留，不以新版本掩盖旧验收缺口。

## 公共验收与边界

管理 HTTP、真实临时来源、独立消费 HTTP/MCP 与浏览器为主要验收边界。行为测试先红后绿，UI 来自实际回执。测试空间与用户空间隔离，不复制模型凭据或自动读现有业务源。

本轮不做公网部署、多租户/计费、任意源的完整语义理解、完整 OWL 或 Helix 全部连接器。只显示实际实现的存取能力；发布定义不代表冻结源数据。场景质量验证留待本轮交付后。

## 实施依赖

025、026、027、028 可以沿现有服务并行实施，027/028 与 026 联调；029 依赖 028；030 验收前述整链。功能状态只在 FEATURE_LIST.md，票勾选只在下列设计块。

## FEATURE_028: 数据底座版本发布与接入管理

### 1. 需求概述
第三页管理工作版差异、检查、发布版本与接入方；工作修改不影响既有外部消费者。

### 2. 影响范围

### 3. 技术方案

### 4. 接口契约
/api/releases 及 check/publish/connect/upgrade/revoke/connection；版本和操作ID校验，重试不重复发布或签发密钥；已有 v4/MCP 保持兼容。

- [x] T028-02（依赖 T028-01）：失败/重启/权限与存量兼容、界面反馈及集成验证。

### 6. 验收标准
独立客户端可读获准固定版本；工作版改动不影响旧客户端；发布差异/失败可见；升级范围受控，重启保留，撤销及在途撤销有效。

Testing Decisions：engine-releases.test.ts 和比较回归验证检查、发布、升级、回退差异、旧语义、撤销和在途保护；浏览器走通发布/升级/撤销。统一证据见[0.2.0验收](../experiment/ENGINE_WORKBENCH.md)。

## FEATURE_029: 外部 Agent 受限委托与插件能力

### 1. 需求概述
第三方除了直接查询，还能委托 ADE Agent 调查、解释获准数据，获取进度、结果与依据。

### 2. 影响范围
委托任务服务、KodaX 单运行槽、消费认证、MCP 工具和接入说明。

### 3. 技术方案
委托绑定发布版本/调用方范围，只提供消费读取工具；不暴露管理员修订、源凭据或发布权。任务持久化，取消和授权变化拦截迟到结果；不把不同调用方任务共享上下文。

### 4. 接口契约
独立受权任务 submit/status/cancel/result 接口与 MCP 工具，operationId 幂等，任务ID不可跨接入方读取。无可用模型时说明状态，不伪造执行。

### 5. 实现步骤
- [x] T029-01（依赖：028）：公共边界行为与前后端操作链，逐片先红后绿。
- [x] T029-02（依赖 T029-01）：失败/重启/权限与存量兼容、界面反馈及集成验证。

### 6. 验收标准
真实临时消费范围限制工具和结果，未知工具/越权/跨调用方读取被拒；取消和撤销有效，重启可说明中断；模型夹具验证不冒充业务质量。

Testing Decisions：engine-delegation(-revocation).test.ts 验证独立 HTTP/MCP、范围隔离、取消、排队、重启和历史结果授权。统一证据见[0.2.0验收](../experiment/ENGINE_WORKBENCH.md)。
