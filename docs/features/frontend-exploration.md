## 1. 目标与已确认决定

将当前工程验证工作台改为两个主页面：

1. **本体与对象**：默认从全局本体图进入，逐步浏览对象类型、具体对象及其关系、属性、依据和历史。
2. **知识构建**：按一轮构建组织资料选择、候选本体生成、构建方案、业务审核、发布与执行、结果查看。

冲突处理采用“图上提示问题、侧栏就地处理、统一待处理清单作为另一入口”。构建审核和对象查证可以相互跳转，不能创建互不关联的两套处理记录。

本轮以实现这些前端体验为目标，可补充必要的只读查询和响应适配；不改变领域语义、授权规则或现有发布/批准/执行门禁。

## 3. 信息架构与布局

### 3.1 本体与对象

主区：左侧类型/领域筛选，中间图或对象列表，右侧所选内容详情。顶部包含页面切换、搜索、当前查看范围、待处理入口及“更新知识”入口。

必须支持以下路径：

`全局本体图 → 点击类型 → 类型聚焦及对象列表 → 选择对象 → 对象局部关系图与详情 → 查看证据/历史/处理分歧`

- 全局图：节点为 ObjectType，边为 LinkType。显示业务名称与简短说明，可附真实对象数量和问题数量。无可靠统计时显示未知或不显示，不能拿第一页长度充当总数。
- 类型聚焦：高亮当前类型及直接关系，展示业务定义、属性、身份说明和可查询的对象列表。
- 对象列表：业务名称、业务编号、少量重要属性和问题提示；不以 UUID、type_id、revision 作为主展示。缺名称时使用编号，再回退为“未命名对象＋短 ID”；不伪造对象名称。
- 对象图：节点为具体对象，默认加载一跳；按需展开并有数量上限、更多结果入口和覆盖说明。入向和出向关系均可探索，方向与名称必须正确。
- 对象详情：身份摘要、当前属性、关系、待关注事项优先；依据和历史按需展开。点击关系可查看其依据与有效时间。
- 类型图与实例图必须有明确标题、面包屑和返回路径，不混用节点层级。
- 保存筛选、选择和视口等页面状态；往返构建页或证据面板不丢失位置。不保存令牌等敏感内容。
- 无已发布本体时显示空态和“开始构建知识”；有本体无对象时仍能看结构，并说明尚未构建对象。

### 3.2 知识构建

按本轮资料及已有真实任务/本体/计划标识组织工作区，不为了界面新增无必要的持久化“轮次”实体。

业务步骤：

1. 选择/接入资料：保留 CSV、PDF、已有连接及来源版本、采集覆盖信息。
2. 系统分析：生成候选本体和构建方案，显示真实进度、阶段、失败原因及重试入口。
3. 业务审核：候选图居中，变化与待决定事项在左，依据、影响及处理方式在右。
4. 发布并构建：沿现有领域服务执行发布、预检、批准、构建；不能因合并按钮而绕过服务端规则。
5. 结果：逐来源显示完成/失败/未执行、真实新增或变更及剩余问题；链接到正式对象浏览。

“计划”在普通界面称为“构建方案”。默认说明“哪些资料产生哪些对象和关系、身份如何对应、时间和口径是什么、哪些旧来源声明将被替代”。原计划 JSON、单源映射及分步工程操作放入高级区域，保留现有能力。

本体发布与事实构建是不同步骤；分步结果分别呈现。只有领域回执证明成功才标完成。若有些操作当前仍需明确业务决定，展示具体候选及影响后再执行，不做前端假自动化。

刷新或任务轮询不得覆盖未保存审核；来源/本体变化导致预检失效、旧计划不可重放等状态仍必须正确呈现。

## 4. 问题的分层与处理

| 问题 | 图中定位 | 处理入口 |
|---|---|---|
| 类型/关系定义分歧 | 候选本体图对应节点/边 | 构建审核侧栏 |
| 对象身份不确定 | 候选对象对比及相关类型提示 | 现有身份审核机制 |
| 属性或关系事实冲突 | 具体对象及字段/关系提示 | 对象侧栏、证据与修正操作 |
| 映射、读取、预检或执行失败 | 构建步骤和任务面板 | 查看原因、修订方案、重试 |

- 某个实例有冲突，不应让全局类型连线看起来像定义错误；类型节点可以显示“该类型下对象问题数量”，并能解释统计范围。
- 侧栏展示：具体分歧、各方依据、影响、可执行选择、保存结果。选择必须映射现有真实领域能力；不添加无后端支持的“智能解决”“一键合并”。
- 统一清单按类别、状态、阻断性筛选；打开事项定位相关图和同一个处理面板。
- 先核对现有 decision packages、计划身份决定和投影问题的实际契约。可用聚合读取适配统一清单，不强行把所有状态改成一种写入模型。
- 如后台没有持久化的“处理完成”概念，不用前端本地标记冒充处理完成；根据当前领域结果重新计算。
- 不要求所有提醒清零才发布。哪些事项阻断什么步骤，以真实服务端校验为准。

## 5. 展示语义与交互要求

- resolved：展示当前值及依据，不称为“已核实”或“业务真实”。
- conflict：不同资料结果不一致，展示候选，不静默选一个。
- incomparable：口径不同或缺必要口径，暂不能比较。
- uncertain：有记录但时间不明确，不能确定当前是否有效。
- missing：当前资料未提供，不展示为 0、否或不存在。
- disputed：当前人工值与新来源有分歧，保留双方依据。
- 否定、计划、条件、推断候选：沿现有规则隔离，不画成正式事实关系。
- 业务有效时间和系统获知时间分别解释；默认当前，历史查询作为可展开入口。不得编造事件时间或历史状态。
- 人工修正保留理由、依据、有效范围和持续方式；使用已有并发修订、幂等及服务端授权。
- 普通界面不显示原始英文状态和 JSON；开发诊断可以保留原值。
- 图支持缩放、平移、聚焦、返回和适当自动布局；文字可读，节点与连线可点击。关系标签不能只在悬停时可见。
- 颜色之外还用图标、文字或线型区分状态。提供可操作的列表替代视图、键盘焦点和窄屏详情布局。
- 优先二维图。图技术由执行 session 核对已有依赖、规模与维护成本后选择，不要求三维和整库实例铺图。

## 7. 必须验收的业务场景

1. 无本体/无对象：可理解地引导到构建，不出现假节点和虚假统计。
2. 企业—合同—负责人：全局类型图进入合同列表、具体合同、企业和负责人，再返回原位置。
3. 金额冲突：对象显示分歧，各来源金额与口径可查证；全局类型关系不被误标为定义冲突。
4. 不可比与未知时间：不显示唯一确定值，不把未知时间解释为永远有效。
5. 负责人交接：按业务时点查询正确关系；系统获知时点可独立选择，时间未知时如实说明。
6. 人工纠正与再次同步：显示人工依据、持续方式、新来源分歧及真实修正回执。
7. 候选定义和身份审核：候选与正式分离，可查依据和影响，沿现有批准机制执行。
8. 构建部分失败/来源变化：不将整个流程标成功，旧预检失效得到解释，未保存编辑不丢失。
9. 对象超过一页、图邻居过多、断连对象、自关系及多条关系：分页/展开有界，搜索和返回可用，布局不把连线标签遮住。
10. viewer/editor/admin：与当前实际权限一致，不仅隐藏按钮，服务端仍执行校验。
