# MVP：三页本体驱动数据融合

2026-09-11。当前开发目标沿用未发布的 v0.1.0，新增 FEATURE_012—016。本文定义本轮完成条件；T012-01 三页布局与迁移已交付，不等于后续融合闭环完成。

## 最小完整体验

企业与数据 → 基础本体 → 分类来源接入 → 本体工作区查看融合并修订 → 消费与治理 → 独立 Agent 查询。

一个企业空间，三个页面，保留黑白灰画布和前景输入浮层。每页有界对话，共享长期保存的定义、来源、对象引用和治理成果；不增加任务或历史会话页面。

## 本轮交付范围

| 部分 | 最小交付 |
|---|---|
| 三页与迁移 | 合并旧企业/来源页；保留成果、授权与历史引用，迁移实际可读取并成功保存的旧草稿，新版支持草稿恢复；同步在线演示和离线分享 |
| 企业基础 | 运行 Skill 通过对话、已有格式文档、确认企业身份后的真实公开研究形成可检查基础候选 |
| 来源 | 保留 HTTP/MCP 记录能力，补一类文档分段来源、一类 BI 指标能力；按真实输入输出契约适配 |
| 数据融合 | 主来源枚举与附来源明确业务键匹配，形成同实体多源属性及跨类型关系，保留冲突/未知/证据 |
| 可视化 | 定义/对象双视角，局部图、表格和详情共用引用，逐层查看含义、映射和实际证据 |
| 治理 | 一条局部关系纠正与一项全局映射修订；检查、差异、有效决定和真实回执；按触发事件辅助治理 |
| 消费 | 新版本许可 API/MCP，生成一致的契约说明和示例；两个独立调用方、证据权限、撤销与语义迁移 |

基础本体可先形成有依据但未映射的概念。没有可执行映射时不伪造业务实例；采用基础定义也不自动开放消费。各页始终可查看，首次引导不强制穷尽公司信息或接完全部数据源。

## 用户应能完成的任务

1. 仅提供企业名称和业务，获得可修改、有依据的小型基础本体；上传或公开研究补充同一份内容。
2. 在第一页连接真实能力，看到可读样本、用途、映射与限制；失败明确，凭据不入聊天。
3. 在第二页看到一个业务对象的多源属性，追查某个值和关系的依据，理解未匹配和冲突。
4. 通过直接操作或 Agent 完成同一项修订，查看前后差异、检查范围和实际采用结果。
5. 在第三页启用许可范围，复制可用接入说明；独立 Agent 不开浏览器即可发现、查询和取证。
6. 处理一次语义变更的消费者迁移；不同范围的读取、撤销、源变化与版本冲突表现准确。

## 验证边界

沿既有管理 HTTP/领域工具、独立 HTTP/MCP 来源、浏览器及外部客户端验证。虚构热力案例同时包含投诉、附源服务记录、回访、业务文档和 BI 指标。真实跨源结果作为依据，不在模型输入中预置评测答案。

实现票各自验证新增行为；最终整链使用真实 KodaX、桌面/窄屏/键盘和两个独立消费者。覆盖同名公司、资料冲突、分页/粒度、零/多匹配、局部失败、旧版本、重复提交、同键不同请求、取消与撤销竞态、重启、存量迁移和离线导出。

任务成功需有实际保存或执行回执；调查以证据不足结束也可有效完成，但不能宣称业务事实已经成立。模拟测试与真实模型/来源验收分别记录，未完成项如实披露。

## 暂不纳入

任意文件格式、所有厂商专用连接器、全量模糊实体消歧、通用 SQL/OWL 推理、任意 CodeAct、源系统写回、全企业后台巡检、多租户/SSO/记录级权限、公网部署及计费。原始数据不默认整体复制；必要证据保留另有范围与权限。
