# MVP 目标：验证方法的本地实验

## 实验要回答什么

1. 企业原始数据能否通过辅助建模，形成可查询、可计算、可追溯的本体与对象？
2. 相比直接搜索资料，以及专用表配合计算工具，本体是否更容易支持跨系统问题和新的问题组合？
3. 业务变化后，内部 Agent 能否提出正确的本体或映射修改，减少人工维护投入？

实验允许出现不支持预期的结果。链路能运行和方法有收益分别判断；不预设本体一定优于其他方案。

## 最小实验链路

```text
虚构企业原始数据
→ 本体与 Mapping 候选
→ 人工确认的初始版本
→ 企业对象、证据和计算函数
→ 外部 Agent 通过只读 MCP 使用
→ 注入数据或业务变化
→ 内部 Agent 调查并提出修改
→ 简单检查、人工确认、保存新版本
→ 重跑问题，比较前后效果
```

前端用于查看这条链路的真实数据与结果。

## 最小范围

| 部分 | 本轮做到什么程度 |
|---|---|
| 企业与数据 | 采用用户确认的区域热力公司案例；先做设施台账、运行监测、客服与维修记录、业务文档的可核查小样 |
| 初始本体 | 从来源字段、样本和业务说明提出对象、关系、口径及映射候选；关键定义人工确认 |
| 数据服务 | 简单持久化，能查询对象、关系、证据，并调用少量确定性计算函数；提供只读 MCP |
| 内部 Agent | 实际接入 KodaX Runtime，借鉴 NOOA 的稳定对象引用、类型化工具和按需读取，完成调查与候选修改 |
| 本体演变 | 演示普通事实更新、一次 Mapping 变化、一次真实本体或口径调整；保存变更原因和前后版本 |
| 前端 | 一个简单本地工作台，用几个标签查看来源、本体、对象、Agent 修改与对比结果 |
| 实验 | 同一问题、模型、数据时点与预算下比较答案、证据、成本及维护前后变化 |

用文件或单个轻量数据库保存数据即可；先采用单机、单用户运行。代码执行只使用受限的数据工具。初始抽取可先接最小模型调用，完整维护 Agent 后续补齐，避免相互等待。

## 保留的最小可靠性要求

- 事实与关系能找到来源；初始本体不直接读取评测用的标准本体或正确 Mapping。
- 标准答案、生成器内部状态和未来事件与被测 Agent 隔离；未来事件按时间释放。
- 业务定义不明确时请人确认，Agent 不自行决定评价口径。
- 聚合、过滤和数值计算由程序执行，Agent 负责选用与组合工具。
- Agent 只提出候选变更；检查后由人确认应用。保存旧版本，并验证可以恢复旧结果。
- 来源与函数结果带时间和版本；普通数据更新与本体定义变化分别记录。

## 怎样比较效果

首轮准备约 10—15 个问题，分成公开开发问题和未用于调试的评测问题，包含事实、聚合、跨源关系、时间及信息不足的情况。

| 对照方式 | 用途 |
|---|---|
| 原始资料 + 来源导航、业务规则、搜索与计算工具 | 测有组织的原始资料能否直接支持任务 |
| 专用表 + 受限查询 | 检查收益是否只来自整理数据和确定性计算 |
| 静态本体 + 对象与函数接口 | 检查共享对象和口径对新问题的复用价值 |
| 同一本体 + 内部维护 Agent | 在变化后检查维护效果与成本 |

不要求首轮建设通用评测平台，脚本运行与结果表即可。普通 RAG 可在需要时作为补充对照。

各组能看到相同的原始业务信息并可使用计算工具；专用表与本体组复用同样的清洗和身份对齐结果。静态和动态组都正常接收业务事实更新。专用表允许为新问题调整，记录改动投入；动态维护也记录人工确认与返工，不能只比较停更系统与已修复系统。

记录答案正确性、证据是否支持结论、Token、耗时，以及建模和维护投入。初始问题、新组合问题、变化后问题分别报告。对维护任务保留一次人工修复参照，判断 Agent 是否减少达到同等质量所需的工作。

小样跑通后，用同一生成规则扩展到超过 1M Token，记录 Tokenizer 和实际大小，再检查按需访问效果。规模扩展不替代上述业务验证；已有星桥大数据只作为另一领域的参考。

## MVP 完成条件

- [x] 原始数据可重复生成，能核查初始问题与来源。
- [ ] 从可见来源构建并确认一版本体，形成实际可用的对象和函数。
- [ ] 外部 Agent 通过 MCP 完成查询，返回证据与版本。
- [ ] 内部 KodaX Agent 实际运行，按需读对象并提出有依据的修改。
- [ ] 至少一项真实本体或口径变化被检查、确认、应用，旧结果可以恢复。
- [ ] 简单前端能查看数据、本体、修改过程与前后结果。
- [ ] 形成可核查的对照结果，明确有效、无效或仍不确定的部分。
- [ ] 完成超过 1M Token 的规模运行并记录实际表现。

## 这轮先不建设

完整企业连接器平台、多租户与复杂权限后台、自动审批流、并发版本合并、分布式部署、独立图数据库、复杂多 Agent 编排、通用 BI、函数市场、完整本体编辑器，以及外部业务系统写操作。

先把实验跑通；只有实际结果表明某个能力影响验证，才把它加入范围。
