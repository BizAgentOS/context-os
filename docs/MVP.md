# MVP 目标：创建企业记忆

## 首要目标

用一条简单、真实的体验展现 DataEngine 的思路：**基于本体，在 Agent 协助下创建企业级记忆系统。** 用户通过输入框说明企业、接入资料和讨论定义，企业记忆逐步出现在页面上。对话是创建与修改的手段，保存下来的企业信息、来源、本体和对象是产品主体。

这是可行性实验，先检查链路是否成立、产物是否有用。完成一次体验不能证明本体普遍优于其他方法；准确率、必要性、成本与规模的对照留到[后续方法验证](experiment/METHOD_VALIDATION_PLAN.md)。

## 四个页面

| 页面 | 交互 | 保存并展示的内容 |
|---|---|---|
| 企业 | 解决“企业是什么”，从名称和业务起步，逐步了解并纠正 | 企业名牌，以及业务、服务对象、职责、目标与流程认知 |
| 数据来源 | 解决“接入什么”，明确用途，再引导接入资料并解释缺口 | 真实接入的文件、可查看的原文和表格；失败原因 |
| 本体与对象 | 可先用文档形成概念草稿；围绕业务问题查看定义、对象与验证 | 有依据的概念草稿、映射候选、对象与来源证据，以及真实业务验证和用户判断 |
| 数据消费 | 解决“谁可以使用、实际如何使用”，通过对话明确 API 调用方和访问范围 | 调用方、可读对象/字段/关系、接入信息、真实访问记录与撤销结果 |

四页实现已接通；第四页归属 FEATURE_007，类型检查、35 项 Agent 测试和 22 项 Python 测试通过，真实模型与两个客户端的整条体验已验收。具体范围见[消费治理设计](DATA_CONSUMPTION_DESIGN.md)，实测记录见[消费链运行与验收](experiment/CONSUMPTION.md)。

企业初稿只需有用，不要求一次穷尽组织、业务和角色。企业名称和主要业务实际保存后才完成第一页。概念建模可从已检查的非空文档开始；实例仍依赖可用 CSV。四页始终可查看和往返，导航本身不代表创建完成；首次顺序引导，后续在原页维护。

**报告和记忆更新专页不进入本轮界面。** 保留已实现的底层能力与历史成果，不为展示产品思路扩充页面。

## 第一轮保持多小

- 一个企业空间，四个页面；每页一个有界对话上下文，不提供任务、新建会话或历史会话管理。
- 单机、单用户、本地轻量数据库。实际接通 KodaX SDK；本体与 NOOA 式对象环境沿用已实现的受限对象方法。
- 数据先支持 UTF-8 CSV、Markdown、TXT 上传。PDF、Word、腾讯文档和知识库/API 连接器尚未接入，不能显示为已经可用。
- 围绕一个小业务目标形成少量概念与关系，不预置整家公司的业务本体。澄川热力固定样本可作为实验输入。
- 页面由已保存的结构化记忆渲染；模型通过领域工具修改数据，界面随之变化，不执行模型生成的任意页面代码。

## 界面与记忆原则

纯黑白灰画布，底部居中一个输入框。输入框上方只显示少量近期对话，距离越远越淡，随后退出画面。对话和输入框作为前景浮层叠在全高画布上，不以布局行切出底部聊天区；透明区域可继续操作背景，长内容末尾可滚出输入框覆盖范围。保留必要提示、查看内容、上传、确认定义和模型配置入口，不陈列任务状态、执行日志或技术指标。

每页只带入该页有界聊天与已保存的企业记忆。裁剪聊天也要限制实际模型输入，不能只在前端隐藏历史。企业事实、来源、本体、对象及其依据独立保存；删去旧对话不等于删去企业记忆。

具体页面、切换条件和状态契约见[记忆画布设计](CANVAS_DESIGN.md)。

## 消费侧的最小规则

第四页始终可查看，采用本体后才能创建可启用的消费范围。Agent 提出调用方名称、用途与可读范围；用户查看具体字段和关系后点“启用访问”。消费方使用独立 API Key 调用只读接口，服务端逐次校验权限并记录真实结果，停用后下一次调用即被拒绝。对象编号也需要明确授权；原文、证据、统计与业务方法尚未对消费方开放。

首次管理访问使用本机启动链接，管理凭据不交给消费方。调用方密钥只在独立窗口交付一次，关闭后清空，不进入聊天或模型上下文。授权固定本体与权限范围，来源记录可经管理员检查后发布新版本，保持同一密钥；后续增加定义不会自动扩大访问范围。来源可记录用途、负责人和限制对外使用的字段；最新敏感分类同时约束旧版本授权中的字段、身份与关系读取。本轮不提供记录级隔离或员工身份管理。

## 保留的最低可信要求

- 真实模型调用、来源读取和持久化。失败、未知、冲突及尚未实现的能力如实说明。
- Agent 提出定义候选，程序检查来源与映射，用户查看后确认采用。程序检查通过不等于业务语义必然正确。
- 用户原话与模型建议分开保存；来源或推测不能覆盖用户已经确认的企业陈述。
- 对象可回查原始记录和定义依据；旧结果保留原依据，读取不触发新的模型写入。
- 页面推进取决于实际保存和校验，不取决于模型在聊天里宣称完成。停止或切换后迟到操作不得写入。
- 私有评测答案、生成器内部信息和未来事件不进入被测 Agent 的输入。

## 本次维护体验补充

- 企业从名称/业务起步，轻量引导一个业务问题；企业陈述可直接编辑。
- 来源用途/负责人/敏感列可直接维护，失败、更新与待确认留在画布上。
- 本体页有定义、对象、验证三个视角；文档概念与记录实例分别展示。
- Agent 根据业务问题真实执行对象查询并保存依据；用户判断是否符合预期。补充资料后明确重验，旧结果可回查，定义不会随新增事实被自动重写。
- 继续保留前景输入浮层与有界聊天，四页共享成果；不增加任务、报告或更新页面。

实现和验证记录见[四页维护验收](experiment/MAINTENANCE.md)，不将此次小型验证当作本体方法的普遍准确率证明。


## 已补齐的第三方 Agent 接入

第四页支持本地 MCP 桥接与 HTTP API，按调用方发现许可结构和读取对象；可从已有范围生成独立接入草稿，确认后取得自己的密钥。资料更新经检查后发布给指定调用方，同一连接读取新版，旧预期版本报冲突，历史结果不改写。本体语义与授权的演变仍单独确认；本轮没有部署公网 MCP 或自动数据连接器。见[接入与发布验收](experiment/AGENT_CONNECTION.md)。
