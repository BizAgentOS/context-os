# MVP 目标：体验 Agent 构建企业大脑

## 首要目标

让用户通过一条真实、简单、连续的产品体验，看懂并操作 DataEngine 的核心思路：**用 Agent 建立企业理解，接入数据，辅助构建本体，形成可使用、可维护的企业记忆。**

首轮重点是把产品思路做成可运行体验，观察各阶段产物怎样衔接。方法的必要性、准确率、成本收益与规模能力继续验证，但不要求先完成全面对照实验才交付这条体验。原有计划保存在[后续方法验证计划](experiment/METHOD_VALIDATION_PLAN.md)。

## 一条连续的体验

| 阶段 | 用户与 Agent 怎样协作 | 用户能看见的产物 |
|---|---|---|
| 1. 建立企业大脑初稿 | 进入 Agent 工作台，配置所需模型；Agent 主动了解企业、用户职责和当前业务目标 | 可修改、可保存的企业理解，包括已知内容和待补充问题 |
| 2. 接入企业资料 | 上传文档/CSV，或通过已实现的连接器授权读取数据；Agent 解释读到了什么、还缺什么 | 来源清单、原文预览、接入摘要及问题记录 |
| 3. 辅助构建本体 | Agent 按业务任务提出概念、关系和口径，展示证据；用户确认关键定义，程序检查映射并生成实例 | 概念卡、局部关系图、映射说明、带来源的对象和未决项 |
| 4. 使用企业记忆 | 用户提出一个业务问题，Agent 按需读取对象和证据，生成简易报告 | 可阅读、可回查来源的回答或报告 |
| 5. 维护企业记忆 | 用户补充资料或纠正企业理解；Agent 说明影响并提出更新，必要时确认后保存 | 更新前后内容、依据与修改记录；后续回答可使用更新后的记忆 |

“先定义企业”是先形成有用的初稿，不要求对话一次穷尽整个企业。接入资料后继续补充企业理解，并据此修订建模候选。初始企业理解不等同于完成本体构建。

## 第一轮保持多小

- 一个企业空间、一个主要 Agent、一条热力业务链。现有澄川热力资料作为可选择的示例和测试输入，不把预先生成的对象包冒充现场建模结果。
- 实际接通 KodaX，并将本体的概念、实例、关系及业务方法呈现为 NOOA 式对象环境；首轮验证小型对象方法组合与按需取证。SDK 接法和 NOOA 取舍见[主 Agent 设计](AGENT_DESIGN.md)；实际连通仍待实现，已有只读浮窗不算这项完成。
- 首条数据路径先使用文档和 CSV。外部 API 连接器按一个明确目标逐个接入，尚未实现的系统如实标明；不要求首轮同时连接多个企业系统。
- 本体围绕当前业务任务设计少量概念与关系，保留定义理由和来源；不追求覆盖企业所有部门，也不以对象数量作为成功标准。
- 生成一份有来源的简易报告，再完成一次资料补充或理解纠正带来的记忆更新。普通事实更新、企业理解修订与本体定义变化分别记录。
- 单机、单用户、简单文件或轻量数据库保存即可。

## 前端原则

主入口是 Agent 对话。建议左侧提供企业空间、任务和资产入口，中间推进对话，右侧展示当前产物；企业理解、资料、本体、对象、报告和变更可独立打开。

Agent 在建模时展示实际读取的来源、结构化结论、依据和待决定事项。六步建模方法融入任务过程，不要求用户依次填写六个页面。再次进入产品时能继续上次任务、检查新资料和待处理建议。

## 保留的最低可信要求

- 真实模型调用、真实来源读取和真实保存；未接入能力、演示数据和技术试样明确标识。
- Agent 提出候选；关键业务定义可由人确认，未知和冲突不自动变成确定事实。
- 已检查的映射与计算由程序执行，结果可追溯原始记录、资料时点和定义版本；程序执行可重复不等于映射语义必然正确。
- 报告中的推测经查证或确认后才进入长期记忆；保留修改记录，避免聊天内容直接覆盖企业事实。
- 标准答案、私有评测与未来事件不进入被测 Agent 的当前输入；已有冻结基线保持原样。

## 首轮体验的完成条件

- [ ] 用户从 Agent 入口开始，经过主动提问形成可保存、可修改的企业理解。
- [ ] 同一体验内接入第一份企业资料，并查看原始内容与 Agent 的接入摘要。
- [ ] Agent 辅助形成有依据的本体候选，经必要确认和程序检查后生成可追溯实例。
- [ ] Agent 实际沿本体对象访问关系、组合业务方法并取证；用户查看同一对象与关系，得到一份使用这些记忆的简易报告。
- [ ] 补充资料或纠正理解后，能检查并保存一次更新，后续读取能反映变化。
- [ ] 主要产物重新打开仍可读取；失败、未决和未实现状态不会被显示为成功。

当前已有样本、导入试样和浏览型实验室，可复用其数据与查看能力；上面的 Agent 主导体验尚未交付。本次调整文档不代表实现已完成。

## 留到后续

四组方法对照、超过 1M Token 的规模实验、完整外部 MCP 消费验证、三类变化的完整回归/恢复体系，以及通用连接器平台、多租户、复杂权限后台、自动审批、分布式部署和复杂多 Agent 编排。

先核对这一条体验中的业务事实、来源和关键定义；质量问题照实记录。完成一次体验只能说明产品链路成立，不能据此宣称本体普遍优于其他方法。
