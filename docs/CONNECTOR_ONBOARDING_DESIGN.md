# 服务连接向导：迁移 KodaX Space 的交互设计

更新：2026-09-17。飞书首轮实现见 FEATURE_019；MCP 入口优化见 FEATURE_021。本机已保存账号可复用；已验证真实 wiki Markdown 附件读取，在线 docx 的真实读取验收仍保留为待完成项。

## 目标

企业用户选择服务、完成官方登录或授权，即可回到 DataEngine 验证连接。普通接入不要求填写 MCP 请求头、CLI 参数、工具 schema 或业务字段 JSON。顶部导航、Logo、底部助手保持现状；改动集中于资料与数据的接入入口及连接对话框。

## 已核查的上游实现

目标仓库：https://github.com/KodaX-AI-dev/KodaX-Space 。调研时 main 树标识为 `570fde9250cf764207bc1d5b61afe0151bf2b2fb`；本次具体文件通过 main 原文读取，后续复制源码前须对照固定提交内容，不能把活动分支读取冒充锁定版本。

- `apps/desktop/renderer/src/features/extensions/PartnerConnectorDialog.tsx`：服务连接对话框、开始/等待/取消/重试、已有账号选择、连接验证及会话绑定；关闭时处理尚未完成的连接任务。
- `apps/desktop/electron/partner-connectors/connection-tasks.ts`：连接任务的宿主生命周期。
- `apps/desktop/electron/partner-connectors/remote-mcp-oauth.ts`：OAuth 元数据发现、客户端注册、PKCE、state、回环回调、令牌更新及取消。
- `apps/desktop/electron/partner-connectors/official-remote-connectors.ts`：Notion、Airtable、Atlassian 等固定服务的身份验证与资源读取适配，限制可调用工具和目标。
- `apps/desktop/electron/partner-connectors/runtime.ts`：飞书 CLI、企业微信、钉钉、腾讯会议、官方远程连接器等组合；使用宿主凭据存储，不把秘密交给渲染器。

这不是给所有 MCP 加一个统一登录网址。各服务使用自己的授权机制，有的需要官方 CLI，有的使用 OAuth，有的仍有管理员或凭据前置要求。应按真实支持展示，不把浏览器打开成功当成连接成功。

当前 DataEngine KodaX 0.7.96-beta.2 已导出 discoverOAuthEndpoints、registerOAuthClient、performOAuthLogin 等符号；仅确认导出存在，不等于已验证上游适配兼容或完成集成。Space 当前许可证为 KAI-FCL；直接引入源码需保留来源与许可，并按本产品团队的适用授权维护，不将其标为 MIT/Apache 副本。

## 用户流程

当前企业页的 HTTP API 独立使用 [Swagger/OpenAPI 导入](experiment/OPENAPI_IMPORT.md)；MCP 接入点击“添加 / 管理”进入统一连接列表。自定义 MCP 粘贴 URL 即可发现能力，认证和高级配置按需展开；飞书服务行直接登录或复用账号。实现与范围见 [MCP 接入验收](experiment/MCP_ONBOARDING.md)。以下 OAuth 分支仍为目标流程，未因本轮 UI 优化自动接入。

1. 在企业页打开 MCP 连接入口。先展示飞书、自定义 MCP 和已保存的 MCP；HTTP API 通过各自模块导入，旧手工来源映射保留为高级入口。
2. 选服务后只呈现连接方式、需要的账号及权限说明，以及“登录并连接”。不显示字段契约表单。
3. OAuth 路径：本地后端建立连接任务，返回官方授权网址；用户打开网页并登录，宿主接收回调。
4. CLI 路径：后端检查已支持的官方 CLI。需要安装时呈现确定的组件和版本；调用受控登录命令，展示官方授权链接或设备码，等待 CLI 的实际结果。禁止执行用户/模型提供的任意 shell 命令。
5. 回来后验证账号和可用能力。页面显示账号、企业/空间、服务状态及可用范围，用户选择本次需要的范围。
6. 后台保存真实连接回执。资料读取和本体映射另行进行，不因授权成功自动导入全量内容。

状态：准备连接 → 等待登录/授权 → 验证连接 → 已连接。另有失败、已取消、已过期，可重试。取消和迟到回调不能将已撤销连接恢复。

## 页面结构

连接对话框的第一层是服务与已保存连接；飞书行可直接进入登录或读取。自定义 MCP 展示 URL 输入、可选认证，再显示可搜索勾选的真实能力目录。标题、关闭与保存按钮固定，超长内容内部滚动。已有账号可复用或重新连接。高级配置保留现有手工 HTTP/MCP 兼容路径，但从普通用户主路径移出。

资料目录按知识文档、BI 指标、业务记录呈现实际读取内容；账号连接目录管理授权关系。这两个目录关联而不混为同一事实状态。

## DataEngine 的适配边界

- Electron IPC 改成本地 Node 后端的连接任务 API；前端只读取任务状态和允许打开的授权 URL。
- OAuth/CLI 由宿主执行。回调校验、任务取消、超时、令牌刷新、凭据保存由后端负责；公共 API 和模型结果不包含凭据或原始登录日志。
- 优先复用上游可分离的授权适配，按固定服务注册工具与网址。前端接线适配原生 JS，不能原样复制依赖 React/IPC 的组件。
- MCP 工具身份和用户许可沿用现有 AgentMcp 服务；新增 OAuth 凭据不能再次以普通 headers 写入连接配置。过期时先刷新，再恢复同一授权范围。
- 第一轮验证指定一个真实服务的完整登录闭环。其余服务只在适配和验证完成后进入可点击连接目录，不展示假登录按钮。
- 接入本体时 Agent 读取真实目录/样本并提出语义映射候选。复杂 JSON 由适配器与 Agent 协助生成，用户核对业务含义；明确字段和只读范围的责任仍由共同服务实施。

## 开发验收

先选首个目标服务，再完成：账号登录、取消、过期、失败重试、回调重放拒绝、账号验证、只读内容发现、断开与重连、服务重启恢复。使用模拟身份服务验证回调和凭据边界；真实厂商登录由用户完成后验证一次读取。安装 CLI、申请厂商应用、实际账号授权必须有对应操作的明确范围，不以连接设计任务冒充账号授权。

UI 验收要确认普通接入无需手工填写 schema，原高级接入仍可用，顶部导航及助手未改变。通用 OAuth 与其他服务仍为设计；本轮只实现飞书 CLI 路径。

## 飞书首轮实现

用户已选定飞书。固定树对应的 feishu-cli、runner、安装与 release lock 文件已补充核查。按命令协议独立适配 Node 宿主，未直接复制 Space 源码。使用官方 larksuite/cli v1.0.92 的锁定文件及摘要。

实现入口：src/connectors/feishu.ts、feishu-cli.ts、web/agent/connections.js、feishu-connection.js。飞书通过 Business SDK 提供 feishu.document.read，并非新增远程 MCP transport。来源映射和基础本体采用仍沿用原服务，登录不代表完成融合。

现有账号保存的是经过验证的 profile 引用，CLI 负责凭据；每次读文档重新核验同一应用和账号。取消等待进程退出，禁止迟到结果恢复；断开清除本地引用，不声称撤销远端授权。账号存在时显示上次核验时间，实际读取再次验证。

首轮验证：128 项测试通过，浏览器确认服务向导与高级 API/MCP 入口。2026-09-17 本机已存在授权账号，本轮只验证直接复用入口，未重新授权或读取私有文档；最新验收和未完成边界见 FEATURE_021 记录。功能状态见功能台账。


## 2026-09-17 知识库附件读取修复

用户提供的 `/wiki/…` 链接实际指向上传的 Markdown 文件，原宿主只接受 `/docx/…`，因此请求在本地被拒绝，未进入飞书读取。账号已授权且相同账号的知识库解析和文件下载均真实成功。

现入口支持指定 wiki 节点：官方 `wiki +node-get` 校验节点身份并取得底层类型；docx 走原正文读取，file 仅允许 Markdown / TXT / CSV。只读调用固定参数、显式 user 身份，不创建或转换远端文档。附件通过固定版本 CLI 下载到宿主生成的私密临时目录，核对路径、普通文件、长度与 CLI 回执，严格 UTF-8 解码、拒绝 NUL，限制 250 KB / 60000 字符，结束即清理。每个异步步骤返回后复核账号连接未断开。目录和其他类型有具体提示，不递归导入。

在线文档返回实际 revision；附件没有文档 revision，返回 null、内容 SHA-256 与 readAt，页面明确显示“文本文件 · 本次读取内容”。新增范围只读使用已有授权；缺少知识库/下载 scope 时提示补充授权，不自动扩大权限。底层仍是官方 CLI 的 Business SDK 读取，不新增远程 MCP 服务，不自动保存为资料或采用到本体。验收见 [知识库附件](experiment/FEISHU_WIKI_FILES.md)。


## 飞书已读资料与本体入口

明确读取的 docx 或 wiki 文本附件，经页面和 `feishu.document.read` 的共同服务保存为 `source` 文本快照。远端身份（域名、对象种类与文档 ID）区分来源，不用文件名合并；同名上传资料独立。内容摘要、标题或远端文档版本变化形成新的本地版本，相同内容重读复用已有快照，保留原快照读取时间；附件无远端版本时不虚构版本号。断开账号不删除此前保存的本地资料。

企业页显示飞书已读份数与可点击文档，详情显示实际正文、字符数、原文链接、快照读取时间及引用它的当前候选/已采用本体概念和关系。旧快照引用明确标注。已读不等于已本体化；没有模型时保留资料并指向模型设置，不生成假候选。

“用于本体化”绑定已保存来源 ID/版本，将任务交给既有本体工作区与唯一 KodaX 循环。Agent 仍需加载基础本体 Skill、分段真实读取和验证原文引文，再保存候选；人工采用保持原合同。基础定义来源可定位到快照和飞书原链接，不是全量同步、业务实例映射或自动发布。
