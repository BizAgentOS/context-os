# Agent 与前端协作契约

更新：2026-09-11。本文只定义前端与内部 Agent 如何共享目标、上下文和业务结果。三页布局及人类流程见 [CANVAS_DESIGN](CANVAS_DESIGN.md)，运行、工具与 Hook 分工见 [AGENT_DESIGN](AGENT_DESIGN.md)，共同对象/操作与服务检查见 [SEMANTIC_CONTRACTS](SEMANTIC_CONTRACTS.md)。

本文为目标契约，当前仍运行四页。三页及新增字段在 FEATURE_012—016 中实施并定稿，示意不是当前 SDK/API 使用说明。外部 Agent 的独立消费只在 [DATA_CONSUMPTION_DESIGN](DATA_CONSUMPTION_DESIGN.md) 定义；本文不维护第二套循环、权限规则或任务状态。

## 1. 共同 ObjectRef，独立展示状态

从 AI 可理解、可操作的本体对象出发：前端与 Agent 通过共同服务解析同一业务身份、说明、关系、证据与操作。图节点、详情行和 Agent 对象代理可以表示同一个领域对象；显示名称、DOM ID 和进程内句柄不能替代稳定 `ObjectRef`。

`ObjectRef` 的空间、种类、标识和相关版本遵循语义契约。定义、实例、断言、来源与变更必须可区分；企业基础定义尚未映射时也能有治理引用，不能虚构业务实例。跨运行重新解析持久引用，不复用旧内存句柄。

缩放、滚动、面板和布局是前端状态，不修改业务本体。前端从同一状态形成可访问的人类表达；机器接口直接提供业务内容。借鉴无障碍树不要求业务图变成树，也不通过 ARIA 标签传递企业数据。NOOA 式对象方法与 KodaX 的运行结构统一由 Agent 设计维护。

## 2. 消息固定的 WorkContext

工作上下文描述“本次在讨论什么”，不定义企业事实，也不授予权限。建议包含当前视图/分区、明确选择、结构化作用范围、相关草稿/变更引用和上下文修订号；仅带本次必要的少量引用，其他内容按需读取。

以下为示意，字段在实现票中对齐共同契约：

```json
{
  "view": "ontology.objects",
  "contextRevision": 18,
  "selection": [{
    "spaceId": "heating-demo",
    "kind": "assertion",
    "id": "a-42",
    "versions": {"semantic": "s3", "mapping": "m2"}
  }],
  "scope": {"district": "east"},
  "changeRef": "change-42"
}
```

引用与语义契约中的断言 `a-42` 对应。身份由宿主绑定，服务仍核对本次企业、当前权限及相关版本；标签、动作清单和客户端 `approved` 标志不能成为授权。显示“东区投诉”不替代结构化过滤条件。

发送时将上下文固定关联到该消息。随后选择、过滤或视角变化只影响下一条消息，不将旧操作重定向。输入旁显示可移除的目标引用；未保存输入需显式标注，不能默认为已采用定义。多目标歧义会影响修改时先做独立检查，再澄清目标。

`setup` 内仍区分企业与来源焦点，合页不抹去对象类别或扩大工具授权。上下文不能全量附带渲染节点、本体或两页历史；可信说明、能力与证据由服务按需提供。

## 3. 展示意图与业务回执

Agent 可请求展示对象、证据、差异或结果入口；这些是展示意图，不提交业务变化、不表示授权，也不覆盖未保存输入。用户正在其他位置工作时可保留当前位置并显示轻量入口；前端关闭不应阻止领域成果保存。

| 信息 | 前端如何处理 |
|---|---|
| 展示意图 | 解析引用后定位/高亮或提供入口，保留草稿和焦点 |
| 读取回执 | 展示实际结果、时间、版本、覆盖与可披露限制 |
| 变更回执 | 按实际保存/采用/冲突/失败更新资产及差异，保留未完成部分 |
| 运行事件 | 表达正在执行、停止或错误，不据此修改业务完成状态 |

服务检查和 Hook 分工引用 Agent 设计与语义契约：UI 直接编辑与 Agent 调用都经过共同服务；组合中的实际方法不能绕过检查。界面只消费真实回执，不凭模型结束语、页面跳转或工具外层成功推断业务成功。

同一有效身份、范围和条件下，两类入口应得到一致的领域结果；这不要求人类与 Agent 拥有相同权限。后置检查失败时据实显示已提交部分与缺口，不能假称自动回滚。源连接仍只读，内部纠正不显示为源系统写回。

## 4. 跨页使用同一 changeRef

`changeRef` 指已保存的共同变更；尚未保存的表单输入是独立草稿，不假装已有服务端变更。第二页负责内容检查、修订和采用；第三页沿同一引用查看消费者影响并处理发布、迁移与授权。

跨页保留变更引用、目标与返回位置，不复制候选、不在两处重复批准同一决定。内容采用不代表消费者自动迁移或新字段自动授权；源事实刷新、语义采用与消费发布分别呈现。具体版本兼容与消费范围遵循消费设计。

回到第二页继续修改时需核对当前版本与决定是否仍有效；旧回执保持历史含义。恢复一个页面不能自动采用、发布、迁移或签发凭据。

## 5. 草稿、停止与状态恢复

分别显示页面到达、Agent 运行、资产状态与业务交付。基础本体已采用但未映射可以是合法成果；连接成功、候选保存、内容采用、消费者迁移不能合并为“完成”。完成判据由 Agent 设计与领域契约维护；如果要求具体核实而证据不足，保留待补条件，不自行降低目标。

停止或切页按运行控制使旧运行失效，迟到写入受服务约束。前端要区分未执行、未提交、取消前已提交、部分完成与结果待核对；取消不能显示为已撤销既有成果。

重试或结果不明时先按操作标识核对实际回执，再遵循幂等/并发规则处理。版本冲突保留本地输入和候选供重新检查，不静默覆盖较新内容，也不直接复用失效决定。

恢复先读取持久对象、变更回执与待处理项，按当前权限/版本重新解析，再重建画面和有界摘要。事件重放只恢复展示，不重复业务写入。未发送草稿保留自己的目标和基础版本，不自动发送，不覆盖另一草稿。

旧版企业/来源草稿只在浏览器内存；迁移前导出或持久化仍可读取的两份，再分别恢复。已经卸载的内存无法找回，新版需实现草稿恢复。旧历史保留原消息与成果引用，`setup` 只取摘要、待处理项和有限近期内容；完整兼容步骤见 [THREE_PAGE_PLAN](THREE_PAGE_PLAN.md)。

## 6. 协作验收

- 图、表、详情和 Agent 引用同一目标；定义与实例不混用，发送后切换选择/过滤不会改错对象。
- 展示证据/差异不覆盖未保存输入；草稿与服务端变更可辨，保存与采用以真实回执显示。
- 直接编辑与 Agent 操作落实相同领域检查；重复、并发、停止后的迟到返回没有错误或重复写入。
- 同一 `changeRef` 串联内容采用与消费影响，未经授权不迁移消费者或开放新字段。
- 停止、切页、重启后按真实成果与当前权限恢复；不重放写入、不丢可恢复草稿、不将运行结束当业务完成。

验证范围与实际限制随对应实现票记录，状态只维护在 [FEATURE_LIST](FEATURE_LIST.md) 与 [版本设计块](features/v0.1.0.md#feature-012)。
