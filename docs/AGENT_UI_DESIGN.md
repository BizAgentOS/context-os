# Agent 与前端协作契约

更新：2026-09-11。本文只定义前端与内部 Agent 如何共享目标、上下文和业务结果。三页布局及人类流程见 [CANVAS_DESIGN](CANVAS_DESIGN.md)，运行、工具与 Hook 分工见 [AGENT_DESIGN](AGENT_DESIGN.md)，共同对象/操作与服务检查见 [SEMANTIC_CONTRACTS](SEMANTIC_CONTRACTS.md)。

当前已实现三页与消息绑定的工作上下文（FEATURE_012）；下节标明实际接口。断言、共同变更、局部编辑与消费迁移仍是 FEATURE_013—016 的目标，不能把全文视为已交付 API。外部 Agent 的独立消费只在 [DATA_CONSUMPTION_DESIGN](DATA_CONSUMPTION_DESIGN.md) 定义；本文不维护第二套循环、权限规则或任务状态。

## 0.2.0 三页协作补充

新空间先配置模型、选择来源（可稍后），再进入数据、本体、发布与接入。数据页以来源和实际策略为主体；本体页保留三维空间与共享输入框，提供定义/对象视角、程序任务、问题、候选检查/采用入口；发布页展示真实差异、检查、历史版本和接入升级。

切页只改变界面，不取消在途 Agent；任务条保留原页面和状态。需要停止时显式操作，迟到结果不能变成新页面的修改。当前页草稿与消息绑定引用继续沿既有契约。没有业务数据时显示空态，不填充展示用对象或统计。


## 2026-10-17 本体浏览引用与回执

当前本体三维页聚焦基础概念或关系时，经共同上下文服务解析后，将它作为输入旁可见、可取消的“当前浏览”引用。已有显式引用优先，继续浏览不会覆盖它。取消当前浏览引用后，同一选择不会被轮询立即加回；切换到新的对象才可重新跟随。自动引用不聚焦输入框、不改动输入文字，也不新增任何领域授权。

默认引用仍使用稳定基础本体 ID、版本、概念/关系 member；解析未完成或失败时不能把页面节点当作已校验上下文。发送时冻结该条消息的完整请求与 workContext，后续移动视角、取消引用或切换选择不会改变已发送目标。明确点击“引用到对话”继续沿相同服务处理，其优先级高于当前浏览。

忙碌、请求与任务进度轮询只更新状态，不销毁语义数据未变化的 Three.js 场景。管理弹窗位于独立宿主；真实语义更新需要重建场景时，已打开弹窗仍保留。采用等操作在当前弹窗内显示处理中、成功或实际错误，在途禁用交互；已知失效候选不显示采用入口，服务端执行时再次检查权限、来源与基线。

本节更新了下文 T012/T015 初始实现中“浏览始终不附带引用”的界面选择规则。引用身份、发送冻结、版本冲突、显式引用及服务端校验合同不变。桌面与窄屏验证证据见[本轮修复验收](experiment/ISSUES_2026_10_17.md)。

## 1. 共同 ObjectRef，独立展示状态

从 AI 可理解、可操作的本体对象出发：前端与 Agent 通过共同服务解析同一业务身份、说明、关系、证据与操作。图节点、详情行和 Agent 对象代理可以表示同一个领域对象；显示名称、DOM ID 和进程内句柄不能替代稳定 `ObjectRef`。

`ObjectRef` 的空间、种类、标识和相关版本遵循语义契约。定义、实例、断言、来源与变更必须可区分；企业基础定义尚未映射时也能有治理引用，不能虚构业务实例。跨运行重新解析持久引用，不复用旧内存句柄。

缩放、滚动、面板和布局是前端状态，不修改业务本体。前端从同一状态形成可访问的人类表达；机器接口直接提供业务内容。借鉴无障碍树不要求业务图变成树，也不通过 ARIA 标签传递企业数据。NOOA 式对象方法与 KodaX 的运行结构统一由 Agent 设计维护。

## 2. 消息固定的 WorkContext

工作上下文描述“本次在讨论什么”，不定义企业事实，也不授予权限。建议包含当前视图/分区、明确选择、结构化作用范围、相关草稿/变更引用和上下文修订号；仅带本次必要的少量引用，其他内容按需读取。

T012-02 已实现的管理接口如下。`POST /api/canvas/context` 接收 `{page, context}`，校验并返回 `{context, target}`；`POST /api/canvas/context/read` 使用相同输入读取定义或当前来源。`POST /api/canvas/message` 接收 `{page, text, messageId, workContext}`，其中 `workContext` 是同一份原始上下文：

```json
{
  "view": "ontology.objects",
  "revision": 18,
  "selection": [{
    "spaceId": "workspace-id-from-canvas",
    "kind": "relation",
    "id": "live-model-id",
    "version": 1,
    "type": "投诉",
    "member": "回访记录",
    "objectId": "TS002"
  }],
  "scope": {"where": {"$id": "TS002"}, "offset": 0, "limit": 20},
  "draftRef": {"id": "browser-draft-id", "revision": 4}
}
```

这是字段示例，ID 需取自当前企业。实际支持：`artifact` 整份成果、`type` 类型定义、`property` 属性、`relation` 关系定义或某对象的关系、`object` 具体实例。细粒度引用当前只支持在线本体；`id/version` 是本体成果的版本，`type/member/objectId` 定位其中内容。关系以起点类型与关系名称定位，不以图上连线数组下标定位。文件实验保留整份成果引用，尚不支持断言级引用或独立语义/映射版本。

`view` 为 `setup.company`、`setup.sources`、`ontology.definitions`、`ontology.objects` 或 `consumption`；一次最多一个选择、十个过滤条件、最多读取一百条。`draftRef` 仅代表浏览器草稿，不是服务端候选或审批。布局、缩放、整张图和源记录不随消息全量提交。

服务核对企业空间、内容种类、类型/成员存在性、版本及当前来源能力；只接受声明的字段，客户端不能自行增加 `approved` 授权。实例关系的过滤作用于起点，分页作用于关联结果；读取使用同一在线查询服务，返回实际时间和覆盖。源不提供历史时，固定本体版本与范围不意味着冻结源事实。

本体三维页浏览基础概念/关系时按上方 2026-10-17 补记跟随为可取消引用；其他对象表、属性及关系入口仍通过明确动作选择讨论目标。输入旁可查看服务解析的内容、版本和范围，显式引用优先。引用操作保留输入文字；刷新或跨页恢复原草稿和其目标。

发送时固定完整请求及服务解析后的目标，Agent 获得同一 `workContext`，通过无参数 `context_read` 读取这条消息的目标。用户消息与 Agent 结果显示该引用。后来的选择、取消、输入编辑不重定向已发送操作；浏览器响应丢失时保存原请求并提示“重试上次发送”，确认原回执后再发送新草稿。服务以消息 ID、文字及规范化上下文校验重试，服务重启与消息裁剪后仍不重复执行。明确拒绝（如旧版本）保留输入，允许重新选取目标。

旧版未决记录 `{id,text,contextKey}` 未保存完整请求，升级后调用 `POST /api/canvas/message/receipt`，以 `{page,messageId}` 只核对原 ID 是否已接收（同时兼容新旧指纹）；不从当前选择猜测或重建旧操作。若此前未接收，保留草稿供用户作为新消息发送。

领域写工具执行前重新核对目标版本与来源；本轮合法更新的可信写入回执可推进执行所依据的版本，消息仍保留原引用。任务状态工具不受领域目标的旧版本阻挡；既有运行有效性继续拦截停止后的迟到调用。上下文是讨论范围，不给额外权限，也不是任意工具参数的自动重写器；局部修改/差异/跨页 `changeRef` 留给后续治理票。

`setup` 内仍区分企业与来源焦点，合页不抹去对象类别或扩大工具授权。上下文不能全量附带渲染节点、本体或两页历史；可信说明、能力与证据由服务按需提供。

## 3. 展示意图与业务回执

Agent 可请求展示对象、证据、差异或结果入口；这些是展示意图，不提交业务变化、不表示授权，也不覆盖未保存输入。用户正在其他位置工作时可保留当前位置并显示轻量入口；前端关闭不应阻止领域成果保存。

| 信息 | 前端如何处理 |
|---|---|
| 展示意图 | 解析引用后定位/高亮或提供入口，保留草稿和焦点 |
| 读取回执 | 展示实际结果、时间、版本、覆盖与可披露限制 |
| 变更回执 | 按实际保存/采用/冲突/失败更新资产及差异，保留未完成部分 |
| 运行事件 | 表达正在执行、停止或错误，不据此修改业务完成状态 |

服务检查和 Hook 分工引用 Agent 设计与语义契约：UI 直接编辑与 Agent 调用都经过共同服务；组合中的实际方法不能绕过检查。界面只消费真实回执，不凭模型结束语、页面跳转或工具外层成功推断业务成功。

同一有效身份、范围和条件下，两类入口应得到一致的领域结果；这不要求人类与 Agent 拥有相同权限。后置检查失败时据实显示已提交部分与缺口，不能假称自动回滚。源连接仍只读，内部纠正不显示为源系统写回。

## 4. 跨页使用同一 changeRef

`changeRef` 指已保存的共同变更；尚未保存的表单输入是独立草稿，不假装已有服务端变更。第二页负责内容检查、修订和采用；第三页沿同一引用查看消费者影响并处理发布、迁移与授权。

跨页保留变更引用、目标与返回位置，不复制候选、不在两处重复批准同一决定。内容采用不代表消费者自动迁移或新字段自动授权；源事实刷新、语义采用与消费发布分别呈现。具体版本兼容与消费范围遵循消费设计。

回到第二页继续修改时需核对当前版本与决定是否仍有效；旧回执保持历史含义。恢复一个页面不能自动采用、发布、迁移或签发凭据。

## 5. 草稿、停止与状态恢复

分别显示页面到达、Agent 运行、资产状态与业务交付。基础本体已采用但未映射可以是合法成果；连接成功、候选保存、内容采用、消费者迁移不能合并为“完成”。完成判据由 Agent 设计与领域契约维护；如果要求具体核实而证据不足，保留待补条件，不自行降低目标。

停止或切页按运行控制使旧运行失效，迟到写入受服务约束。前端要区分未执行、未提交、取消前已提交、部分完成与结果待核对；取消不能显示为已撤销既有成果。

重试或结果不明时先按操作标识核对实际回执，再遵循幂等/并发规则处理。版本冲突保留本地输入和候选供重新检查，不静默覆盖较新内容，也不直接复用失效决定。

恢复先读取持久对象、变更回执与待处理项，按当前权限/版本重新解析，再重建画面和有界摘要。事件重放只恢复展示，不重复业务写入。未发送草稿保留自己的目标和基础版本，不自动发送，不覆盖另一草稿。

旧版企业/来源草稿只在浏览器内存；迁移前导出或持久化仍可读取的两份，再分别恢复。已经卸载的内存无法找回，新版已实现按企业和页面的草稿恢复。旧历史保留原消息与成果引用，`setup` 只取摘要、待处理项和有限近期内容；完整兼容步骤见 [THREE_PAGE_PLAN](THREE_PAGE_PLAN.md)。

## 6. 协作验收

- 图、表、详情和 Agent 引用同一目标；定义与实例不混用，发送后切换选择/过滤不会改错对象。
- 展示证据/差异不覆盖未保存输入；草稿与服务端变更可辨，保存与采用以真实回执显示。
- 直接编辑与 Agent 操作落实相同领域检查；重复、并发、停止后的迟到返回没有错误或重复写入。
- 同一 `changeRef` 串联内容采用与消费影响，未经授权不迁移消费者或开放新字段。
- 停止、切页、重启后按真实成果与当前权限恢复；不重放写入、不丢可恢复草稿、不将运行结束当业务完成。

验证范围与实际限制随对应实现票记录，状态只维护在 [FEATURE_LIST](FEATURE_LIST.md) 与 [版本设计块](features/v0.1.0.md#feature-012)。

## 基础定义协作（T013-01）

企业与数据、本体工作区显示同一 `foundation` 当前候选及已采用版本。用户可展开逐项原话、查看未知/冲突/变化、绑定整个基础成果与助手讨论，再采用具体版本。名称纠正显示原名与新名；修订不会替换仍有效的 adopted 定义。基础采用不自动产生可查询数据。T014-03 已接通概念/关系的动态绑定投影：当前已采用有效执行子集显示已绑定，候选可预览，未映射内容仍保留；入口与版本边界见[绑定契约](SEMANTIC_CONTRACTS.md#t014-03-基础概念与业务执行子集)。基础成员级选择及完整图编辑仍属 T015，实际接口见[基础 Skill 契约](COMPANY_FOUNDATION_SKILL.md#10-t013-01-实际接口)。


### 基础定义的文档原文定位

企业与数据、本体工作区使用同一 foundation 版本及 evidence ID。“查看依据”区分用户陈述与文档；“定位资料片段”从共享服务取得原文上下文、高亮引文，并显示依据版本和当前资料版本。未解决冲突同时展示原含义、资料建议及双方依据。前端不自行推断引用位置、解决冲突或推进采用版本。


网页依据与文档沿用同一 evidence ID、基础成果和定位接口。界面标明“公开网页”、读取时间、覆盖与适用时间未知；“打开原网页”访问当前网站，“查看当时网页片段”展示保存的原文。快照按需读取，不随着页面基础投影批量传入对话。

## T015-02 对象、属性与关系探索

在线执行子集下可展开“探索在线对象与关系”，在对象表/关联图中检查同一读取结果，再用明确的“引用对象/属性/关系”动作固定讨论目标。具体属性引用保留 objectId 与 member；关系引用保留起点对象与关系名、当前分页范围。查看图表本身不覆盖对话目标；模型读取时重新访问当前源。

页内按需读对象与关系，逐属性查看状态/原值/来源字段，关系返回失败时清除未确认图形并提供重试。请求代次与组件存活共同保护晚到结果，附到对话前再次检查当前详情代次。类型和模式等页面状态与草稿分离；展开状态及列表所选对象在同一页面重绘时尽量保留，不保存查询结果为企业事实。

### T015-03 已实现：局部关系治理

本体工作区中，从完整对象关系结果或映射下的治理入口提出纠正；表单与 Agent 共享服务、候选和变更引用。表单保留理由与提交者依据，空目标集合明确显示“无关联”；检查后展示原值、目标、适用条件与具体检查版本，再由用户确认采用。采用后重新读取关系可见纠正与原目标，不写回源系统。取消只处理未采用候选。

治理列表读取有界元数据，点击再读指定版本正文。列表与详情忽略卸载或过期请求；保存期间冻结输入，失败恢复草稿，响应未知时按同一操作 ID 重试，不提前宣称未保存。窄屏与键盘复用同一按钮和表单。仅完整关系结果预填纠正，分页结果需先确定完整集合；详情可展开实际读取依据。验证见[局部关系纠正验收](experiment/RELATION_CORRECTIONS.md)。

### T015-04 已实现：全局映射治理
