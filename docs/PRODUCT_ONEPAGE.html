DataEngine.产品说明 / 本地 MVP · 2026.09

用 Agent 构建企业记忆

以本体组织知识，让企业信息被持续维护、共同使用。

DataEngine 是企业记忆引擎。Agent 协助理解企业、整理资料、构建本体，将分散信息变成有业务含义、可追溯、可查询的企业记忆，再提供给其他 Agent 和应用使用。

01

Agent 怎么做：执行能力 + 对象工作区

KodaX · 负责执行

通过 SDK 管理模型调用、会话与工具执行循环。Agent 选择下一步，根据工具返回的实际结果继续工作。

NOOA 思路 · 组织操作环境

把企业信息、资料、本体和业务记录组织成有状态的对象，供 Agent 按需读取、关联和执行方法。

用户提出目标→KodaX 驱动 Agent⇄对象工作区执行并返回结果

本体本身可被检查与修订；采用后的定义，决定业务对象的结构与方法。
DataEngine 负责保存、检查和版本管理；NOOA 作为对象工作区的设计参考。

02

四步建立企业记忆系统

企业 → 数据 → 本体 → 连接
01
建立企业认知这家企业是什么？

通过问答明确名称、业务、职责和目标。Agent 补问关键缺口，用户纠正，保存可持续完善的企业基础信息。产出：企业画像与业务目标

02
创建数据基础需要哪些资料？

实验准备虚构热力公司的文档与记录；实际使用时接入企业资料。Agent 检查内容，保留原文、用途和版本。产出：有来源、有版本的资料库

03
构建业务本体数据代表什么？

Agent 依据资料提出概念、身份、属性、关系与业务口径，将记录映射为对象；程序检查并预览，用户确认采用。产出：本体定义 + 业务对象 + 来源依据

热力示例：投诉 → 处理工单 / 居民回访。
“工单办结”与“供热恢复”分别定义，沿关联查证，避免混为一谈。
04
连接第三方谁可以使用？

通过 MCP 或 HTTP API 提供只读查询。第三方 Agent 和应用各用独立密钥，限定对象、字段与关系范围，可查看调用记录并停用。产出：可授权、可复用的企业记忆服务

03

建好后，持续维护与更新

补充资料→检查变化→确认发布→下次查询读取新数据

记录更新沿用本体与密钥；定义和权限变更需确认。历史来源与依据持续保留。

用户维护企业知识，Agent 协助建设，多个应用共享同一套业务理解。

当前 MVP：单机实验；支持 CSV / Markdown / TXT 与只读 MCP / HTTP 接入。
真实系统连接器、云端部署后续扩展；随附 HTML 为虚构数据的离线演示。
