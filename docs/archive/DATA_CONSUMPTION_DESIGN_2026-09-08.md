# 第四页：连接与访问治理

2026-09-08，依据用户对四个页面职责的补充。归属 FEATURE_007，状态 Completed；第四页与消费 API 已实现，35 项 Agent 测试与 22 项 Python 测试通过，真实模型、浏览器及两个独立客户端的体验验收完成。完成状态以功能台账和[实际验收](../experiment/CONSUMPTION.md)为准。

## 四页各自回答什么

| 页面 | 核心问题 | 持续形成的内容 |
|---|---|---|
| 企业 | 企业是什么？ | 企业认知初稿：业务、服务对象、职责、目标与关键流程，随对话逐步补充 |
| 数据 | 需要接入什么数据和资料？ | 来源清单、内容、业务用途、接入状态与缺口 |
| 本体 | 如何把资料组织为一致、可使用的企业记忆？ | 概念、身份、关系、业务口径、映射、实例与证据，是产品核心 |
| 连接 | 谁在使用企业记忆，可以使用什么，实际使用了什么？ | 调用方、授权范围、接口接入信息和真实访问记录 |

第一页的名称和业务只是启动门槛，后续仍须逐步建立企业理解。第二页包含“为什么接这份资料”，不只展示文件。第三页把企业理解与资料联系起来。第四页使这些记忆能被下游应用和 Agent 受控复用。

来源质量、接入时点与来源追溯由第二页承接；定义一致性和本体变化由第三页承接；第四页聚焦消费方身份、访问范围和审计。安全约束在实际读取路径执行，不能仅放在第四页的界面上。

## 页面怎样形成

保持现有黑白画布、底部单一输入框和渐隐对话。初次提示：“哪些应用需要使用这些企业记忆？”

例如用户说：“让客服助手查询投诉和回访，但不要读取联系方式。”助手根据实际已采用的本体提出可检查的授权范围，画布出现“客服助手”以及它能访问的对象、字段和关系。对实际不存在的对象或字段先说明缺口，不能凭空创建授权目标。用户明确授权后保存，凭据通过专门的受控交付显示，不进入模型上下文或聊天历史。

有消费者后，画布显示企业记忆与调用方的连接。点开一个调用方查看允许访问的内容、启停入口、接入方式和最近实际调用。接口地址和必要的接入参数按需显示；原始执行日志、工具轨迹、无用途的技术统计不进入主画面。

FEATURE_008 调整后，连接页始终可以查看；没有已采用本体时不能签发消费权限。本体采用不会自动授权任何调用方。

## MVP 只验证一条消费链

一个本地企业空间、两个实验调用方、一组只读对象 API。两类客户端可复用同一脚本，用不同凭据验证各自权限。

1. 登记调用方名称和用途，按当前本体指定可读对象类型、字段及允许的关系。未明确允许的内容不可访问；首轮不提供外部写入。
2. 每个调用方使用独立凭据识别，支持停用/撤销。调用方身份指凭据所属的应用或 Agent；如需识别应用背后的具体员工，另需可靠的员工身份机制，本轮不冒充已实现。
3. 通过真实 API 查询授权范围内的对象；相同请求在另一个没有权限的身份下被拒绝。外部调用不需要启动模型才能执行权限检查。
4. 页面出现真实访问记录：调用方、时间、操作与资源、成功/拒绝及必要原因、所用本体/数据依据。记录不保存完整凭据和不必要的原始返回内容；拒绝请求也不能泄露受限内容。
5. 停用调用方后，下一次请求被拒绝，重启后授权与记录仍然保留。

首轮按对象类型和字段控制读取，关系目标也必须在授权范围内。暂不实现按楼栋/片区等记录级隔离，不作这种权限承诺；需要该能力的场景另行扩展。原始文档与完整来源行默认不向消费方开放，避免通过证据入口取回被限制的字段。若要提供来源内容，必须另有明确范围并检查实际返回。

## 与现有引擎怎样结合

复用本体定义、对象查询和固定来源依据，在外部消费入口加入独立的身份与授权检查。Agent 负责理解配置意图并提出方案，应用服务负责授予、撤销和每次请求的实际校验。凭据按不可逆摘要保存，完整值仅在必要的交付环节提供。

授权绑定已采用的具体本体定义和明确字段清单，不用“允许全部未来字段”的隐式授权。新增字段、关系、模型或来源版本不因变化自动扩大可读范围；一次请求使用一致的本体/来源依据。首轮固定授权对应的已采用版本，迁移时重新检查权限适用性。

应用自己的管理与预览接口包含完整记忆，不能作为消费端的替代入口开放。原始文件读取、关系展开、证据、集合/统计和错误信息同样受消费权限约束；首轮只开放已经有实际校验的读取操作，其余拒绝。

HTTP 消费入口与本地 MCP stdio 桥复用同一权限边界；FEATURE_009 补齐本地第三方 Agent 接入，远程 MCP 服务另行建设。保持本地实验范围，不部署公网、多租户、企业 IAM、复杂审批、计费或完整数据治理平台。

## 完成时应看见的证据

用户通过对话登记一个真实可用的实验调用方；画布显示明确授权；独立客户端实际读到允许的对象，并被阻止读取范围外内容。关系或证据入口不能绕开限制。调用记录和撤销结果在第四页可查看。仅画出调用方卡片、生成 API Key 或展示模拟日志都不能算完成。

## 本次实现约定

沿已定的真实 HTTP 验收边界推进 T007-01/02。管理接口与消费接口同处本地服务但分别鉴权：管理端使用本机启动链接交付的管理凭据和浏览器会话，消费端 `/v1/objects` 只接受调用方 Bearer 凭据。首次本机管理链接的凭据片段读取后从地址移除，合法请求建立 HttpOnly 管理会话；管理凭据和调用方密钥不发给模型。

对象编号 `$id` 也属于显式授权字段；关系仅在两端类型及关联字段都获授权时开放。首轮不开消费方原文、证据、统计与业务方法入口。新授权由对话产生草稿，再由用户对具体版本启用；停用立即失效。第四页可随时查看，采用本体本身不自动授权。


| 入口 | 实际行为 |
|---|---|
| `consumer_propose` 领域工具 | 按已采用本体保存名称、用途与明确字段/关系草稿，无签发或撤销能力 |
| `POST /api/consumers/activate` | 管理端确认当前草稿版本后启用，完整 API Key 仅随该次响应交付 |
| `POST /api/consumers/revoke` | 管理端停用调用方，后续消费请求逐次检查最新状态 |
| `GET /v1/objects` | 调用方凭据鉴权，支持授权范围内的对象、指定字段、关系与分页读取 |
| `GET /api/canvas?page=consumption` | 管理端读取第四页、当前调用方与最近真实访问记录 |

消费授权绑定本体和来源版本，调用方使用明确的类型及字段清单；对象编号 `$id` 需要显式加入，关系两端类型及连接字段也必须获授权。管理端查看原文与对象证据的能力不随消费凭据开放。首轮消费接口不支持写入、任意过滤、统计或业务方法。

## 来源侧使用限制（FEATURE_008）

来源用途、负责人和敏感列单独保存；最新敏感分类在提出、启用、实际读取时检查，包括映射属性、编号、关系连接字段和目标输出。固定旧来源版本的授权也受约束，仍使用的历史列可以后续分类。管理界面原文查看不受消费投影限制；标记不改变原始数据版本，不自动扩大任何授权。见[维护验收](../experiment/MAINTENANCE.md)。


## 第三方 Agent 接入与持续数据（FEATURE_009）

第四页已扩展为“连接与使用企业记忆”。可查看 MCP 配置模板或 HTTP 端点，通过独立调用方凭据查询许可结构与对象。配置按需展示，客户端按自身设置格式填写路径、服务地址与凭据；不会把本机管理密钥交给外部 Agent。本次适配器在本机运行，云端 Agent 不能直接访问用户电脑上的回环地址。

采用后的本体负责稳定的业务含义，来源记录可以继续更新。消费侧默认继续使用已发布记录，管理员在第四页检查准确的资料版本变化，明确“发布给此调用方”后，同一密钥的后续请求读到新记录。发布只更新当前模型已映射的 CSV，语义文档与本体版本保持不变；字段、类型、关系含义变更回到第三页确认，不自动扩大已有权限。新来源尚未映射时也不自动成为消费内容。

每次请求在一个确定的数据版本执行。客户端可以把 `describe_memory` 返回的 `dataVersion` 用于一组查询；若期间发布新版，旧预期版本收到 409，需要重新读取结构与执行本次查询。接口不会替第三方 Agent 更新自身缓存或历史回答。HTTP 返回禁止缓存；Agent 的长期缓存仍由调用方按版本管理。

新增独立接入可复用一个已启用调用方的明确范围，先生成待确认草稿，用户再启用并取得新密钥；不会替换原调用方。该草稿从所选本体保存时的数据起步，启用后可检查并发布新资料。凭据锚定首次启用的本体与授权；数据发布只能沿用完全相同的模型和范围，停用立即失效。

检查包括映射列、非空唯一对象编号、逐行字段完整性和当前来源限制；它不保证业务事实真实或业务语义自动正确。数据接入仍以现有上传/更新为主，定时 API 同步、自动审核发布和远程部署留到后续。完整运行与验收见[Agent 接入](../experiment/AGENT_CONNECTION.md)。
