**2026-09-09 实现更新：**API/MCP 来源的实际 Agent 工具、字段映射、按需执行与第三方访问已接通，见[当前连接链路](../experiment/LIVE_MEMORY.md)。本文此前基于文件的流程作为历史设计保留。


2026-09-08，依据用户手绘草图及随后确认的产品定位。T003-04 / T005-04 已交付前三页；用户随后增加第四页“连接”，归属 FEATURE_007，现已实现并完成真实模型、浏览器和客户端的整条体验验收。本文及[消费治理设计](DATA_CONSUMPTION_DESIGN_2026-09-08.md)共同描述当前交互，替代旧工作台的三栏聊天布局与任务导航。

## 产品目的

DataEngine 用本体组织企业级记忆，通过 Agent 的协助创建这套记忆。用户交互的成果是企业信息、来源连接、定义和对象视图；这些内容构成产品页面。对话只承担创建和修改的入口。

**数据连接原则：**第二页连接企业原系统的 API/MCP，原始业务数据留在源系统，按授权按需读取；DataEngine 保存企业理解、本体定义、来源能力、映射与引用，不默认整体复制数据。第四页则向第三方 Agent/应用提供企业记忆的 API/MCP，两侧方向和权限分别管理。下表描述这一产品方向；后文文件操作及验收记录属于已实现的本地实验，来源侧连接器尚未实现。

判断一项界面元素是否保留：它是否帮助用户建立、检查或纠正当前企业记忆。默认不展示运行日志、会话/任务编号、工具名称、进度百分比、历史任务、无关解释和产品宣传。

## 四个页面

| 页面 | 起步问题 | 长期保存的内容 | 首次引导 |
|---|---|---|---|
| 企业 | 企业叫什么，主要提供什么服务？ | 企业名牌、业务与逐步补充的服务对象、目标和流程 | 名称/业务已保存即可进入资料；可围绕一个业务问题继续补充，不要求完整问卷 |
| 数据 | 哪些企业系统与资料可以支撑这个问题？ | API/MCP 来源能力、映射与引用、用途、负责人、使用限制与读取结果 | 连接授权范围内的来源并检查实际可读内容，再开始建模；当前实验以文件输入验证 |
| 本体 | 这些资料在业务上意味着什么？ | 定义、实际对象、关系与证据；业务问题的验证结果 | 定义/对象/验证三个视角，用户明确采用映射本体后才能开放消费 |
| 连接 | 谁能使用哪些记忆？ | 调用方、对象/字段/关系授权、真实调用和停用结果 | 空白也能查看，未采用本体时解释缺口；实际授权仍需明确启用 |

四页始终可以查看和往返。导航只选择当前页面、必要时停止前一页运行；不触发模型、不创建任务或伪造完成。首次创建可顺序引导，回到已完成页面做维护时不自动跳走。每页保留独立有界聊天，共享已保存的企业记忆。

现有实验支持 CSV、Markdown、TXT 文件输入，用于验证企业记忆链路。非空文档可通过 `ontology_outline` 形成有来源依据的概念草稿，草稿不会伪造记录或直接成为消费本体。有非空 CSV 后，通过现有 `ontology_propose` / `ontology_preview` 检查实际映射与对象，采用仍绑定准确候选版本。文件保存不是产品对远端数据的默认接入方式；来源 API/MCP 仍需对应连接器，本轮未实现。

### 定义、对象与验证

以下版本读取、历史回查与重验行为描述当前文件实验。远端对象应依据来源映射按需读取；源系统持续修改业务记录，DataEngine 检查本体和映射是否仍适用。连接器是否缓存、保存快照或要求发布，以及更新何时对外可见，尚待设计；来源引用不等于拥有远端历史副本，也不承诺每次查询自动实时。

第三页默认用关系图展示概念与业务对象类型，节点显示名称和对象数量，连线保留实际关系名称及方向。选中节点或关系后，侧栏展示含义、属性与来源；概念草稿与映射候选/采用版本可切换。对象视角选择一条真实记录，展开直接关联，选中邻居可继续向外查看。对象与关联均读取所选本体固定来源版本；单次图最多展示 20 个对象，超出明确提示，无关联记录不等于业务事实不存在。窄屏时图在自身范围内缩放与移动，详情排在下方。验证视角输入业务问题，由真实 Agent 将意图转为受限对象方法并通过 `ontology_verify` 保存实际结果、覆盖范围、模型/来源版本与证据。结果不会由模型直接写成“通过”。用户可标记符合预期或需要调整，该判断与程序结果分别保存。

每次从验证输入发起检查，明确使用最新资料；普通对象追问保持当前调查快照。旧验证结果和依据不变；来源更新后可以重验并比较。新增事实不自动重写定义，业务含义变化再讨论新的本体候选。消费授权仍使用其固定模型/来源版本，新验证不会自动扩大或升级外部授权。

### 持续维护与资料安全

画布从实际保存的来源、企业陈述、本体、验证与页面待确认状态推导必要提醒，涵盖坏/空来源、未整理来源、资料更新、企业冲突、候选与验证判断。提醒独立于聊天裁剪。用户直接保存企业陈述可解决该字段冲突，历史不同说法仍保留。验证按同一问题的不可变执行序号取最近一次待办，审核旧结果不会把旧待办变成最新。

来源详情可直接填写用途/负责人和标记限制对外使用的 CSV 列。这些信息单独保存，不改变原始数据版本。敏感列通过业务字段映射在授权提出、启用、实际访问时检查；对象身份及关系连接字段同样受限。历史授权还在使用的旧列也能标记，已启用调用方随最新分类收紧。无标注不等于自动识别安全；文档原文本来就不向消费 API 开放。

## 画面与对话

整屏为黑白画布，不把草图的外框做成额外的大边框。空白时保持留白、一句当前引导及底部输入框。有内容后，企业信息、资料或本体成为画面的主体。

画布从导航下方延伸到屏幕底部；对话和输入框属于前景浮层，与背景按前后层次叠放，不占独立的底部布局行。底部居中一个输入框，内含发送，以及实际运行中的停止。前三页保留资料入口；连接页隐藏上传，资料仍从数据页接入。模型连接放在小型设置入口。没有虚假的语音按钮或尚未接入的能力入口。

输入框上方只显示最近少量对话，越往上越淡直至消失。浮层容器和对话区域透明，只有输入及相关操作接收点击，透明部分的点击与滚动传给背景画布。对话区域有固定高度上限，不能随历史增长挤压画布。用户点击、键盘查看或滚动画布时，近期对话淡出，避免文字重叠；重新聚焦输入框或发起对话时恢复。待确认信息仍留在画布。非空内容末尾保留可滚动的留白，随浮层实际高度调整，最后一项也能滚到输入框上方查看；空态不加入这段留白。用户主动打开的原文、实例或验证详情可占据画布，此时保留清楚的返回入口。精确修改用直接编辑、勾选、确认等小型操作，不要求所有事情都通过聊天完成。

每页只有一份交互上下文。不显示“新建任务”、历史对话列表或可切换的多个 Agent。用户切回页面时继续该页，不额外创建用户可见会话。

## 连接画布

连接空白时询问哪些应用需要使用企业记忆。有草稿后，画布呈现“企业记忆 → 调用方”的连接，卡片显示名称、用途、对象范围和授权状态。点开调用方才展开具体字段、关系、接入方式与最近真实调用。

Agent 只提出草稿；待确认草稿的具体版本上显示“启用访问”。用户启用后，调用方 API Key 只在独立窗口交付一次，关闭即清空。已启用调用方显示“停用访问”，旧凭据立即失效；调整范围通过对话重新整理并确认。页面不模拟请求或访问统计。

管理页面首次使用本机启动链接；地址中的管理凭据片段读取后移除，合法请求建立浏览器管理会话。消费方使用自己的 Bearer 凭据调用独立只读接口，不能利用管理预览接口获取完整记忆。

## 对话寿命与企业记忆

页面原始聊天使用明确的数量和长度上限，超出时移除最早内容。真实模型输入采用同样的有界页面上下文，不只在界面隐藏旧消息、却继续让 SDK 累积历史。每轮从这份上下文与当前企业记忆构造执行输入；KodaX 的执行会话是内部细节。

公司、资料、本体及已经保存的用户陈述不会随旧聊天裁剪删除。跨页读取已经建立的企业记忆，不把上一页完整聊天复制过去。用户陈述的引用原话保留在已保存的事实中，供必要时核查。

内部继续保留现有的执行有效性与版本检查：停止或换页后旧运行的迟到写入不能覆盖新工作；模型说“完成”不等于完成创建。页面推进只依据真实保存、程序检查和当前阶段完成动作。仅收到数据或者建出未经检查的候选，不触发正式本体采用。

## 实现与验收边界

复用当前 KodaX SDK、来源解析、企业记忆和本体对象工作区。前端根据实际结构化成果形成页面，模型不能把任意 HTML 或脚本当作已经创建的企业记忆。原来的报告/任务 API 可以为历史数据保留，但不成为新产品流程入口。

沿已有的“用户输入 → 真实工具执行 → 已保存成果 → 再次打开”公共边界检查：

- 从空白企业输入实际信息，画布出现企业名牌与信息；只在条件满足后自动进入数据页。
- 从数据页上传实际资料，看到来源与内容；文档能开始概念草稿，坏/空文件有清楚缺口，不能推动假完成。
- 从本体页创建、预览并决定具体候选，看到真实关系、实例与证据。
- 一页一份上下文；跨页不串用原始聊天；旧消息裁剪后企业信息仍在。
- 最近对话向上淡出，长对话不遮挡画布；没有任务列表、历史聊天栏、报告和更新页。
- 暂停、换页、重开和失败保留真实成果，明确候选采用仍遵循版本检查。
- 连接页通过对话提出范围，用户确认后真实读取；未授权的字段、关系与管理入口被拒绝，页面出现真实访问记录。
- 停用后下一次调用失败，密钥不进入模型、聊天或访问日志。消费链实测见[运行与验收](../experiment/CONSUMPTION.md)。

自动检查覆盖状态/数据契约，浏览器检查实际画布、淡出和输入交互，真实模型检查语义工具和页面推进。无需新增完整平台或通用页面生成引擎。

四页维护与验证的本轮结果见[维护验收](../experiment/MAINTENANCE.md)，票状态归属 FEATURE_008。


## 第四页的接入与数据发布

“连接与使用企业记忆”画布展示企业记忆 → MCP / HTTP API → 调用方，启用中的调用方优先，已停用接入简略保留。点击调用方后查看接入配置、已发布数据及许可内容；技术参数只在配置展开后出现。新 Agent 可以复用已确认范围创建独立的待启用草稿，单独交付凭据。

当前文件实验的“检查数据更新”显示哪些映射资料由哪个版本变为哪个版本；确认发布给当前调用方后，后续请求读取新数据。模型与权限保持不变；新字段和业务关系仍回第三页确认。这项实现不预先决定远端 API/MCP 的缓存或发布策略。资料更新、配置展开和来源版本说明不会新增一页，也不引入任务或历史对话管理。
