# Data Engine 语义与操作契约

日期：2026-09-11 更新。最新三页与具体实施范围见[三页产品计划](THREE_PAGE_PLAN.md)。

本文细化[产品与架构设计](DATA_ENGINE_DESIGN.md)中的共识，供后续 Agent 设计和实现具体 Feature 时使用；界面协作见[Agent 与前端设计](AGENT_UI_DESIGN.md)。
它是设计提案，不是现有 API 文档。文中字段名、枚举、函数名及 JSON 均为**建议或示意，需对应 Feature 定稿**，不据此自动增加实现范围。
当前在线能力及限制以[运行与验收记录](experiment/LIVE_MEMORY.md)和实际实现为准；新增能力只有在实现、开放和验证后才能标为可用。

## 0.2.0 构建与发布对象

`engine_build` 是可中断的工作任务，`engine_dataset` 是有界来源轮廓，`engine_candidate` 是带输入版本/覆盖/问题的候选，均不等同于已发布数据。采用时复核当前来源、基础版本和映射基线，并原子保存基础定义与执行映射；稳定概念ID不随显示名称改变。已有待审语义修订时自动更新不得代替人的采用决定。

`data_release` 不可变地引用已采用基础/映射及对外契约，发布检查绑定输入hash；`release_connection` 是独立授权主体，升级明确选择目标发布且不扩张旧许可。历史定义可用不代表历史事实快照；来源当前授权始终有效。外部委托任务绑定接入方及数据集版本，查询结果、历史读取和幂等重放都不能绕过撤销。


## 1. 共同契约解决什么

先定义 AI 可理解的业务对象世界，再把同一对象与操作投射给人类治理界面。
人、内部治理 Agent、外部消费 Agent 共享对象身份、业务含义和操作规则，各自得到适合任务且获准的内容。
前端业务按钮和 Agent 方法应进入共同领域服务；缩放、滚动、面板位置等展示动作由界面自行管理。
底层本体可以是图，当前视图可以是树或列表；不能因界面层次而改变业务关系或对象身份。
契约与传输、存储、编程语言解耦；第一版不要求完整 OWL、通用规则引擎、全量复制或任意代码执行。
KodaX 继续承担内部 Agent 循环；借鉴 NOOA 的对象发现与有类型方法，不由每次对象查询再启动一轮治理 Agent。

## 2. 业务对象与治理启动对象

| 对象类别 | 负责表达 | 生命周期与消费边界 |
|---|---|---|
| 业务定义 | 类型、属性、关系、身份规则、业务口径和约束 | 候选与已采用定义分开；正式业务接口绑定明确语义版本 |
| 业务实例 | 某条投诉、某栋楼及其属性、关系 | 按来源和映射解析；实例更新不自动修改类型定义 |
| 来源连接 | 已批准来源能力、使用限制、契约及检查结果 | 无业务本体时即可存在；凭据和内部地址不进入消费描述 |
| 建模草稿 | 企业理解、候选类型、映射、问题和样本检查引用 | 可以反复修订；候选实例预览必须标明其未采用状态 |
| 变更与决定 | 修改目标、原依据、候选差异、检查、采用决定和结果 | 从提议到保存、采用分别记录；不因聊天宣称完成而推进 |
| 查询或检查结果 | 一次有界读取、聚合、验证的实际结果 | 引用输入、版本、范围和时间；保留策略独立于聊天历史 |

空白企业从来源、企业认知与建模草稿开始，不需要先虚构一套正式业务类型才能操作。
业务对象与治理对象可以互相引用，但修改“投诉类型定义”与修改“投诉 TS002 的关联断言”必须是不同目标。
未实现的业务方法可以记录为待建设需求，不能出现在可执行能力目录里；描述存在不等于实现存在。

## 3. ObjectRef 与身份解析

T012-02 当前已实现在线本体的类型、属性、关系与实例引用；实际字段见[协作契约](AGENT_UI_DESIGN.md#2-消息固定的-workcontext)。以下包含后续断言与独立版本的目标，不能直接作为已实现接口。

建议 `ObjectRef` 至少区分企业空间、对象种类、稳定标识；访问某一修订时附带明确版本条件。
稳定业务标识不采用内存地址、DOM 节点编号、列表序号或显示名称；这些标识可以变化且不能跨客户端解释。
类型定义、关系定义、实例、断言、来源、草稿、变更和结果应能区分引用种类，具体枚举在 Feature 中收敛。
同一实例出现在图、表格和详情时共用领域引用；展示节点另有界面标识，不创建重复企业对象。
来源 ID 与业务 ID 的映射规则需要可解释；跨源同名对象不能直接认定为同一对象。
合并或拆分身份应记录前后引用和迁移关系，历史结果不能被静默改指到另一个实体。
服务端解析引用时检查空间、种类、版本和当前授权；客户端传入的引用描述不是可信事实。
引用可被重新定位不保证旧值可重现；历史来源已不可用时明确返回无法重现及可披露原因。

## 4. 属性、关系与断言

类型的属性定义描述含义、值类型、单位、可用状态及适用约束；实例属性提供某一时点的值或未知状态。
关系定义描述端点类型、方向、成立条件及适用约束；关系实例说明具体哪些对象按何种依据相连。
建议用断言定位一项可查证陈述：主体引用、属性或关系引用、值或目标引用，以及该陈述的依据与状态。
每项属性和关系可有独立来源及有效时间；不能只在整个对象上附一个来源标签后暗示所有字段同源。
同一属性可以同时保留源值、人工纠正和推导值；当前业务视图应说明采用哪一项及采用规则。
存在冲突时保留冲突与支持依据；不默认取最新文本、最高模型置信度或一次点击结果覆盖所有其他记录。
缺字段、未知、未接入、关联失败、无权读取、来源失败和业务上的否定是不同情况。
空数组只描述本次返回没有条目；只有覆盖范围和明确的业务规则允许时，才据此作否定结论。
关系图有环不一概错误；是否禁止取决于业务含义、约束和实际推理或验证器支持。

## 5. 证据、有效时间与解释

建议证据最小引用可定位到来源、记录及字段/片段，附实际读取时间和来源提供的版本信息。
关系证据还应能说明端点身份及关联依据；计算结果引用输入、采用规则和实际方法版本。
有效时间表示陈述适用于业务世界的时间；读取时间表示何时观察到它，二者不能互相替代。
人工补充或纠正记录责任主体、理由、适用条件与有效范围；原始来源及先前陈述继续可追溯。
纠正依赖的源记录变化后重新检查适用性；不能让一次局部修正永久覆盖所有未来读取。
解释分别回答“含义是什么”“依据来自哪里”“结果如何由已知输入计算”，不要求暴露模型内部思维过程。
自然语言解释只是这些依据的呈现；没有证据时不能由模型补写一段说明冒充可核验出处。
证据与对象同样受权限控制；对外可提供获准摘要或不透明引用，不泄露内部地址、凭据或受限字段。
无法披露详细限制时返回适当的受限状态；不能通过错误、关系目标、计数或取证接口绕过授权。
优先按需解析和保留最小引用；为复盘保存证据快照须明确用途、保留期限和权限，不默认复制整个企业。

以下是**建议的关系断言返回片段**，为合法 JSON 示意，不是完整 schema，也不代表该接口已开放：

```json
{
  "ref": {"spaceId": "heating-demo", "kind": "assertion", "id": "a-42"},
  "subject": {"kind": "instance", "id": "complaint:TS002"},
  "predicate": "complaint.belongsToBuilding",
  "target": {"kind": "instance", "id": "building:B03"},
  "status": "source-derived",
  "versions": {"semantic": "s3", "mapping": "m2"},
  "evidence": [{
    "ref": "evidence:e7",
    "recordRef": "source-record:r19",
    "field": "buildingCode",
    "readAt": "2026-09-10T02:00:00Z"
  }],
  "validTime": {"status": "unknown"},
  "history": {"reproducible": false, "reason": "source-history-unavailable"}
}
```

## 6. 版本与读取一致性

| 建议区分的版本维度 | 描述什么 | 不应被误认为 |
|---|---|---|
| 语义版本 | 企业采用的类型、关系、口径与身份规则 | 当前所有源记录的统一快照 |
| 映射版本 | 业务字段和关系如何解析来源能力 | 语义定义本身或源数据版本 |
| 来源读取信息 | 每个来源的读取时刻、源版本或快照标识 | 没有来源支持也能历史回放 |
| 方法版本 | 参数/返回契约及实际计算或检查实现 | 同名方法永远行为相同 |
| 权限修订 | 当前有效许可和撤销状态 | 固定旧语义可绕过最新撤销 |
| 工作上下文修订 | 发送消息时的选择、筛选、视图和草稿引用 | 企业长期事实或修改授权 |

各维度的 ID 格式和存储可以简化，但含义及失效条件必须分开说明，不合并成一个含糊的“最新版本”。
查询记录实际使用的版本组合；修改绑定相应基础版本，提交时检测冲突。
跨源按需读取记录各来源读取时间，明确一致性级别；未获得共同快照时不承诺原子一致。
现有文件消费的 `dataVersion` 与在线消费的 `readAt` 含义不同；不能把文件回放能力直接承诺给在线来源。

## 7. 动作描述与共享执行

建议操作描述包含稳定操作标识、目标种类、业务说明、参数/返回契约、实际实现绑定及前置条件。
区分读取、生成候选、检查、采用与源写回等实际效果；具体分类由 Feature 定稿，不只按 HTTP 动词判断。
动作目录可以提供当前可用性及可披露原因，服务端仍在执行时重新检查；隐藏方法不是授权机制。
前端与 Agent 使用同一个业务动作，不要求其操作表面完全相同；如表单和对象方法可传入同一修改命令。
方法实现、参数约束、输入规模、超时、取消、返回说明及授权范围被验证后，才可登记为可调用。
关键操作同时声明前置条件、实际效果、后置条件及完成依据。例如采用修订前检查候选/基础版本/有效决定，执行后返回真实新版本与变更记录；“已保存草稿”不等于“已采用”。规则校验调用已实现代码，模型生成候选不具有确定性规则的地位。
Harness 的调用前后和结束检查复用共同领域服务。受限组合或 CodeAct 一次外层调用内可能有多个对象操作，各操作仍单独执行校验；UI 和外部入口也不能绕过。需阻断写入的条件在提交前或事务内检查，后置发现错误不能自动撤回外部副作用。
推导规则与有副作用的动作分开；规则校验通过不代表外部写入成功，类型正确不代表业务陈述真实。
停止、确认和采用等责任边界由服务落实；模型不能通过自填 `approved` 或宣称“用户同意”产生授权。

## 8. 有界发现、动态接口与 SDK

建议能力族为发现/描述、查询/展开、解释/取证、已登记计算、治理提议与检查；不是新增端点清单。
初次发现只给任务相关且获准的目录摘要，详细类型、关系与方法按引用展开；不向模型默认发送全企业定义。
描述与数据查询都设置返回规模和深度，提供分页及明确的完整性信息；大规模统计由已验证实现执行。
动态描述、SDK 类型、工具说明和基础表单元数据由同一契约来源派生，避免手工维护多套冲突定义。
语义共源不要求自动生成完整页面；信息层级、图布局和差异展示仍需人类体验设计。
动态客户端声明所用契约版本；静态 SDK 需要生成、发布和客户端升级，不会因 schema 改变而自动更新部署。
新定义采用时检查查询行为、方法绑定和已授权消费者兼容性；新增字段与关系不能静默扩大旧许可。
远端边界传稳定引用、参数与结构化回执；SDK 对象只是代理，不传服务进程内对象地址或任意可执行对象。
未实现的分页方式、解释、计算与 SDK 生成功能只能写在提案中；必须结合当前连接器能力给出限制。

## 9. 查询回执

建议查询回执包含结果引用、所用查询条件、对象或断言、有界覆盖范围、各类版本与读取一致性。
覆盖范围至少回答返回多少、是否还有后续、总量是否已知、过滤实际是否执行、是否有来源失败或局部结果。
完整性必须相对于明确范围表达；未返回完整企业数据不等于失败，局部结果也不能被标为全量。
方法或聚合结果还应记录实际输入范围及实现版本，不让 Agent 根据某一页数据声称完成全量统计。
查询不能调用模型后把猜测补入来源值；可选生成解释时须分开标记并引用真实结果。
空结果、权限拒绝、来源不可用、版本冲突及契约不兼容分别处理；错误信息的细节遵循披露权限。
当前在线对外接口主要是 `/v2/schema` 和 `/v2/objects`；完整断言、解释和证据回执属于待设计能力。

## 10. 变更类型与变更回执

| 变化 | 建议处理 | 边界 |
|---|---|---|
| 来源事实变化 | 按既有映射重读并记录时间 | 不自动产生新语义定义 |
| 局部事实或关系纠正 | 保留原值，新增有依据、有效范围和责任主体的纠正 | 不默认替换整个对象或修改全局规则 |
| 关系规则、身份或业务口径修改 | 候选、检查、影响、决定、采用及兼容处理 | 影响预览说明抽样、未知和未覆盖范围 |
| 源系统写回 | 独立批准的来源能力及执行流程 | 当前只读 HTTP/MCP 来源不支持，不能冒充本地纠正 |

建议变更回执区分提议已保存、检查通过、已采用、冲突、取消及失败；状态不应仅由模型文本决定。
回执说明实际修改范围、原版本、新版本、决定或授权依据、验证结果与已知未完成项。
需要人工决定时绑定具体候选和检查版本；内容改变使旧决定失效，同一明确决定无需无理由反复确认。
人工治理不等于所有写操作逐次人审；按已有授权、修改影响和可逆性确定路径，不能由 Agent 自行扩大范围。

以下是**建议的变更冲突回执片段**，为合法 JSON 示意；`applied: false` 明确本次没有采用修改：

```json
{
  "operationId": "op-81",
  "changeRef": {"kind": "change", "id": "change-42"},
  "status": "conflict",
  "applied": false,
  "expectedVersions": {"semantic": "s3", "mapping": "m2"},
  "currentVersions": {"semantic": "s4", "mapping": "m2"},
  "reason": "base-semantic-version-changed",
  "nextStep": "refresh-and-review-diff"
}
```

## 11. 服务端授权、并发与取消

每次读取和执行按真实调用主体、空间、目标及当前有效许可检查；权限修订不从前端传来的布尔值推断。
字段、身份、关系端点与证据贯穿同一授权边界；撤销或来源停用后，在途结果返回前也应复核。
不将契约提案等同于已具备多租户、员工身份或记录级权限；新增维度必须有真实身份来源和验收。
写入在服务端检查基础版本并保持检查与提交的一致性；冲突时返回新旧依据，不静默覆盖他人修改。
幂等键绑定调用主体、目标、操作及请求内容；重复提交回到原回执，同键不同内容拒绝或明确冲突。
停止使运行写入资格失效，迟到工具结果不得保存；取消与提交竞态需区分“取消前已提交”和“未提交”。
操作已经提交时不能声称取消回滚成功；补偿或撤销应形成另外一项有依据的动作与回执。
T015-03 的局部关系纠正已将幂等键绑定主体、方法和规范化请求：同键同内容返回原历史回执，同键异内容拒绝；其他历史操作仍未统一改造，不能泛化此保证。
读写规模、超时与重试由执行器限制；来源能力不支持安全重试的写操作不能自动重复发送。

### 状态恢复与完成依据

企业定义/事实、治理候选和进度、临时句柄、界面选择分别保留，恢复任务先读取实际成果与回执，再按当前权限解析引用。事实更新不自动扩展本体 Schema。一次调查可因证据不足而结束，但必须保留范围与缺口；停止输出、工具成功、草稿保存和业务完成不能合并成一个状态。

第二页的内容变更与第三页消费迁移共享 changeRef；采用决定与迁移/授权分别表达。新接口来自已采用可执行子集，基础本体采用不会使所有未映射概念自动可消费。

## 12. 最小验收与继续设计

- 空白企业可操作来源和草稿；未采用类型不能伪装为正式业务消费接口。
- 图、列表和内部 Agent 针对同一关系引用发起操作；切换选择不改变已发出的目标和基础版本。
- 一项属性与一条关系具有各自出处和时间；纠正后能区分源值、纠正依据及当前有效视图。
- 独立消费客户端不开页面完成有界发现、查询和关系取证；未开放能力明确不可调用。
- 无回访、来源失败、受限证据和分页截断不被当成否定或完整结果；越权不能绕道证据接口。
- 重复提交、并发修订、撤销、停止后迟到写入产生真实回执；失败与未提交不显示成功。
- 改变语义不自动扩大旧许可；改变源记录不冒充新语义；版本固定不承诺不存在的远端历史。

后续 Feature 明确选用的字段、操作、持久化与开放范围，再在在线来源链路验证；本文不登记功能状态或替代设计块。
参考：[NOOA 对象发现](https://github.com/NVIDIA-NeMo/labs-OO-Agents/blob/ee61c9012f2e4135eabba1e5db80c8e991a88184/docs/concepts/tools-and-visibility.md)、[W3C SHACL](https://www.w3.org/TR/shacl/)、[W3C PROV](https://www.w3.org/TR/prov-overview/)。这些资料提供设计依据，不意味着已实现完整标准或框架。

## T013-01 基础本体的当前实现

`foundation` 是企业空间内独立的版本化成果，包含企业身份、稳定概念/关系 ID、原话证据与未决项；与旧 `ontology_outline`、`ontology`、`live_ontology` 分开。当前候选和仍有效的已采用版本并存，采用只确认语义含义，定义保存时没有执行映射；T014-03 已按当前执行子集动态投影概念/关系绑定状态。UI 与 Agent 调用同一基础领域服务；完整字段、增量合并、名称纠正、采用与边界见[实际接口](COMPANY_FOUNDATION_SKILL.md#10-t013-01-实际接口)。基础成果整体可绑定消息；成员级选择按 T015 实施，正式映射见本文 T014-03 合同。


### 基础定义的文档证据

已实现的 `foundation` 允许用户陈述和文档片段两类依据。文档证据固定来源 ID、版本、哈希、位置与实际读取时间；采用检查绑定已经读取引用的版本，历史引文不随来源更新漂移。引用校验不等于业务真实性；文档证据本身不构成来源映射，执行绑定状态由 T014-03 单独投影。完整当前合同见[基础方法接口](COMPANY_FOUNDATION_SKILL.md#11-t013-02-文档证据扩展)。


T013-03 追加 `kind:"web"` 的外部陈述依据：研究身份、实际 URL、读取时间、正文位置、覆盖与读取片段快照由宿主绑定。固定片段可核查不表示网页永远最新；网页不参与上传文件的本地版本推进检查。候选沿用相同概念身份和人工冲突决定，具体字段只在[基础方法契约](COMPANY_FOUNDATION_SKILL.md#12-t013-03-公开网页证据)维护。

## T014-01 知识来源与片段证据（已接入合同）

内容类型与传输分别声明：每项来源能力增加 `contentKind: records | knowledge`，旧配置缺省为 records；连接的 `protocol: http | mcp` 沿用原合同。上传资料仍保留在文件目录。`source_catalog {offset?,limit?}` / 管理接口 `POST /api/live/catalog` 返回同一分页中的 files 与 connections，默认20、最多50项，coverage 含 nextOffset；不将原始正文装入目录。

首轮知识适配为**同一获准只读能力的精确查询与片段读取**。HTTP 使用声明的 GET 路径，MCP 使用批准工具及连接时的输入 Schema 摘要。片段行必须含字符串身份字段（默认示例 id）及 `documentId/title/revision/text`，title/身份/revision 不超过500字符，正文为有效文本且最多16000 UTF-16字符。身份过滤和总数路径必须配置，分页参数不得与过滤冲突。长文由上游先分段；不提供通用厂商知识库抓取、全文检索或自动 PDF 解析。

```json
{
  "name": "documents",
  "contentKind": "knowledge",
  "path": "/documents",
  "fields": ["id", "documentId", "title", "revision", "text"],
  "idField": "id",
  "filters": {"id": "id", "documentId": "documentId"},
  "itemsPath": "items",
  "totalPath": "total"
}
```

- `knowledge_query {sourceId,capability,connectionVersion?,where?,offset?,limit?}`：仅接受 filters 中的精确过滤，默认5、最多10片段。实际响应逐行检查过滤、字段、身份和分页，返回 segmentId/documentId/title/revision 与查询覆盖、实际 readAt。正文不进入 Agent 的目录结果；当前适配在受限网络响应中取得片段行后投影目录，不宣称上游只传元数据。无 total 只能报告覆盖未知。
- `knowledge_read {sourceId,capability,connectionVersion?,segmentId,revision,offset?,limit?}`：按片段身份过滤，必须返回且总数为1。目录 revision 与读取时不一致则拒绝；默认4000、最多6000字符，nextOffset 相对当前片段，完整也只代表该片段。每轮最多40次知识查询/读取，读取字符预算40000，预算在 I/O 前预留。网络单次最多2 MB、12秒，失败不给替代数据。
- 两个管理预览接口为 `POST /api/live/knowledge/query` 与 `/api/live/knowledge/read`，共用 KnowledgeReader 与 SourceConnections，仍要求本地管理员身份。页面预览回执不能作为 Agent 本轮引文，Agent 必须实际重读。
- 新证据输入 `{id,kind:"knowledge",readId,quote}`。readId 由当前运行产生，quote 必须唯一匹配已返回片段。宿主保存连接版本、能力、文档和片段身份、来源 revision、实际读取时间、正文哈希、读取覆盖与最多6000字符快照。validTime 为 unknown；读取时间不冒充业务生效时间。
- 基础本体引用知识证据后仍是未绑定定义，不把文档行当业务对象。常规成果投影隐藏快照；管理员按 evidenceId 查看实际保存片段。来源后来停用也可审查旧依据，界面明确显示连接当前状态及“读取时快照”，不保证远端当前内容或完整历史。
- 读取前后及引用时检查授权和连接版本；采用检查当前仍被概念/关系/企业/未决项引用的知识来源。已经保存但不再使用的历史证据不阻止替换来源后的采用。采用不会联网检查全部远端文档的新鲜度；远端不更新 revision 时无法仅靠该字段保证内容不变。

知识材料是外部陈述，正文中的指令不授予操作权限。沿稳定概念身份补充时保留前后含义、双方依据与冲突，仍由新用户决定解决。该票没有修改对外消费协议、开放知识快照给其他 Agent 或实现自动本体演变。

## T014-02 BI 指标定义与观测

新增 `contentKind: metrics`，每项获准能力声明一个 `metricId`，协议仍为 HTTP GET / MCP Streamable HTTP。例：`{name:"metrics",path:"/metrics",contentKind:"metrics",metricId:"resolution_rate"}`。字段/过滤/总数不套用记录映射；指标不可通过 `live_read` 或映射为业务明细。配置来源仍由管理入口完成，Agent 只能调用获准能力。

### 上游适配合同

同一只读能力接受两种 operation。HTTP 用声明路径上的查询参数，`where` 为 JSON 字符串；MCP 参数中的 where 为对象。不是任意 BI SQL 或通用厂商连接器。

- `describe` 请求为 `{operation:"describe",metricId}`，返回 `{definition}`。
- definition 为 `{id,name,description,revision,unit,grain,timeZone,dimensions:[{name,label}],aggregation:{kind,additiveDimensions,timeAdditive}}`。id 必须等于配置的 metricId。grain 首轮支持 day/month，timeZone 是运行时认可的时区标识（包括固定偏移）；维度最多10个，名称唯一，值在观测中为字符串；定义、可加总维度、过滤与观测均拒绝保留名 `__proto__`，避免解析时静默丢失筛选。
- aggregation.kind 为 sum/ratio/average/distinct_count/snapshot；可加总维度必须在声明维度内。ratio/average/distinct_count 不得声明可直接跨维度或期间加总，snapshot 不得跨期间加总。此处校验规则的一致性，不代替业务口径审核，也不执行跨行合计。
- `query` 请求为 `{operation:"query",metricId,start,end,where,offset,limit}`；响应 `{definition,query,items,coverage:{total,dataComplete}}`，query 回显除 operation 以外的全部查询参数。total 为非负整数或 null，dataComplete 为 boolean 或 null，是**来源对数据覆盖的声明**。
- 每项观测含 dimensions（必须与定义维度集合一致）、periodStart、periodEnd、status、value。observed 的 value 必须为有限数字；missing 必须 value=null 且带 missingReason。零与缺失不同，空结果不表示指标为零。
- start/end 是指标时区的日历日期，左闭右开，跨度最多366天；月粒度两端必须为月首。每条观测必须对应恰好一日或一月，落在请求范围，符合精确维度过滤；同一维度与期间不能在当前页重复。首轮不支持小时/季度、任意时间窗口、数值维度或自动单位换算。

### 人与 Agent 的共同接口

`metric_describe {sourceId,capability,connectionVersion}` 实际读取定义，返回 definitionHash 和来源/连接版本/实际 readAt。`metric_query` 除这些定位字段外要求 `{definitionHash,start,end,where?,offset?,limit?}`，默认20、最多50项。

每次 query 先重新读取定义并核对 hash、维度和粒度，才发出观测查询；观测响应携带的定义再次核对，覆盖两次读取之间的口径变化。名称、口径、单位、维度、粒度、时区、可加总性或 revision 变化都会导致重新检查，不静默延用旧定义。读取前后检查来源有效性；运行中停止后不交付迟到结果，也不从已完成定义读取继续发起第二次观测请求。

回执为 `kind:metric_observations`，有 readId、definition、definitionHash、实际 query、逐项 observationId、coverage 与 provenance。observationId 根据来源/能力/定义/维度/期间确定；数值更新不改变同一定义下的定位身份，readId 和 readAt 区分读取时点。这不是持久观测库或来源历史快照，跨页也不保证数据原子一致。

coverage 区分**查询结果分页完整性** complete 与 **来源数据覆盖** dataComplete；当前页出现 missing 会将 dataComplete 降为 false。总数未知的非空页允许按 offset+shown 续读，直到空页；结束也不把未知总数标为完整。每轮最多40次来源操作，describe消耗1次、query包含重读定义与读结果共2次；单次网络最多2 MB、12秒。

管理预览使用 `POST /api/live/metrics/describe` 与 `/api/live/metrics/query`，共用 MetricReader，要求本地管理员身份。页面展示实际定义、维度、日期、数值单位、可加总规则、缺失原因和读取时点，不自行合计。当前不将指标 readId 当作 foundation 文档证据，不新增对外指标消费；共同跨源取证已由 T014-05 接入，见下节。

## T014-03 基础概念与业务执行子集

基础定义和执行映射继续分别保存；不复制概念建第二套语义。现有 `live_propose` / `POST /api/live/propose` 增加 `foundationRef:{id,version}`，引用已采用基础本体；`baseModelRef:{id,version}|null` 引用用户或 Agent 实际看到的当前已采用执行子集，没有时显式传 null。基础已存在时不允许绕过概念引用再创建独立新映射；历史未绑定模型仍可查询。

- types 在原有来源/能力/fields 之外携带 conceptId，name/description 与已采用概念一致；关系携带 relationId，名称及 from/to 类型对应基础关系的概念端点。一个概念首轮只映射一个主来源，关系两端都在当前执行子集内。
- fields 为业务属性名→实际源字段；对象 `$id` 来自获准来源 idField。仅 records 能力可绑定，知识片段与指标拒绝。业务属性语义由用户/Agent依据任务核对，字段存在及结构校验不保证语义真实。
- live_propose 提交完整执行子集；新增绑定时保留仍需使用的现有类型与关系。执行基线在实际读源前后校验，旧页面不能覆盖另一页面刚采用的映射。候选持久化映射、来源版本和检查摘要，不保存全量记录。
- 保存时每种类型读取最多3条实际记录，检查获准字段、身份、分页及关系目标过滤能力；采用时再次读源，绑定候选必须仍有实际记录。基础、连接和执行基线在 I/O 前后检查；检查范围只限样本，不声明全局身份唯一或全量数据质量通过。
- `live_query {modelId,modelVersion?,conceptId|type,id?,relation?,fields?,where?,offset?,limit?}` 与管理 `/api/live/query` 仍共用 LiveMemory。候选查询是预览。绑定查询返回 `conceptRef:{foundationId,foundationVersion,conceptId}`、对象 `$id`（字段选择允许时）、读取时间、覆盖；关系遍历返回目标概念引用。实例仍按需从来源读取，不建立原始记录副本或跨源原子快照。
- foundation_read / 画布投影为概念与关系附加 bindings、mappingStatus；只将当前已采用执行子集计入 bound，候选单独展示，过期候选带不可用原因。移出当前执行子集后概念仍保留为 unbound。历史已采用映射为既有固定版本消费者保留，不冒充当前主绑定。
- 新基础草稿不改变仍有效的已采用版本；采用新基础版本后，旧版本绑定的查询、采用和消费检查均拒绝，需按新基础版本重新检查。首轮保守按整份基础版本失效，尚未做逐概念兼容性迁移。
- Agent 的 task_ask 可用 candidateId/version 绑定 live_ontology 候选；企业与数据、本体工作区均可按具体版本决定。自然语言“采用这版”和页面采用进入同一 live.adopt 路径，实际来源检查后，采用结果、消息回执、进度与待决定状态在同一同步事务内提交；来源或存储失败不消耗“采用这版”的消息回执，可用同一消息标识重试。清理匹配的待决定目标；Agent 没有直接采用或授权外部消费工具。

界面在概念下提供主来源选择、业务属性命名、映射依据、检查保存、候选预览及采用；关系映射本轮由 Agent/已有接口构建，页面显示其真实状态。未经映射的概念、关系和未决项继续治理。T014-04 已增加多源属性融合和逐字段冲突（见下节）；共同文档/指标证据由 T014-05 取证记录承载。

## T014-04 同实体多源属性融合

在现有 type 上增加可选 `supplements`，最多3项；旧模型无此字段仍走原路径。每项为 `{name,sourceId,capability,match:{primaryField,sourceField},fields,rationale}`。主来源枚举对象并决定 `$id`，附记录源仅按明确业务键补属性；匹配起点是主属性或 `$id`，终点必须支持已授权精确过滤。知识与指标不能充当同实体明细。类型合并后最多100属性，映射不自动推断语义、转换单位或转换身份类型。

- 保存/采用实际读取主来源样本及附来源，记录匹配状态、覆盖、读取时间，保存来源契约版本；不持久化原始对象集合。失败来源不能完成检查/采用；已发现的缺失、歧义、未知或冲突可保留并由人核对规则。采用规则不表示所有属性真实一致。
- 查询每页最多20个主对象，最多40次附来源读取、4个并发；每个业务键最多返回2行，用匹配范围完整性判定。唯一且完整才贡献附源值；总数>1或多行是歧义；总数未知或分页不完整不得判唯一。缺失键不请求来源，预算耗尽显示未知，可缩小主分页重新读取。
- `items` 返回业务属性；`evidence` 按对象包含 `properties` 与 `matches`。属性状态为 resolved/missing/conflict/uncertain，每个值保留 sourceId、capability、connectionVersion、recordId、field、sourceTitle、readAt 和 eligible。非唯一行仅作候选依据；不同非空有效值为冲突，失败或不确定匹配阻断重叠属性的静默回退。冲突/不确定返回 null，0保留为0。完整零匹配是缺失，不阻断已有主值。
- 字段名相同但含义/单位/期间不同必须映射成不同业务属性，不能依字段存在证明语义相同。当前不做自动消歧、值优先级或单位换算，也不构造跨源原子快照。不同来源读取时间分别保存，后续查询读取来源当前值。
- `where` 和关系端点只支持未被附来源映射的主属性，避免拿融合前值过滤后冒充完整融合查询。按 fields 按需读取相关附来源；模型依赖的连接版本/权限仍整体校验，撤销/版本变化、基础或运行失效时拒绝返回过期结果。
- 页面直接编辑、Agent live_propose/query 和上下文 context_read 使用同一映射。完整定义分开显示主/附来源；附来源属性可通过同一对象引用交给 Agent。编辑现有绑定保留映射，不可用旧源必须明确重新选择或移除。
- v2 授权可选择附来源属性，但外部只返回已授权值和逐行 `fieldStatus`，不返回内部 evidence、匹配业务键、来源记录 ID 或未授权字段；读取时间保留。旧 v1/v2 模型继续兼容，采用新映射不自动扩大消费授权。

## T014-05 文档、指标与业务对象共同取证

`evidence_bundle` 是独立的有界历史依据记录，保存一项业务问题、固定模型引用、请求范围和三类实际读取结果。它不修改基础定义、不采用映射、不扩展外部消费授权，也不是持续同步对象库。文档关联理由是业务声明，维度相等只说明按声明规则匹配；对象期间未自动核对，不保证文档适用性、语义等价或因果归因。

- `evidence_collect {question,objects,documents,metrics}` 与管理员 `POST /api/live/evidence/collect` 使用同一 EvidenceService。objects 沿 live_query，必须显式 modelVersion、fields（含 `$id`，最多20字段），每页最多10对象，支持原有对象/关系范围；拒绝保留筛选键，避免静默扩大查询。候选映射可取证，但记录明确标记候选预览。
- documents 为1–3项 knowledge_read 参数，必须 connectionVersion，再加 rationale。目录身份/版本来自实际 knowledge_query；每片段最多6000字符，保存实际文本、字符范围、文档/片段ID、revision、哈希、来源/能力/连接版本与实际读取时间。只覆盖选取片段，不声明全库完整。
- metrics 为1–3项 metric_query 参数，再加 rationale、dimensionBindings:[{dimension,property}]。必须使用已读定义哈希与明确期间；保持单位、粒度、时区、可加总规则、维度、观测/缺失、分页和数据覆盖。property 必须在对象 fields 中，dimension 必须是唯一的实际指标维度。
- 未声明 dimensionBindings 时仅作背景指标；声明后，对当前返回对象中已确定且同类型相等的属性与观测维度连接，输出 objectIds/uncertainObjectIds 和 matched/unmatched/uncertain，保留对象覆盖。未知/冲突不参与确定匹配；不能把聚合值写成个体属性，也不跨行合计或自动转换单位。匹配不证明时期相同，数据适用性仍由业务核对。
- 单项来源读取失败或返回契约不符时保存 unavailable 及请求范围，保留其他实际已读部分；来源撤销/连接版本变化、映射/基础版本或运行失效是整次致命错误，不保存迟到记录，停止后不启动后续来源读取。所有来源按当前权限读取并在保存前再次校验。
- 每个 Agent 运行最多4次共同采集，每份序列化内容最多256KB；超限需缩小范围，不能截断后声称完整。底层继承主/附查询、文档和指标的网络、分页及读取预算。原始记录仅保存本次选取字段与必要证据，不整体装载企业源。
- status=partial 表示存在来源失败、缺失、冲突、未确定、分页或数据覆盖不足；collected 仅指选取范围已读，没有“结论正确/企业全量”的含义。保存结果是依据集合，系统不自动生成业务判断。
- `evidence_list {offset?,limit?}` 最多20条有界元数据，包含 id/version/问题/时间/模型/范围状态；Agent 跨页面和新轮次先发现再读，正文不整体注入上下文。`evidence_read {id,version}` 与管理员 `POST /api/live/evidence/read` 返回历史记录及当前模型/来源可用性，来源停用后保留已授权本地管理员查看的历史依据并显式标记失效，不冒充最新读取。新取证创建新记录，不覆盖历史值。
- 企业与数据、本体工作区可从表单创建和查看；列表是相同服务的有界投影。页面始终显示来源身份、能力、连接版本和请求范围（含失败项），指标展示维度绑定。完整原文可展开，长表在容器内滚动。表单首轮每次选一个文档和指标、读取5个对象；更多来源/分页使用 Agent/接口。v1/v2 不新增文档、指标或依据包消费入口，新消费语义在 FEATURE_016 实施。

## T015-01 基础定义引用

`ObjectRef.kind` 新增 `foundation_concept` 与 `foundation_relation`。两者使用 `spaceId/id/version/member`，其中 id 是基础本体成果、member 是稳定概念或关系 ID；不得携带 type、objectId 或实例过滤。只在 `ontology.definitions` 使用，不能借此查询未映射实例。

管理 `canvas/context`、`canvas/context/read` 与 Agent `context_read` 共同解析引用。可读当前候选或仍采用的基础版本；已被取代的版本拒绝作为新选择，保留原草稿等待重新选择。写入仍沿原基础版本重验，不把查看旧采用版变成覆盖新候选的权限。

解释返回所选定义、动态映射状态、主/附来源字段、关系连接字段、相关冲突双方与证据，以及标注为整版本的未决数量和未知项。来源不可用时定义仍保留，绑定标记不可用；映射说明不保证源记录存在或业务正确。基础引用区别于在线执行类型/实例引用，前端不通过 SVG 节点序号产生领域身份。

## T015-02 具体对象属性与在线探索

`property` 引用可以携带 `objectId`，表达某个对象的具体属性；不携带时仍是属性定义。宿主沿原版本、类型、member、对象编号与范围校验。`context_read` 对具体属性仅查询 `$id` 和选中属性，保留其融合状态、对应字段证据、匹配覆盖与读取时间；不是把浏览器已读值当成当前事实，也不承诺历史回放。保留既有停止、来源有效性、旧版本及范围校验。

页内在线对象工作区复用 `/api/live/query`，每次最多20个返回对象；展开关系使用同一映射版本和起点ID，只在成功读取后画边。关系与对象分别保留查询范围及来源读取依据；起点/邻居不冒充同一时点快照。同类型自关联中本次返回包含起点时优先使用新返回对象，图表一致。短页按实际返回数量续页；未知总数非空页可继续，空页停止且不把未知覆盖标为完整。

## T015-03 当前实现：局部关系纠正

`RelationCorrections` 是管理 HTTP 与内部 Agent 的共同服务。目标是已采用执行映射的 ID/版本、起点类型/规范对象 ID、关系名；替换该起点的整个目标集合（0—20 个，空集合明确表示无关联），不修改源系统或全局映射。起点与目标须唯一存在、原关系须完整且不超过20个，来源失败或不完整不能保存为“无关系”。数字编号别名必须先解析成源返回的规范 ID。

候选保存原关系、起点/新目标读取依据、理由、提交者依据、责任主体和前一有效纠正引用。提交者文字标记为 submitted_rationale，不自动当作独立验证事实。保存读取总量上限256KB。check 生成新版本，adopt 仅允许本地管理员对具体 checked 版本确认。校验不证明业务真实；Agent 可 propose/check/cancel，无 adopt 工具。停止中的 Agent 不能迟到写入。已采用记录不能通过 cancel 回滚，后续纠正可替代它。

提交前重新检查来源指纹、模型版本、记录版本和前一有效纠正；本地原子提交新版本、替代旧纠正与操作回执。源基线包括已读取值、属性冲突依据和匹配状态，不包括易变读取时间；远端读取不是跨源事务，无法锁住外部变化。内部关系查询重新确认适用性后叠加纠正，并返回原目标/纠正引用；源变化会明确失败，不能继续静默使用旧纠正。返回完整性相对本次分页范围计算。

`relation_correction_list` 最多返回40条元数据，正文/快照用 `relation_correction_read(id, version)` 按需读取。HTTP 对应 `/api/live/corrections/list|read|propose|check|adopt|cancel`。现有外部 v2 消费仍使用原始映射关系，不自动发布内部纠正，消费迁移在 FEATURE_016 完成；当前也没有多用户审批或外部源回写能力。

## T015-04 当前实现：全局映射修订

`MappingChanges` 供管理 HTTP 与内部 Agent 共用。每次以最新已采用映射的 `baseRef:{id,version}` 修订一个已有绑定：`patch.kind=property` 指定 type/property/sourceField，省略 supplement 表示主来源，指定名称表示附来源；`kind=relation` 指定 type/relation/fromField/toField。首轮不重命名概念、删除类型、改变来源身份定义或任意重写 Schema。候选理由与依据是提交者陈述，必须与读取证据区分。

复用 `LiveMemory.prepareDefinition` 校验现有映射规则和实际样本。候选保存在 mapping_change，不生成可直接采用的 live_ontology 候选；预览定义仅作为服务内部参数，HTTP/Agent 查询不能传任意定义。管理员采用时原子生成新 live_ontology 记录、变更决定与幂等回执。新记录有新 ID、从 v1 开始，并保留 base 与 changeRef；原映射不覆盖。候选 v1、检查 v2、采用回执 v3 与新执行映射的版本分别显示。

共同引用为 `changeRef:{kind:"mapping_change",id,version}`。`read` 返回同一份内容差异和带此引用的 `impact`：contractVersion、scope、samples、summary、dependencies、dependentSupplements、localCorrections、consumption。规则差异使用结构化路径和 before/after。最多读取受影响类型首批5个起点（非统计抽样），逐个检查唯一身份；关系每起点最多20目标，结果分别保留分页覆盖。修改附来源匹配键时，样本同时比较受影响补充属性及匹配依据。依赖此属性的关系定义明确列出，但不自动逐个比较其全部实例。

证据按需保留，实际序列化差异及影响上限256KiB（界面记为256KB）。业务字段包括 readAt/attemptedAt 等名称均参与比较；只在明确读取回执位置忽略动态时间。相同样本集合仅改变来源顺序不导致失效；样本集合、属性值、冲突依据或已登记治理引用改变则拒绝沿用旧候选。来源失败不生成虚构影响。多源读取不是原子事务，不能据此保证所有企业记录或业务含义正确。

提议/检查/采用/取消都使用绑定主体、方法及请求内容的 operationId；重复请求返回原版本，同键异参拒绝。采用前重读来源与治理依据、复核当前映射及候选版本；检查不能代替人工语义判断。停止运行在源读取前后失去执行资格，不继续后续读取或保存。已采用修订不能取消为“回滚”。取消未采用记录不要求上游仍可用。

`mapping_change_issues` 按当前模型汇总已保存局部纠正：最多40组、每组20引用，给出实际组数和每组记录数。这是登记记录汇总，不是全企业异常扫描。列表最多40个修订元数据，`mapping_change_read(id,version)` 才读正文。HTTP 为 `/api/live/changes/list|read|issues|propose|check|adopt|cancel`；Agent 有相同名称的 list/read/issues/propose/check/cancel 工具，没有 adopt 工具。

原模型的局部纠正不会自动复制到新模型。`impact.consumption.status=not_evaluated` 明确第三页消费者影响尚未集成；已有授权仍固定原模型。T016-03 使用该共同 changeRef 集成真实消费者影响与迁移，本票不声称发布或迁移已完成。
