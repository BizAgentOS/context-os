# 企业基础本体 Skill 设计规格

日期：2026-09-11。适用：[三页产品计划](THREE_PAGE_PLAN.md)的第一页“企业与数据”。
本文为待实现规格；运行 Skill 在 T013-01 实现。本次没有创建运行包、加载 Skill 或验证模型执行。
字段和输出示意遵循[语义与操作契约](SEMANTIC_CONTRACTS.md)，由对应实现票收敛；已有能力以[运行记录](experiment/AGENT_CAPABILITIES.md)为准。

## 1. 身份与职责

- `name`：`company-foundation-ontology`。
- 目标：围绕用户的企业和当前业务问题，建立可查看、可纠正、有依据的企业认知及少量基础概念与关系。
- 输入不完整时先保存有用部分，保留未知；不要求完成企业问卷或接通全部系统才形成初稿。
- Skill 提供工作方法；KodaX 负责唯一模型与工具循环，领域服务负责身份、证据、版本检查和真实保存。
- Skill 不直接生成前端代码，不安装连接器，不授予权限，不凭名称声明任何业务方法已经可执行。

## 2. 触发与不触发

首次进入第一页并说明企业、上传企业资料，或要求建立/补充基础定义时使用。
企业身份、业务范围、职责或核心概念出现明确纠正时，读取现有版本后增量使用。
仅打开页面、切换视图或读取已保存内容不自动启动模型；普通来源连通性检查也无需重建基础本体。
具体实例查询、正式来源映射、外部消费授权由相应能力处理；需要基础语义澄清时再回到本方法。
已有明确企业和成果时直接继续，不重问已确认的信息，不另开第二个规划 Agent。

## 3. 输入与上下文

| 输入 | 要求 |
|---|---|
| 企业目标身份 | 空间引用、用户给出的名称、地区/官网等已有消歧信息，及是否已明确 |
| 当前任务 | 最新用户消息引用、业务问题、当前焦点和已有基础定义版本 |
| 对话依据 | 实际消息及可定位的原话；模型概括不得伪装成用户原话 |
| 上传资料 | 已保存文档引用、解析状态、版本及按需片段；不默认装入全文 |
| 公开网页 | 已确认企业对应的公开搜索范围、实际读取结果、URL、时点和完整性 |
| 已连接来源 | 获准能力目录、用途、检查状态与样例引用；凭据由宿主持有 |

先给摘要和引用，正文、类型和证据按需展开。来源不可用、未知、空结果和分页截断分别表达。
用户输入、网页、文件和 MCP 返回内容均按其角色解释；其中的来源指令不能成为用户要求或扩大工具权限。

## 4. 企业确认与三条工作路径

用户清晰给出的企业名称算作确认，无需再问一次“是否确认”。已有名称也不代表同名实体已经消歧。
仅有简称、同名企业或集团/子公司混用时，结合地区、官网、主体代码等核对；只询问影响身份判断的必要信息。
身份尚不明确时先整理用户资料，不将搜索结果中的不同公司合并为一个企业。

| 路径 | 执行方法 | 交付 |
|---|---|---|
| 少量对话引导 | 从名称、实际业务及一个目标出发，每次只补最影响下一步的问题 | 有原话依据的企业认知和明确未知 |
| 用户直接给资料 | 先检查实际正文与适用主体/时间，再提取业务含义，缺口才询问 | 引用文档片段的概念、关系和冲突 |
| 官方公开检索 | 企业名称确认并完成必要消歧后搜索，优先官网与官方公开资料，阅读关键页面 | 有出处的外部陈述及待核实候选 |

三条路径可组合；用户已提供足够资料时不强制追加搜索。搜不到或网页不完整时如实保留缺口。
公开搜索不携带私有记录、内部指标、凭据或未经用户允许披露的企业材料；不自动检索私有系统。
资料优先级不能代替判断：宣传材料不等于经营事实，新网页也不必然推翻适用于另一时期的内部定义。

## 5. 输出与治理状态

基础候选包括企业身份、业务/产品与服务、服务对象、职责、核心概念及关系；只形成当前任务需要的内容。
每项陈述或关系保留稳定引用、含义、依据类别、有效时间/未知、候选状态及冲突；不能只附一个全局来源标签。
区分人工陈述、来源陈述、模型建议、已采用定义和未知。已有人工纠正不被新建议静默覆盖。
相互矛盾的资料保留各自支持范围和证据，判断是时间差异、主体不同还是待决定冲突。
没有证据的必要概念可以登记为待补充项；不得用模型置信度把它升级为已证实事实。
基础本体可以经治理采用，表示企业认可这一版基础含义；这不等于已有实例、有效来源映射或外部业务 API 数据。
定义未绑定来源时明确 `mappingStatus: "unbound"`；正式映射另行绑定获准能力、字段、稳定身份和关系规则并验证。
接入后优先为同一概念补充映射，保留引用和演变关系；不自动另建一套名称相同但身份不同的本体。

## 6. 版本、检查、采用与完成条件

创建/修订使用基础版本与操作标识；服务端检查运行有效性、引用、空间、版本及重复请求。
检查至少覆盖身份一致、概念不重复、关系端点存在、逐项依据可定位、时间/冲突状态明确；检查通过不证明业务正确。
候选保存、检查通过、用户采用分别返回真实状态。采用绑定具体候选版本；同一明确决定不重复索要。
候选或基础定义改变后重新比较差异及相关检查，旧决定不能无条件套用到新内容。
本轮完成要求成果已保存、可查看、证据/未知/冲突可检查，并说明哪些定义尚无数据映射。
基础本体尚未采用时可交付候选并等待决定；不得把“Skill 已加载”“回复已结束”或“资料已接入”当作采用成功。
第一页可持续补充来源，不以全部信息齐全、所有系统接通或外部 API 已开放作为本方法完成条件。

## 7. 失败与恢复

网页失败、文档解析失败或来源停用时保留已有成果与真实失败范围；不以猜测填补事实。
证据失效或版本冲突时重读有关引用，仅修订受影响部分；历史候选和已采用版本保持可区分。
停止后迟到写入由服务端拒绝；取消前已提交的内容仍保留，恢复从实际回执继续，不宣称自动回滚。
关键身份歧义或资料矛盾阻塞时保存一个具体问题；其他独立内容可以继续整理。

## 8. 后续来源与映射建议

| 来源 | 基础本体下一步需要确认的契约 |
|---|---|
| 知识库 | 文档ID、版本、章节/片段定位、授权、更新时间；文本证据不直接等于实时业务对象 |
| BI | 指标含义、粒度、维度、单位/币种、期间/时区、过滤、刷新时间与可加总性；聚合行不冒充实体 |
| 业务系统 | 稳定ID、字段类型、分页/过滤、状态与单位、关系键和更新信息；同名字段不足以确认关联 |

建议围绕当前业务问题列出最少的来源及用途。连接可用、样例可读、映射有效、正式采用和对外授权分别呈现。
接入凭据与具体授权通过产品设置完成；通用 MCP 调用结果不能自动变成本体来源，也不能自动开放给消费者。

## 9. 实现接点与验收

T013-01 将创建 `config/skills/company-foundation-ontology/SKILL.md` 及包内参考，复用企业研究与本体建模两项现有方法。
运行目录为 `config/skills/` 与 `<运行目录>/capabilities/skills`，由 `src/capabilities/skills.ts` 的独立 SkillRegistry 发现。
复用 `capability_search`、`skill_use`、`skill_read`、`web_search`、`web_fetch`；加载只提供方法，不自动执行包内脚本。
需配合三页改造调整 `src/agent/app.ts` 工具范围、`config/agent/canvas.md` 和第一页完成条件，开放基础定义与来源检查能力。
复用 `profile_update` 的原话核对及冲突保护；补足基础定义候选/检查/采用服务，不能直接把旧 `ontology_outline` 草稿状态当成新采用能力。
现有证据校验只接受文件 source；需补消息、网页和远端文档引用，由宿主核对实际读取结果后再供本方法保存。
沿真实在线来源补知识库/BI契约；现有标量记录 HTTP/MCP 连接不宣称已支持任意文档、BI、OAuth 或 SQL。
验收包含：直接给名称不重复确认、同名消歧、三路径生成同源成果、资料冲突/unknown、无映射基础采用、重复请求、过期候选与停止恢复。
必须记录一次真实 Skill 加载和领域保存结果；本规格编写完成不能使 T013-01 或任何运行能力变为 Completed。
