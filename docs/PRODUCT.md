# 产品需求：基于 KodaX 的本体数据融合 Agent 产品

更新：2026-09-11。本文承担 PRD 职责，定义用户、价值、任务和产品边界；运行设计见 [Agent 设计](AGENT_DESIGN.md)，技术分工见[总体架构](DATA_ENGINE_DESIGN.md)。本文描述目标，实际交付见[功能台账](FEATURE_LIST.md)。

## 1. 产品定位

**Data Engine 通过本体统一异构多源数据的概念、身份和关系，由 Agent 协助构建和治理，形成供人和 AI 共同使用的企业语义数据层。**

企业不同系统中的同名字段未必同义，不同编号可能代表同一个业务对象。产品要让跨源数据共同回答业务问题，并使其依据、冲突和修改可以被理解与检查。内部 Agent 承担阅读资料、提出概念、配置映射、调查异常和准备修订等工作，降低纯人工维护本体的成本。

产品设计顺序是业务目标 → 领域对象与操作 → Agent 工作方法 → 共享服务 → 人类与机器的使用入口。以 AI 可理解、可操作为起点，同时让人能看懂、纠正和决定企业采用的业务含义。

## 2. 用户与使用角色

| 用户/角色 | 主要任务 | 得到的结果 |
|---|---|---|
| 人类业务查看者 | 查看企业结构、简单查询、追溯结果 | 可解释的对象、关系和证据 |
| 人类业务负责人或数据维护者 | 定义含义、补资料、修正匹配与口径、管理访问 | 有依据和版本的本体、映射与治理决定 |
| 外部 Agent / 应用及其接入开发者 | 按任务发现和消费企业数据 | 有界、受权、可溯源的 API/MCP 契约 |

内部 KodaX Agent 是产品的协作能力；外部 Agent 是独立消费者。业务角色描述不代表当前已实现员工身份系统。采购方、首批客户与商业模式需客户验证，不由框架选型推断。

## 3. 以 Agent 工作闭环组织能力

| 工作 | Agent 承担的判断与行动 | 确定性服务形成的产物 | 人的参与 |
|---|---|---|---|
| 建立企业基础 | 读对话、资料或确认身份后的公开网页，提出少量有用概念 | 带依据、未知和冲突的基础候选 | 补足关键业务含义、纠正、按范围采用 |
| 接入与语义对齐 | 发现获准能力、检查内容、建议字段/身份/关系映射 | 来源目录、可执行映射、检查结果 | 提供访问与必要业务解释 |
| 组织与解释融合结果 | 按对象查询、沿关系调查、比较跨源依据 | 融合对象、属性/关系证据与覆盖范围 | 查看结果、指出问题 |
| 协助持续治理 | 区分局部事实与全局规则问题，提出最小修订并检查 | 差异、影响、候选和实际采用回执 | 处理需要业务决定的变更 |
| 开放与维护消费 | 协助选择适合任务的视图、解释变更影响 | 实际接口、授权范围、发布/迁移记录 | 配置调用方与授权、处理迁移 |

一个内部 Agent 根据目标选择 Skill 和已实现能力。工作可跨页、可返回补充，页面不对应独立 Agent，也不规定必须做完整企业问卷才能建模。已授权的读取、检查和普通编辑直接推进；缺少关键信息时先交付已有成果，再提出具体问题。

本体、映射、证据和治理回执是主要工作成果。对话帮助协作，长期成果独立保存。纯查看或外部查询无需启动内部模型；治理也不默认等于全天后台运行。

## 4. 三页作为共享工作入口

| 页面 | 核心问题 | 内容 |
|---|---|---|
| 企业与数据 | 企业是什么，哪些来源支撑当前问题 | 企业基础、本体 Skill 三条起步路径、知识/BI/业务来源及连接检查 |
| 本体工作区 | 数据怎样融合，结果是否可信，如何修改 | 定义/对象视角、局部图表、映射证据、检查与内容修订 |
| 消费与治理 | 谁可以使用哪些内容，变更影响谁 | 消费视图、真实 API/MCP、接入说明、权限与版本迁移 |

保留黑白灰全高画布、底部输入浮层和渐隐近期对话。图、表、详情与 Agent 指向同一领域对象；无障碍树启发一致的身份、状态、关系和动作表达。具体人的体验由[画布设计](CANVAS_DESIGN.md)定义，机器与界面协作由[人机契约](AGENT_UI_DESIGN.md)定义。

第二页负责内容修订与采用，第三页围绕同一变更处理消费者影响、发布和迁移。三页均可查看；正式消费要求所选定义和映射已采用、可执行且获准。基础本体无源时可保留未映射概念，不生成虚构实例。

## 5. 数据与治理原则

- 原始数据按授权从源系统按需读取；本地保存定义、映射、稳定引用、治理记录及按用途保留的必要证据。
- 文档片段、BI 指标与业务记录各自保留语义，不把聚合结果当明细，不按同名自动合并对象。
- 事实、人工陈述、候选、推导与采用状态明确；校验结构合法不等于业务正确。
- 前端与 Agent 的业务操作经过共同服务，分别检查身份、当前权限、版本和效果，界面与模型以真实回执判断结果。
- 采用定义不自动开放消费或迁移所有调用方；源事实变化、语义变更和权限变化分别处理。

## 6. 成功判据与本轮范围

用真实跨源任务检查：同一业务对象能从两个来源取得正确属性；一项查询能结合文档口径、指标范围和记录依据；人可查看并通过直接编辑或 Agent 纠正同一目标；两个独立消费者取得各自获准结果。

同时记录任务正确性、证据覆盖、人工处理时间、建议采纳与误改/漏检、模型上下文和工具成本。目标是降低融合与治理成本，不能用对话轮数、图节点数或调用工具成功率代替产品成效。

本轮为本地单企业 MVP，详细交付与非目标只维护在 [MVP](MVP.md)。当前已实现三页与存量迁移，复用 KodaX、部分 Skill、记录来源与外部只读查询；基础本体、分类来源与融合能力继续按 [012—016](features/v0.1.0.md#feature-012)实施。源码宿主仍为 Node/Web，不引入桌面多 Agent 平台。
