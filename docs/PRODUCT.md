# 产品需求：ADE 本体数据融合

更新：2026-10-19。本文定义产品价值、用户与目标边界。v0.3.0 的详细需求和依赖见[版本设计](features/v0.3.0.md)，状态只在[功能台账](FEATURE_LIST.md)；目标设计不等于已接入能力。

## 产品定位

**ADE 把企业不同来源的数据自动整理成一份可查证、可修订、有版本的业务本体，让人和 Agent 通过同一个 Agent 修改它、用它回答业务问题，并把确认后的版本交给外部 Agent 使用。**

核心是本体驱动异构多源融合：让不同系统的对象身份、属性和关系共同回答业务问题，保留逐属性依据、冲突与未知。内部 Agent 降低构建和治理成本，业务用户与外部 Agent 消费同一语义服务。结构发现参考 Helix，KodaX 保持唯一内部模型与工具循环。

## 用户与场景

| 用户 | 核心任务 | 可检查结果 |
|---|---|---|
| 数据维护者 | 接入来源，让本体正确、完整、可发布 | 定义、绑定、复验、变更与工作版 |
| 业务使用者 | 问跨系统问题，判断答案是否可信 | 结论、属性级依据、版本与覆盖 |
| 外部 Agent 及其开发者 | 在许可范围内稳定读取企业对象与关系 | 发布绑定的 v4 HTTP / MCP 合同 |

第一阶段为本地单企业、单管理员，暂无指定客户或行业；星桥（研发管理）作为主样本，另设独立留出样本。业务角色不等于已实现账号或企业 IAM；三种本地角色属于 FEATURE_064。

## 产品闭环

接入数据 → 程序生成本体初稿 → 问答验证 → 发现缺口 → 构建修复并采用 → 发布 → 外部 Agent 消费与反馈。

程序、人、Agent 都可以提出结构变化，经同一确定性服务复验，再由人采用。程序不是唯一结构设计者，Agent 也不能自行采用结构；首次构建与同结构重绑的自动规则见[ADR-007](ADR/ADR-007-bounded-auto-adoption.md)。名称、别名、说明属于普通编辑；首次批量命名仍交人确认。

同一个 Agent 具有构建与问答两种模式。构建模式观察、提议、复验和预览，问答模式只读并可创建缺口单；页面只给默认模式与焦点。双模式及缺口闭环分别由 FEATURE_048、052、054 实现，当前运行仍是按页面装配工具的单一模式，不用提示词冒充权限隔离。

## 三页与共同状态

| 页面 | 解决的问题 | 目标呈现 |
|---|---|---|
| 数据 | 哪些来源可用、怎样更新、哪里需要处理 | 表格 / 文档 / 指标、状态、规模、数据截至、一个主动作 |
| 本体 | 数据如何连接、答案是否可信、如何修订 | 图、详情侧栏、待处理队列；实体、属性、关系和对象 |
| 发布与接入 | 交付哪个版本、谁能用、如何升级或撤销 | 工作版差异、检查、发布、接入方 |

三页共享一个 Agent 面板、一个会话体系和服务端投影的计数与来源状态。所有待决定事项进入同一待处理中心；用户可见版本只有工作版与发布。原始 JSON、UUID、内部字段和组件名仅在开发者视图出现。具体交互见[画布](CANVAS_DESIGN.md)与[协作契约](AGENT_UI_DESIGN.md)。

## 数据与治理原则

- 结构化来源默认同步为本地不可变快照，工作区和问答默认读已采用快照；实时读取需显式选择并在回执说明。发布固定本体、绑定、身份决定与快照组合，见[ADR-004](ADR/ADR-004-managed-snapshots-and-pinned-releases.md)。不承诺来源未提供的业务时点历史或跨源同时性。
- 文档不产生实体、属性、关系结构，用于名称、说明、依据、未知、冲突与知识检索；指标保留口径、粒度、期间与可加总性，不把聚合结果当明细。
- 前端、人、Agent 和外部入口使用共同领域服务；服务核查身份、版本、授权、运行有效性与提交效果，不把 Prompt 当作约束实现。
- 保存、复验、采用、发布及许可分别有真实回执。采用本体不自动授权，工作版更新不静默迁移旧接入方。
- 本体、变更、缺口、决定与完整会话历史长期保存；模型上下文另行有界裁剪，不用删除历史减少 token。

## 成功判据与范围

| 指标 | 度量 |
|---|---|
| 首个正确答案时间 | 接入一批新数据到正确回答第一个跨源问题的时间 |
| 业务问题准确率 | 固定问题上的漏连、误连、误合并与错误版本 |
| 人工介入量 | 初稿到可发布所需决定次数与时间 |
| 可解释率 | 答案说明依据、版本、数据截至与覆盖；答不了时说明原因 |

同时记录模型成本。功能数、图节点数、工具调用成功率和回归数量不代替这些指标。主样本与留出样本通过真实 KodaX、浏览器和独立外部客户端验证，答案不进入被测输入。

当前最小范围按[MVP](MVP.md)推进。第一阶段不做继承与命名空间、OWL 推理、图数据库、任意 SQL 对外开放、源系统写回或自动业务动作、多租户、SSO、行级权限、公网部署及计费。当前交付基线与历史证据见[文档中心](README.md)，不因本文更新宣称新版本完成。
