# 星桥软件：演示视频样例

虚构的 B2B 软件公司星桥软件（Starbridge Software），用于录制 DataEngine 演示视频：把三个系统里的人、项目和文档融合成一套本体，发布为 MCP 插件，再让第三方 AI 助手回答项目交付问题。所有人物、产品、邮箱和记录均为虚构。

改编自外层调研目录的 `fixtures/starbridge`，为视频做了这些调整：项目系统改为 CSV；HR 不再携带项目系统用户名，人员身份必须跨系统对齐；去掉文档里直接点明答案的提示；增加一批 9 月 3 日的更新数据。

## 三个来源

| 系统 | 目录 | 怎样指代一个人 | 内容 |
|---|---|---|---|
| StarHR 通讯录 | `sources/hr/` | 工号 `SB005`、中文名 | 13 名员工、8 个团队、汇报线、在职状态 |
| StarTrack 项目系统 | `sources/tracker/` | 用户名 `chen.wang`、英文显示名 | 账号、产品、项目、版本、需求、任务与阻塞关系 |
| StarWiki 知识库 | `sources/wiki/` | 中文名或称呼“王工” | 交付会议纪要、产品说明、负责人交接、旧需求草案、路线图 |

三个系统之间没有共用的人员编号。HR 和项目系统大多可以用邮箱对上，但有例外；文档只写中文名或称呼。

`updates/2026-09-03/tracker/` 是项目系统 9 月 3 日的完整导出（任务、版本两张表），用于演示“数据更新 → 新快照 → 答案变化”。

## 视频主线

主问题：**“FlowPilot 3.2 为什么延期？现在该找谁推进？”**

1. 不接插件时，第三方 AI 助手无法回答或只能猜测。
2. 在 DataEngine 中上传三个来源，构建本体；人、团队、产品、版本、需求、任务和文档连成一张图。
3. Agent 指出跨系统冲突，人确认修正并采用。
4. 发布版本，创建 MCP 接入，配置到第三方客户端。
5. 再问主问题，得到带出处的回答。
6. 可选：上传 9 月 3 日更新，同一问题得到新的答案。

标准答案和验证问题在 `data/private/starbridge-demo/`（不入库），不能放进 Agent 可读的来源。

## 上传顺序

1. `sources/hr/` 两个 CSV；
2. `sources/tracker/` 六个 CSV；
3. `sources/wiki/` 五篇 Markdown。

时间均为 UTC+08:00，资料可见时点 2026-08-30 09:00。

## 检查

在产品仓库根目录运行（Python 3.9+，仅标准库）：

```sh
python3 scripts/validate_starbridge_demo.py
```

脚本检查主键与跨表引用，确认视频依赖的冲突仍在数据中，并重写 `manifest.json`（文件、记录数、字节数与校验和）。修改数据后需重新运行。
