## 来源包

`sources/` 中是可供后续建模和消费 Agent 使用的业务资料；`manifest.json` 记录允许输入的文件、来源 ID、记录数、字节数、校验和及时间语义。文件内行主键与 manifest 的 source_id 一起构成来源引用。

各系统保留自己的站号、监测标签及居民原始地址；必要的跨系统联系来自接入交接、物业地址说明和派单记录。没有预填全局对象 ID、标准本体、故障事件分组或标准答案。

当前源文件是截至可见时点的导出快照。客服单和维修单中的状态是最终行状态，`available_at` 为该行版本的记录时间；它们不能直接当作任意历史时刻都可读取的事件流。历史创建/更新日志和按时点投放在 T001-02 完成。小时监测、回访和测温则分别保留自身行为时间与可见时间。

监测值是简化合成值。对正常质量的小时行，热量按 `流量(m³/h) × 供回水温差(℃) × 0.004186` 合成，单位 GJ/小时区间，保留三位小数；用于检查数量关系，不作为工程模型或真实仪表校准。温度为区间均值；室温是少量上门测量，不代表全体住户。缺失采集明确留空，累计时须报告覆盖率。

## 输入边界

后续运行环境应只挂载本次 `sources/` 和 manifest；所有对照组获得相同的业务导航与规则。此 README、项目代码、开发文档、`data/private/`、生成器内部状态和未来变化计划均不属于 Agent 输入。

目前只有文件组织与清单检查，尚未实现运行时隔离。不能把 Git 忽略或清单本身当作访问控制；基线开跑前必须验证隔离和未来时间过滤。

## 检查

在产品仓库根目录运行（Python 3.9+，仅标准库）：

```sh
python3 scripts/validate_heating_sample.py
```

检查来源清单与哈希、记录主键和引用、时间顺序、楼栋与站点面积、监测覆盖和合成热量关系。检查器不读取私有答案或未来计划。
